意图三级级联

60 秒版：分类不能另花一次模型请求，否则缓存省下的成本会被分类器吃回去。系统先用 T0 规则和实体扫描快速决断，再用 T1 意图质心处理规则外问法，最后才让模型以工具调用作为意图证据。十个意图里 UNKNOWN 是显式状态，缓存放行必须 fail-closed。

Decision

T0 规则层：关键词、实体正则和所有格动作词表决定 cacheable/dynamic，目标是低于 1 ms 的早停；检测到动作意图时动作优先。

T1 质心层：每个意图由 8-15 条样例句形成质心，最近邻需要置信度和 top-1/top-2 margin 同时达标；该层复用 L2 语义缓存所需的 query vector，避免重复向量化。

T2 模型层：只有前两层都判不动才进入正常模型调用，模型返回的 tool call 作为意图证据，不额外增加一次分类请求。判不动则 UNKNOWN，不查缓存，必要时转人工。

重点看三类例子：含订单号或“我的”动作请求必须 dynamic；纯政策问法可 cacheable；T0 判不出的反义或含糊问法不能因为“像政策”就直接进缓存。

Three questions

Q1：为什么不为分类单独调一次模型？

因为缓存的价值来自减少模型调用。若每个请求先花一次分类模型，再决定缓存是否命中，热点重问仍然支付分类成本，收益结构被破坏。三级级联用规则、质心和已有工具调用证据完成分类。

Q2：T1 为什么复用 L2 的向量？

同一条 query 在意图判定和语义缓存中都需要 embedding。复用一次向量避免同一请求打两次向量服务，也把新增的约 10 ms 比较成本控制在可预算范围内。缓存命中路径再通过进程内向量缓存做到零远程 embedding。

Q3：为什么动作优先，又为什么保留 UNKNOWN？

动作链路可以附带政策上下文，政策链路却不能替买家执行订单操作，所以多意图取动作优先。显式 UNKNOWN 把不确定变成可观测状态，确保不进入缓存读取，也便于降级为人工处理。

Failure symptom

症状含义
“我的订单到哪了”返回通用政策答案动态请求被误判为 cacheable，缓存准入或动作优先失效。
反义问法因 T0 识别失败而进入 L2UNKNOWN 没有按 fail-closed 处理。
同一请求在 T1 和 L2 各打一次 embedding向量复用断开，TTFT 与远程调用量被重复支付。
