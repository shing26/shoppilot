入口与身份

60 秒版：买家进入网关后，身份只来自验签通过的 JWT。网关把租户、买家和会话写进服务端上下文，忽略请求里客户端自带的租户字段；dev 默认凭证只在回环地址合法，绑定到非回环地址仍用默认值就直接拒绝启动。

Decision

身份不能由调用方声明。AuthFilter 在控制器之前验 token，JwtService 验证签名与有效期，TenantContext 保存服务端派生出的身份。请求体、查询参数或 header 里的 tenantId 不能成为授权依据。

观测坐标在入口建立。traceId、tenantId、customerId、conversationId 进入 MDC；跨线程提交时手工包装上下文，避免异步写回和工单路径丢 trace。

dev 便利性由绑定地址约束。回环地址允许默认密钥和 mock 签发端点，但启动 WARN 并在观测面暴露 devDefaultsInUse；非回环地址若仍使用默认值，DevDefaultsPolicy 阻止启动。

Reproduce

.\mvnw.cmd -B -ntp -pl shoppilot-gateway -am `
  -Dtest=AuthFilterTest,DevDefaultsPolicyTest,DevDefaultsStartupBlockerTest `
  -Dsurefire.failIfNoSpecifiedTests=false test

# 需先起栈；该脚本同时验证伪造 token 与跨租户越权
pwsh -NoProfile -File scripts/verify-action-loop.ps1

预期：JVM 测试通过；活体验收中伪造 token 得到 401，换店或换买家查同一订单得到“未在本店找到该订单”，不能看到对方的收货信息。

Three questions

Q1：为什么不能相信客户端传的 tenantId？

租户隔离的根必须只有鉴权结果。若 header 能改租户，A 店用户只需改一个字段就能查 B 店数据；即使 repository 写了归属条件，授权根也已经错了。因此网关忽略客户端租户字段，并从签名 token 重建上下文。

Q2：为什么不直接加一个 prod profile 删掉默认值？

这个项目没有 prod 档，而干净克隆又要求没有 .env 也能起栈。加一个永远不使用的 profile 会把问题从“可能误配置”变成“看似处理过”。绑定地址是能自动触发的条件：回环上允许演示，非回环上默认值立即成为启动阻断项。

Q3：为什么 MDC 要在 AuthFilter 里装？

鉴权入口已经同时拿到 token 身份、会话和请求坐标，是同步与 SSE 共用的最早位置。异步写回、工单升级和虚拟线程会跨线程，MDC 不会自动传播，所以在提交异步任务时还需要显式包装并清理。

Failure symptom

症状含义
改 header 或参数中的 tenantId 后读到另一家店铺数据授权根被调用方可控，租户隔离已经失效。
server.address 改为非回环后仍能用默认密钥启动dev 默认值边界没有执行，发布形态不安全。
SSE 有 traceId，但写回或工单日志没有异步边界丢失 MDC，事后无法关联同一请求。
