## 1. 设计目标与三个判断点

**目标**：让项目呈现为真实可落地使用的产品，而非展示型 demo；突出实际使用场景、内容可信度、操作效率与业务闭环。

**判断点一**：当前 demo 感不是视觉问题，而是三类"身份暴露"叠加——
① 演示入口（一键体验 / 演示口令见 .env / 预填问题）；
② 工程细节外露（JWT 明文、运维令牌、故障注入、复位演示单）；
③ 身份虚化（URL 传店铺、mock-token 免凭证领身份）。
这三类不去掉，换配色只会更精致地像 demo。

**判断点二**：三版差异按"为谁做、解决什么问题"切（买家 / 坐席 / 工程评审），不是按配色切。

**判断点三**："数据不留"（默认档 H2 内存重启即清、报表 `process-local-cumulative`）和"身份靠 URL"是**后端/部署口径限制**，纯前端无法解决。任何声称解决它们的方案都在造假——所以三版对此的处理方式不同，这是它们真正的差异。

## 4. 三版方案

### V1 · 店铺客服中心（面向真实买家）

- **设计定位**：把买家端改造成真实售后入口——买家带着订单来、带着结果走。删掉所有身份选择入口，身份由令牌决定；数据留存按档位诚实标注（演示档显示"数据不跨会话保留"，不假装留存）。
- **信息架构**：帮助首页（搜索 + 退货/物流/优惠/生鲜四类）→ 会话 → 我的订单（详情/物流/带上下文提问）→ 我的工单 → 账户（只读）。不设改密/注册邀请/消息订阅（后端不支持）。
- **核心布局**：沿用两栏（对话 + 350px 上下文感知侧栏）。侧栏随上下文变化：会话中→订单卡 + 依据条款 + 执行进度；看订单时→可执行动作；无上下文→进行中工单。帮助首页替代现有 welcome 快捷问题，把意图清单变成可见分类。
- **主要交互**：① 从订单详情 deep-link 带 orderNo 进入；② 政策问答 SSE + 依据条款 + 点赞/点踩（点踩进复核）；③ 缺槽位时追问、下次输入续办、绝不猜；④ 退款显示"已受理/订单冻结/资金未动/待人工放行"，放行后"到账由支付渠道处理"；⑤ 降级给可查工单号。
- **视觉风格**：沿用 teal + 深墨 chrome，不加新色板。信任感来自信息密度（时间戳、工单号、ruleId、责任人署名用等宽字），顶部改为真实店铺名 + 买家署名。
- **组件拆分**：框架 `BuyerShell/TopBar/AuthGate`；首页 `HelpHome/PolicyCategoryCard/PendingSummary`；会话 `ChatThread/Composer/AgentPhases/CitationPanel/FeedbackBar`；上下文 `OrderContextCard/RefundTracker/TicketDrawer`；账户 `AccountPanel`（只读）。
- **响应式**：≥1024 两栏；768–1024 侧栏 280px；<768 单栏 + 底部抽屉，触屏目标 ≥40px。
- **四态**：空（无待办引导提问）／加载（骨架 + "正在理解你的问题"）／错误（status:0 重试、429 倒计时、4xx 回显 message、降级给工单号）／权限（未登录登录门、店铺不符丢弃存档、403 无权限文案）。
- **改进重点**：身份从 URL 迁到令牌；演示入口下线；侧栏上下文感知；数据留存按档位标注。
- **适用场景**：拿到真实店铺/买家共创伙伴，或要向业务方演示售后产品。无真实客户时 V1 会变成"更精致的演示"。

### V2 · 售后服务台（面向坐席与运营）

- **设计定位**：坐席一天真正用的工作台——按优先级处理工单、资金动作留责、知识飞轮沉淀重复问题。调试台故障注入/令牌/复位**彻底移出产品面**，归入独立"工程师模式"（需运维凭证、默认折叠、不同路由）。角色塑造界面：agent 看不到管理员入口。
- **信息架构**：工作台首页（今日待办/超时/待审退款）→ 工单队列 → 退款审核 → 渠道会话 → 知识飞轮 → 质量看板 → 管理（仅 ADMIN）→ 工程师模式（独立路由 + 运维凭证）。
- **核心布局**：深墨侧栏 212px + 主区，侧栏项按角色过滤 + 待处理角标。队列页 = 5 KPI + 筛选条 + 列表（优先级色点/来源徽章/SLA 剩余） + 详情（会话上下文/生命周期/处理框）。退款页 = 待审卡 + 四段决策路径 + 二次确认，责任人**强制取自令牌**，不提供输入人名字段。
- **主要交互**：① pull 领取，409→"刚被同事领走"；② 填结论→RESOLVED，渠道来源触发结果回流；③ 退款四段路径→确认弹窗复述不可逆/回滚→审计留痕；④ 点踩→去复核→人工写稿（系统不代写）→发布→标"已发布·待 ingest"→手动跑 ingest→纪元+1；⑤ 质量看板下钻到工单。
- **视觉风格**：深墨 chrome + teal，14px 基准，优先级色对齐后端枚举（URGENT_EMOTION 红 / MONEY 琥珀 / NORMAL 中性），SLA 写"已超时标记"而非"违约"。
- **组件拆分**：`WorkspaceShell/RoleSideNav/EngineerModeGate`；`QueueFilters/TicketList/TicketDetail/LifeCycleTimeline/ResolveDialog`；`RefundCard/DecisionPath/ReviewDialog/ActorStamp`；`FlywheelStepper/ReviewQueue/RevisionEditor/EpochBadge`；`QualityReport/DrilldownLink`。
- **响应式**：≥1280 三栏；1024–1280 两栏；<1024 侧栏折叠图标条、详情抽屉；移动端只保留查看/审核轻操作。
- **四态**：空队列/空审核/空复核；加载中各视图"正在读取…"、提交禁用；错误含 409 领取冲突、409 重复审核、502 飞书回复失败、status:0；权限 403 坐席文案 + 管理入口不渲染 + 工程师模式独立拒绝页。
- **改进重点**：调试能力物理隔离；角色塑造菜单；资金动作责任人不可抵赖可视化；"发布≠生效"可见化。
- **适用场景**：有真实售后团队、要提效与合规追溯。单人演示或面试作品会变成"为像产品堆功能"，正是路线 A 停止清单禁止的。

### V3 · 可信运行时控制台（面向工程评审 / 技术决策者）

- **设计定位**：不伪装客服产品，把项目真实差异化资产——每次回答可回放、工具有风险分级、资金动作 HITL、租户隔离 HTTP 反证、评测有 golden 与任务级判据——做成一等界面。**不掩盖演示态，而是把口径摊在界面上**：每个指标挂"数据口径"标签（合成数据/演示档/进程内累计/MockLLM 估算），每个字段可点开看证据来源与复跑命令。当"这是演示档"从弱点变成明示的证据边界，demo 感就消失了。
- **信息架构**：概览（一次回答的生命周期）→ 运行记录/回放 → 证据中心（评测/隔离反证/安全门禁）→ 质量观测 → 知识纪元 → 工程师模式（物理隔离）。
- **核心布局**：单轮回放三栏——左：问题 + 元数据（意图/缓存/租户/纪元/耗时）；中：答案 + Agent 三段 + 依据条款；右：执行证据时间线（复用 console SSE 帧，重命名为"执行证据"）+ 审计事件。证据中心卡网格：每卡 = 一条可复跑命题（命令 + 实际输出 + 证据路径）。口径标签悬浮展开"怎么来的/什么时候测的/不能推出什么"。
- **主要交互**：① 选轮次→逐步播放 SSE 帧→点帧跳证据→复制复现命令；② 证据中心选"跨租户串号"看反证与 404；③ 审计选退款放行看 `actor_authenticated=true` 署名；④ 知识纪元人工写稿→发布→"待 ingest"→手动触发→纪元+1；⑤ 工程师模式注入故障→看降级与工单→清除（明确标注测试动作）。
- **视觉风格**：工程控制台风，深墨 + teal + 等宽字承载 ID/命令/数字，无营销插画/渐变。配色只区分"事实/口径警告/经验证/未达成"四类语义。**遵守禁语**：不说"生产级 SaaS 开箱即用"、"比大厂更智能"、"自主完成任何售后任务"、"多 Agent 协作平台"；改用"可回放/可复跑/受控/有边界"。
- **组件拆分**：`RuntimeShell/ScopeBanner/EngineerModeGate`；`ReplayPlayer/SseFrameList/AgentPhases/CitationPanel/FallbackBadge`；`EvidenceCard/RunCommand/EvidenceFootprint/CaliberTag`；`QualityReport/DrilldownLink`；`EpochTimeline/RevisionList/IngestTrigger`。
- **响应式**：≥1440 三栏；1024–1440 两栏证据栏折叠为标签页；<1024 单栏、时间线折叠步骤条；移动端只读。
- **四态**：空（无运行记录→给复跑命令）；加载（逐帧呈现即加载态）；错误（证据产物缺失、口径冲突显式显示两处数字差异）；权限（只读面免登录、工程师模式无凭证给拒绝页、资金审计只展示已验签署名）。
- **改进重点**：口径与证据边界做成界面；调试帧升级为可复现证据；工程师模式物理隔离；全程禁语。
- **适用场景**：秋招面试作品集技术展示、需要参考架构的工程团队评审、要复跑证据链的技术决策者（即路线 A）。

## 5. 三版对比矩阵

| 维度 | V1 店铺客服中心 | V2 售后服务台 | V3 可信运行时控制台 |
|---|---|---|---|
| 目标用户 | 买家 | 坐席 / 运营 | 工程评审 / 技术决策者 |
| 业务闭环 | 问 → 办 → 查 → 评 | 领 → 办 → 审 → 结 | 问 → 证 → 复跑 |
| 可信度来源 | 引用溯源 + 退款进度 | 责任人署名 + 审计 | 可回放 trace + 可复跑命令 + 口径标签 |
| 效率重点 | 带订单上下文提问、少填槽位 | 优先级队列、批量筛选 | 一键跳证据、复制复现命令 |
| 去 demo 关键动作 | 身份从 URL 迁令牌、演示入口下线 | 故障注入隔离、角色塑造菜单 | 明示口径而非隐藏演示态 |
| 需后端/部署配合 | 高（真身份、数据留存） | 中（角色菜单、工程师模式路由） | 低（纯前端重组现有资产） |
| 与路线 A 关系 | 违反停止清单（继续加客服功能） | 违反（继续扩视图） | **完全一致（把证据做成产品）** |
| 当前推荐 | 暂缓，等共创伙伴 | 暂缓，等真实团队 | **首选** |

**建议**：当前阶段选 V3——唯一不需后端改动、不违反已锁路线、且把 demo 感根源转化为优势的方案。V1/V2 是真要转产品时的方向，但必须先解决数据留存与真实身份两个后端前置条件。

## 8. 给接手方的落地注意

1. 先决定方向（推荐 V3），再把样张里的信息架构/组件拆分映射到现有 Vue SPA，**不要另起技术栈**。
