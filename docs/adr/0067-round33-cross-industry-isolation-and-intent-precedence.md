# round33 开轮：跨行业隔离补上 Domain 维度，T0 回到“动作优先”

Date: 2026-10-17　Status: Accepted　Owner ruling: 2026-10-17「按修复顺序建议开始修复」。
Tickets: 票 124-128（见 [`round33-spec-cross-industry-isolation.md`](../../.scratch/shoppilot-mvp/round33-spec-cross-industry-isolation.md)）。

Context:

round32 把酒店作为跨行业咨询对照引入后，暴露的不是“少一条酒店规则”，而是**跨行业隔离缺了一整个维度**。
当前代码里：

- 检索可见范围只有 `tenantId + PLATFORM`，而平台级语料全部是电商政策；酒店租户因此会看到
  “生鲜理赔 / 退货政策 / 快递规则”，问“押金什么时候退”也会答成电商条款。
- 缓存平台桶键只有 `PLATFORM + intent + epoch + query`，没有行业维度；T001 先问酒店问题写进平台桶后，
  T004 会直接命中同一条电商答案。
- 空召回时 `HybridRetriever` 会把 `intent=null` 再检一次，等于把酒店问句放宽到全部电商政策。
- `T0RuleLayer` 只在实体或第一人称出现时才动作优先；“生鲜坏了我要退款”没有实体也没有“我的”，
  于是被政策词表判成 `POLICY_FRESH`，待办退款动作丢失。
- `FRESH_WORDS` 和 `HOTEL_WORDS` 含“坏了 / 早餐”这类过宽词，导致“手机坏了怎么赔”被判生鲜、
  “早餐机坏了怎么赔”被判酒店。
- 版本化底座提示词以“你是电商店铺的在线客服助手”开头，酒店租户也拿到这份电商人设。
- 买家端引用契约与网关不一致：网关返回 `List<String>`，前端按对象读，页面只显示“政策条款”。
- `return-01-7day-basic.md` 把“七天无理由”写成“十四天内可申请”，与标题和店铺十五天窗口抵牾；
  T002 的门面叙事点名“死蟹、六小时、按只折算”，但语料里没有一份 T002 店铺级死蟹细则。

这些是 round32 真实暴露出的实现与承诺不一致，按所有者显式裁定开 round33 修复。它不是 ADR 0030 /
ADR 0031 的触发已到，**不自动续期**：round33 收口即止。

Decision:

1. **新增行业维度 `Domain`（`ECOMMERCE` / `HOTEL` / `UNKNOWN`）**，并把它贯穿租户解析、规则块、
   检索过滤与缓存分区。租户属于哪个行业来自显式配置；未登记租户默认 `UNKNOWN`，只看得到本租户自己的
   规则，**不自动获得平台级电商政策**（fail-closed）。
2. **平台级政策带行业归属**。电商平台语料为 `ECOMMERCE`，酒店语料为 `HOTEL`；检索可见范围变为
   “本租户 + 同行业平台规则”。酒店租户永远不能引用电商平台政策，电商租户也不能引用酒店平台政策。
3. **缓存平台桶加 domain 维度**。`PLATFORM` 桶不再全局共享；同一句“押金什么时候退”在
   ECOMMERCE 与 HOTEL 下是两条不同的缓存空间。L1 key、L2 payload/filter、负缓存、写回桶全部同步。
4. **删除检索的空召回意图放宽**。“按意图过滤后为空”返回空，不再用 `intent=null` 重检。宁可转人工，
   不可拿另一个行业的条款回答；降级与“确实没有这条政策”仍按既有 `degraded/empty` 语义分开。
5. **T0 判定顺序明确为**：显式转人工 → 行业门（酒店租户只能得到酒店政策/转人工）→ 第一人称/实体动作
   → 显式办理动作 → 酒店词表 → 电商政策词表。显式办理动作（“我要退款 / 帮我申请退款 / 改地址”等）
   必须动作优先；纯政策问法（“退款政策是什么 / 能退吗”）仍走政策。
6. **收紧关键词表**。`FRESH_WORDS` 去掉“坏了 / 破损 / 变质 / 理赔”这类泛词，改成行业对象词
   （生鲜、水果、水产、活鲜、大闸蟹、死蟹等）；`HOTEL_WORDS` 去掉独立“早餐”，改成
   “酒店早餐 / 含早 / 早餐券 / 早餐时间”。目标是先消除已复现的误判，不追求词表完备。
7. **提示词换代**。agent-system 基座升到新版本，改成行业无关的客服底座；酒店行业由附加约束明确
   “纯咨询、无办理工具，办理类诉求说明办不了并转人”。不把酒店补丁写进电商人设。
8. **买家引用契约做只增兼容**。保留既有 `citations: List<String>`（反馈与旧脚本依赖它），新增
   `citationDetails: [{ruleId, heading, doc}]`；买家端优先读新字段，旧响应仍可降级显示 ruleId。
9. **语料修正**。`return-01` 的“十四天”改回七天；新增 T002 店铺级死蟹细则，写清六小时窗口、
   按只折算、订单核验、看照片不能定责必须转人。新增内容一致性回归测试，不再让标题与正文互相打架。
10. **判据红线不动**：不改 180 条 gold、阈值、指标分母或验收判据。新回归测试只加在 JVM 与既有 0 token
    门禁内；活体读数按实测登记。

Considered Options:

- **只给 T004 加白名单/特判**：否决。它把行业隔离问题伪装成一个租户例外，下一个行业会原样复发。
- **让酒店也挂平台级语料**：否决。平台级对所有租户可见，会污染全部电商租户；round32 已明确否决。
- **保留空召回意图放宽以保缓存命中**：否决。那正是跨行业串答案的直接入口；正确性优先于命中率。
- **把 `citations` 直接改成对象**：否决。反馈账本、旧脚本和历史契约都按字符串读；改成对象会制造一次性
   breaking change。只增 `citationDetails` 达到同一目的。
- **只改前端把字符串当对象读**：不够。它只能让 ruleId 勉强显示，heading 仍然丢失；本轮把详情补进
   `AgentResult` 与缓存条目。
- **改 `return-01` 但不加内容门禁**：否决。一个“七天规则”正文再被写成十四天，JVM 与检索门都不会红。

Consequences:

- 接一个新行业从“改四处”增加为“显式登记租户 domain + 语料 domain + 意图/词表/入库映射/评测集”；
  这条成本变更要写进一页纸与 CODE_MAP，不能再宣称“只换知识库”。
- `T0RuleLayer`、`HybridRetriever`、`CacheService`、`CacheEntry`、`MarkdownChunker`、`IngestRunner`
  与 `AgentStateMachine` 的调用签名会变化；对应 JVM 用例同步更新，属于本轮主交付，不是顺带重构。
- `PromptCatalog` 版本推进一格，历史 `v1.0.0` 文件保留；SSE/Sync 的 promptVersion 断言同步换代。
- 活体验证必须覆盖：T001/T004 同一问法不共享平台缓存；T004 不引用电商平台规则；T002 门店死蟹细则
  可检索；T004 办理类诉求不调用电商工具；“生鲜坏了我要退款”追问后仍保留退款待办。
- round32 的“两处未执行”（真人 cold-read、酒店活体套件）继续照登，不被本轮的 JVM 绿冒充。
