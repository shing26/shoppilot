# 实现轮的门禁改判内容级红线，窗口锚点逐轮重锚

Context: 第三轮留下的收口审计（`.scratch/shoppilot-mvp/round3-closeout-audit.py`）为「只收尾不加功能」的轮次而设计：B7 把 `scripts/`、`eval/`、`src/`、`shoppilot-`、`docs/adr/`、`knowledge/` 整片划成禁面，白名单是七个具名文件，窗口锚点停在第九轮闭环那一笔，同时 A2 要求工作树 clean。这套形状在任何一次编辑上都必红一条：不提交则 A2 红，提交则 B7 红。而 ticket 21-26 这一簇的唯一产出就是 `src/` 里的 Java 改动。

决定：窗口锚点每轮重锚到本轮起点；B7 仍是一条 check，谓词只看内容级禁面——窗口内 `eval/` 标注集、gold、阈值常量与既有 21 份 ADR 出现即红；改动文件清单与计数降为 detail 里的读数打印，不做白名单判定。审计总项数保持 95，`TAIL_CHECKS`、`_FX`、产物末行、`LOCAL_ONLY` 那张清单与历轮「项数不变」那串自述全部不动。

顺带消掉的是 `not forbidden and not stray` 这个合取谓词。第十轮刚给合取项立过规矩（摘掉任一条必有格子判错），这里不必补格子——`stray` 在代码轮已经没有含义，谓词单一化比给它配夹具更诚实。

## Considered Options

- 冻结 round3 审计、实现轮接受 B7 恒红：否决。本仓已在 Qdrant 健康检查上认过「恒红的健康检查只会教人忽略红色」这笔账，把同一颗灯装在自己的量具上，等于教下一轮忽略红。
- 逐文件白名单扩到本轮全部 Java 文件：否决。那份清单会退化成「本轮改了哪些文件」的第二抄本，而抄本正是第八到十一轮反复清理的对象。
- B7a 与 B7b 各算一条 check：否决。多一格读数换「知道是哪条红」，代价是总项数变 96，连带 `_FX`、产物末行与历轮那一大片「项数不变」自述全部换代，而这一格能分辨的信息在 detail 字符串里就有。

## Consequences

- 铁律里「不许为把读数改高而改判据、阈值、gold」这条红线改由 B7a 承载，保护面不减：它本来也已经由阈值常量检查与 gold 标注检查钉着，路径禁面只是多出来的一道。
- 第六轮立的「白名单必须是具体文件名，整目录前缀等于免检通道」在它唯一有效的场景（文档轮）里保留；实现轮不再用路径白名单冒充内容审查。
- `STRICT_ALLOW` 那张表随本轮删除，不留成死条目——本仓已有 F2b 那条家法管这个形状（豁免表不许长出没人读的条目）。纯文档轮若再需要它，五行代码请回来，且那时是有意加回而不是继承一个没人核的默认。
- B7 的名字文案要改口，它不再是白名单。P14 到 P17 里那几处「只碰得到 B7 白名单内的具名文件」「由 B7 当场判」是历史 Pass 陈述，按 W9 的处置加换代指针、不改写原文。
- 代价照登：审计脚本一笔改动，散文里「最后一次改动审计脚本那一笔」的锚点链由六版扩到七版，反证跑器与干净克隆检查按既有判据重跑一遍。
- 未做：不新增门禁第 18 步。新代码的断言落在 surefire 用例里，由门禁既有的 `build` 与 `unit` 两步跑。
