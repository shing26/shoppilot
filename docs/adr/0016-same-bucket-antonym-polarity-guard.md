# 同桶反义由极性守卫兜，不由阈值兜

Context: ADR 0003 把语义漂移转化为跨意图隔离问题，前提是"反义提问会落在不同意图桶里"。ticket 17 的标定实测给出反例：「这个能退吗」与「这个是不是不能退」余弦 0.9682，两侧同属 POLICY_RETURN、都在缓存准入范围内，意图分区与 0.95 阈值同时失效。而同意图改写对的最大余弦只有 0.9435，说明在这个 embedding 模型上"越界"与"同意图"并不相关：调高阈值只会先把召回压成 0，压不掉这一对。

决定：在 L2 命中之后、复用答案之前加一道确定性词法守卫 `PolarityGuard`。比较缓存问法与当前问法的否定极性，不一致即拒绝复用并打点 `shoppilot_cache_l2_polarity_blocked_total`。三条判定：含否定标记为 NEGATED；正反问（"是不是""能不能"）说话人未表态，记为 NEUTRAL，与任何极性都不冲突；句末的"不/没"（"可以退货不""发货了没"）是省略问句语气词，不计为否定。缓存条目因此必须携带写入时的归一化问法（`CacheEntry.query`），历史条目无该字段时按 fail-closed 处理，一律不复用。

Considered Options（已否决）：把阈值提到 0.97（0.95 处召回本来就是 0，提到 0.97 只是把 L2 关得更死，且这一对 0.9682 仍然在 0.95-0.97 区间里晃）；让模型做一次反义复核（每次 L2 命中多付一次模型调用，缓存的意义当场作废）；把否定极性塞进 embedding 距离（换模型才可能解决，不是本层能定的）。

Consequences:
- 守卫只做词法判定，不理解语义：「这个能退吗」与「这个不能退吗」会被分开，这是有意的保守，代价是 L2 召回进一步下降——而 0.95 工作点上召回本来就是 0，代价不可测量。
- 串号防线从三层变四层：缓存准入、写回资格、极性守卫、语义阈值。阈值退到只管"同意图同极性桶内的表述归一"，它不再是任何一条安全性质的唯一承担者。
- 这条性质由 `PolarityGuardTest`（Java）与 `scripts/calibrate_threshold.py` 的退出码断言（Python 镜像实现）两头钉住，两份实现漂移会当场红。
- 调试台与 README 里"L2 语义缓存"的实际作用要按此说明，不能继续按任务书原文讲成"拦截口语化改写的主力"。
