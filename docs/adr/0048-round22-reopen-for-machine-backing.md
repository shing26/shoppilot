# round22 重开：RAG 的机器背书（检索录放门 / task 级判据 / token 计量标签 / 告警 + promtool）

Context: 本 ADR 由 round21（ADR 0046）的 Consequences 触发——ADR 0046 明写它只做「闭环最后一公里」那一格，**「机器背书最后一格」登记给后续轮次**。那一格的全部内容是：**CI 里没有任何一条断言在守检索排序**。

取证（round21 期间对仓核实，本 ADR 沿用）：

- `scripts/eval_suites.py:130-235` 的 24 条夹具按 `kind ∈ {emotion, channel, plan, style}` 分发，**四个 kind 都不读 `ruleIds`/`citations`/RRF 序**。
- 唯一那份 RAG 质量证据 `docs/retrieval-comparison.md` 里 16 条查询 `dense` 与 `hybrid` **名次完全相同**（`:30-31`、`:61`）→ 对 RRF 回归**判别力为零**：把 `rrf-k` 从 60 改成 30，CI 全绿。
- 融合本身是**纯函数**：`ruleId` 同时是 ES `_id` 与 Qdrant point id，给定两路序与 `k`，`HybridRetriever.rrf()`（`:198`）+ `accumulate()`（`:208`）的结果完全确定（`score += 1.0/(rrfK + rank + 1)`）。
- 评测面同理：现有四列（意图 / 工具 / 参数 / 槽位）都是**单维请求质量**，没有一列是**端到端终局**；最刺眼的形态是**四列全绿而任务没办成**（`AgentStateMachine.failedStep()` `:717-720` 已认 `NOT_FOUND`/`STATE_NOT_ALLOWED`/`TIMEOUT`/`UNAVAILABLE` 四种终态，判据面却不看它）。
- 可观测面：仓库里**没有任何 `*.rules.yml`/`*alert*`/`*prometheus*`**（round21 复核过）。

Decision: round22 范围锁定 **票 64-68**，一条一票。**依据逐条分清，不许图省事统一贴一个标签**（ADR 0045 起立的写法）。

| 票 | 内容 | 依据 | 依赖 |
|---|---|---|---|
| 64 | 检索融合 0 token 录放回归门（并入 Chunker/Retriever 聚焦单测） | **政策越过**（见下，**不是**「触发已到」） | 无 |
| 65 | task-level 判据最小形态 | **触发已到**（round19 登记第 4 项） | 无 |
| 66 | token 计量加 `source` 标签 | **政策越过** | 57（计数耦合，已收口） |
| 67 | 告警最小集 + `promtool test rules` | **触发已到**（ADR 0030 第 5 条） | 无 |
| 68 | round22 收口 | — | 64-67 |

具体口径：

- **票 64 必须诚实记为「政策越过」，不许讲成「登记第 5 项的触发已成立」。** `round19-spec-trust-observability.md:133` 的登记第 5 项，触发原文是「**出现可离线复跑的录制/回放路径**」，而**建这条路径就是票 64 本身** —— 引自己当依据是循环论证。
- **票 64 的诚实分界：它守的是排序流水线的确定性与四个常数、语料 sha、夹具完整性，不覆盖活体 hit@5 准确率，因此不闭合 round19 登记第 5 项。** 这一条必须写进 ADR 0049 的 Consequences，收口时不许讲成「活体数字进 CI 了」。要闭合它得回放含模型的整条问答链，代价高一个量级。
- **票 65 的触发原文逐字成立**：`round19-spec-trust-observability.md:131`（登记第 4 项）写的是「有人提出一条能机器判定『任务是否办成』且现有门禁承载得了的判据」——本轮 spec §3 提出了这条判据（只读 `plan[]` / `context.ruleIds` / `fallbackReason` 三个既有字段，零新增后端代码、零新增探针），**故是「触发已到」而不是「政策越过」**。
- **票 67 的排除理由已被技术路径推翻**：ADR 0024 把「最小告警集」列为非目标，理由是「本机无 Prometheus 与 Alertmanager 实例，**写了只能证语法、证不了该响时会不会响，正是这条判据要拦的自述**」；而它说的「这条判据」是同一份 ADR 立的总筛子 ——「一项改造只有能在本仓以 **0 token、不依赖一次性活体读数**的形式被机器复跑证明，才进本轮范围」。`promtool test rules` 是**纯离线**的告警规则单元测试：喂合成序列、断言**该响时响、不该响时不响**，证的正是 ADR 0024 说「证不了」的那一句，且满足那条筛子。**因此 ADR 0024 排除告警的核心理由不再成立，ADR 0030 第 5 条的触发线随之真正达成**（原文：「本仓任何一天出现可机器寻址的 Prometheus/Alertmanager 形态（含 CI service container），该否决自动失效」）。它与票 64/66 的「政策越过」性质完全不同，**不许混为一谈**。
- **票 66 是本轮最弱的一票，可无损删。** `shoppilot_llm_tokens_total` 的三个来源计量方法不同（`MockLlmClient.estimateTokens()` **估算**、`OpenAiCompatibleLlmClient` / `OllamaLlmClient` 用 provider 回报的 **真值**）却共用一个名字、无标签区分。模式在部署期固定，所以同序列内不混方法 —— 缺的是**口径声明的机器可读性**，不是测量正确性。给现有计数器加 `source=provider|estimate` 标签（**名字不变 → 指标名计数不变**，照票 47 的 `result` 标签先例）；**红线：不改 `TokenBudget` 的放行语义**。
- **两处「不许」**：不许为让结果变绿改任何判据/阈值/gold/分母；不许为放行自己收窄门禁（round20 `F1c` 的教训）。

非目标（本 ADR 不授权）：

- **闭环侧的一切**（工单回流、`REFUNDED` 终态推进、输入侧上下文裁剪、知识反向沉淀自动咬合、批量向量化）：沿用 round19 登记节，触发条件不变（见 round21 spec §7）。
- **L2 阈值 0.95 / rerank / 知识纪元的物理 purge**：禁区，一个字都不改。
- **`feedback` / `plansteps` 两条活体红、拦截率 74% vs 80% 裁决**：判据一字不改，按登记保留。
- **票 64 不闭合 round19 登记第 5 项**（见上）；**票 67 不接任何真实 Prometheus/Alertmanager 实例**，也不声称规则在生产会响。

Considered Options:

- **只开「触发已到」的 65/67，64/66 继续登记**：否决。轮次被拆成两次开轮，而「机器背书」这条主题被打断；且 64/66 的政策成本（建夹具家族、加一个标签）与 65/67 相当，一次开完更省协调。
- **票 64 讲成「登记第 5 项的触发已成立」**：否决。循环论证。
- **票 65 并进 `eval_suites.py`**：否决。`round19-spec-…`（登记第 4 项）**逐字要求**「新增独立评测模块（`eval_suites.py` 形态）比改现有 gold 安全」——改现有文件会撞 `verify_eval_judge.py:218/221` 的精确断言与 CI rescore 差异集合。
- **票 65 给 task_done 一个总分或并进四列百分比**：否决。四列是单维请求质量，`task_done` 是端到端终局；混进同一分母会让「四列全绿而任务没办成」这个**它要抓的形态**重新隐身。
- **票 66 新增一个指标名承载 source**：否决。名字一变指标名计数就变，而这个标签要的是「口径声明的机器可读性」，加标签即可达。
- **票 67 只写规则不写测试**：否决。那正是 ADR 0024 说「证不了该响时会不会响」的形态，等于把已推翻的排除理由重新捡回来。

Consequences:

- 冻结线对 round22 之后继续有效；本轮结束后回到 ADR 0031 机制，**不自动续期**。五票独立可交付，中途冻结任意时刻项目仍自洽（65/66/67 甚至不需要票 64）。
- **票 64 会给 CI 加第 6 步**（现五步 → 六步），并新增一个 append-only 的夹具家族（`eval/retrieval-fixture-<date>.json`）；`rrf()`（`:198`）改**包级可见**（零行为改动）。
- **票 67 会在一个刻意保持零依赖的 CI 子集里引入一个需下载的二进制**（promtool）——这是本票的真实代价，写进 ADR 0051；其余步骤仍 0 依赖。
- **票 65 会新增一列公开读数**（`task_done`），单独报、不给总分；`unverifiable` 条数与比率一起报。README 的评测口径段要同步。
- **票 66 不改变指标名计数**（只加标签），故 round22 收口时指标名计数应以现场 grep 现算为准（round21 收口为 53，若 64/65/67 未新增指标名则仍是 53）。
- round22 收口（票 68）必须把 spec 登记节、`docs/EVIDENCE.md` 新读数、tracker、`docs/CODE_MAP.md`（`knowledge` 与 CI 步）、收口审计 `ROUND_FP`/`G6_EXPECT` 换代，并**如实登记未达成项**（票 67 不得声称生产会响）。
