# round32 开轮：把「通用客服」从形容词变成两个能跑的场景，并把「租户」收敛为唯一概念

Date: 2026-10-17　Status: Accepted　Owner ruling: 2026-10-17「按 round32 计划实现」。
Tickets: 票 117-123（见 [`round32-spec-generic-customer-service.md`](../../.scratch/shoppilot-mvp/round32-spec-generic-customer-service.md)）。

Context:

- 本轮的现实问题不是「功能不够」，而是**画像不清**：仓库里已经有一套能跑的多租户客服链路，
  却没有任何一处让**业务侧读者**（客服主管 / 运营 / 产品）在三分钟内复述出「谁在问、问什么、
  走哪几步、哪一步转人、什么情况办不了、现在哪段没通」。第一屏被架构与指标占据，读者要靠
  自己从工程叙事里反推业务，于是「通用客服」停留在形容词层，demo 感来自**没有具体的一进一出**。
- 本仓此前所有多租户主张都用**同一套电商语义**（同一条政策话术、同一批工具）证明，跨行业
  从未落成可运行实例。「换知识库就换场景」这句话因此无法证伪，也无法被业务读者核验。
- 计划（所有者 2026-10-17 提交）给出的手段是：一个具体门面场景（鲜果驿站 T002 死蟹理赔：
  六小时窗口、按只折算、需订单核验，且存在「系统不能看照片定责、必须转人」的真实边界）+
  一个跨行业对照（酒店入住与退改规则：**纯咨询、零工具依赖**），用两个都可跑的实例证明
  「同一套代码，换一套知识库就换一个行业」。
- 本轮同时要落一处**术语收敛**：`CONTEXT.md` 现有的「**租户 / 店铺**」把两个词并列成同一个
  概念，读者分不清「隔离单位」到底叫租户还是叫店铺。按 `AGENTS.md`，术语表变更**必须由 ADR
  明文覆盖**，实现者不得自行改写——本 ADR 就是那处覆盖。

Decision:

1. **开 round32，性质是所有者政策覆盖，不是 ADR 0030 / 0031 的触发已到**（`RELEASE.md` Freeze
   policy 第 4 条）。本轮**不自动续期**：round32 收口即止，后续工作照旧回到触发线或所有者显式
   裁定。交付面 = 业务一页纸 + README 首屏降级 + RELEASE 换代指针 + 两个可跑实例。
2. **术语收敛：`租户 (Tenant)` 升为唯一概念，「店铺」降为电商域内的业务叫法**。`CONTEXT.md`
   的「租户 / 店铺」条目改写成：租户是数据隔离、缓存分区、限流配额与政策归属的**唯一单位**；
   「店铺」只在电商语境里作租户的业务叫法（一家电商店 = 一个租户），酒店这类非零售租户不叫
   店。**逐字改写落 `CONTEXT.md`，本 ADR 是它的授权来源**。其余术语条目不动。
3. **新增 `Intent.POLICY_HOTEL` 与酒店租户 `T004`（云栖酒店）**。酒店域是**纯咨询域、零工具
   依赖**：本仓没有酒店办理工具，所以它只回答规则文本，绝不触发订单类动作。这既是演示对照
   的要求，也是诚实的能力边界——「咨询域可换知识库，办理域必须新增工具与意图」。
4. **酒店知识库按 `tenant_id: T004` 入库，刻意不挂 `PLATFORM`**。检索可见范围是 `tenantId +
   PLATFORM`；平台级语料对**所有**租户可见，把酒店政策挂上去会污染全部电商租户的检索结果。
   这条是隔离红线，不是可选项。
5. **评测：酒店用例单独成列（`eval/cases-part9-hotel.jsonl`，`kind: hotel`），不并入 180 条
   gold**。把新用例并进 gold 就动了分母与 CI 的 rescore 基线，违反仓库红线（不为凑绿改分母）。
6. **公开交付面以业务一页纸为主**：`docs/round32-two-runnable-scenarios.md` 承担「谁 → 遇到什么
   → 走哪几步 → 哪步转人 → 哪个域换知识库就换、哪个域换不了 → 哪段未通」的完整叙事；
   README 首屏降级为**指路牌**，不再与工程读者争第一屏；`RELEASE.md` 只加换代指针、不改正文。
7. **新意图的同步成本要对外讲**：接一个新行业＝改四处（`Intent` 枚举、`T0RuleLayer` 词表、
   `MarkdownChunker` 入库前缀映射、评测集），加知识库与租户行。**「按这个流程接一个新行业要改
   哪几处」本身就是本轮可对外讲的结论**，写进一页纸，不藏进代码注释。
8. **与 ADR 0007 的两处冲突，明文登记（不改既有 ADR 结论）**：
   - **意图数突破 10 封顶**。ADR 0007 Context 写死「意图清单封顶 **10** 个」。本 ADR 加
     `POLICY_HOTEL` 后是 **11** 个。这是**所有者政策覆盖**（本轮授权）下的**有意偏离**，不是笔误；
     ADR 0007 的原文与封顶结论**照旧保留**，由本 ADR 承担这次越过的登记。将来若要继续加意图，
     每次都要重新说明理由，不自动续期。
   - **ADR 0007 的「四处」里「限流统计」在本仓不可观测**。ADR 0007 Consequences 写「意图清单是
     缓存分区、工具裁剪、限流统计、评测集共用的唯一枚举」。按仓核实，前三处只有两处成立：
     缓存分区走 `CacheService.lookup/writeNegative`（按 `Intent` 分区）、工具裁剪走
     `AgentStateMachine.toolsFor`（按 `isAction()` 分流）、检索过滤走 `HybridRetriever`（按
     `Intent` 过滤）；而**限流**（`ratelimit/RateLimitService`）的键是**租户 + 买家/IP**，
     **没有意图维度**，也找不到任何以 `intent` 为 tag 的 meter。**因此本轮不声称「限流统计自动
     生效」**——`POLICY_HOTEL` 不需要改限流。ADR 0007 那句「限流统计」是继承来的、未经本轮核实的
     说法，**照登为既有文档缺口**，不据它写实现或对外结论。**新行业实际要同步的是两处自动
     （缓存分区 / 工具裁剪）+ 检索过滤 + 评测集**；改一处枚举并不会「顺带」把限流统计改成按意图。

Considered Options:

- **不做具体场景，继续用「支持多租户」措辞**：否决。这正是本轮要治的病——形容词无法被业务读者
  核验，也无法证伪。
- **酒店域也接办理工具（订房 / 改期）**：否决。办理域要新增工具契约、意图、状态机分支与全部
  判据，「换知识库就换行业」这句话会被稀释成「换什么都不够」；纯咨询对照反而把边界讲清楚。
- **酒店语料挂 `PLATFORM`**：否决。会污染所有电商租户的检索结果（决策 4）。
- **把酒店用例并进 180 条 gold**：否决。动分母，违反红线（决策 5）。
- **改写 `CONTEXT.md` 而不过 ADR**：否决。`AGENTS.md` 要求术语变更由 ADR 明文覆盖。
- **重排 `T0RuleLayer` 让酒店词表复用通用动作逻辑**：否决。酒店是纯咨询，通用动作逻辑会把它
  判成 `ACTION_*` 并挂上全套电商工具（`AgentStateMachine.toolsFor` 实测：动作意图下发全部业务
  工具），酒店问句于是拿到 `QUERY_ORDER`、被动作意图踢出缓存准入，「0 token 命中」当场失效。

Consequences:

- **`Intent` 是共享枚举，加一个值要同步四处**（缓存分区 / 工具裁剪 / 限流统计 / 评测集）：
  缓存分区走 `isPolicy()` 自动生效；工具裁剪走 `isAction()` 自动生效（政策不下发工具）；
  限流统计按意图计数自动生效；评测集新增 `kind: hotel` 分区。**四处同步是预期成本，不是缺陷。**
- **多一个质心会改变 T1 最近邻地形**：加 `POLICY_HOTEL` 后 `intent-samples.json` 的质心集合变了，
  `MIN_CONFIDENCE` / `MIN_MARGIN` 的标定结论必须**重跑 180 条标定重验**，不许凭手感沿用。
- **`CONTEXT.md` 术语变更影响面**：文档里凡引用「租户 / 店铺」并列的地方以租户为准；代码标识符
  不动（`TenantContextHolder` 等本就用租户），种子店铺名以 `knowledge/` 语料为准对齐。
- **收口审计读数以实测为准换代**：入仓的 `G6_EXPECT` 与 `PASS/FAIL` 是 round22 的落点，本轮
  收口按新鲜 JVM 实测换代，**不为凑绿改判据**；对外一页纸不复述指标数字（数字仍只在 `README.md`
  与 `docs/EVIDENCE.md` 维护，不做第二份数字表）。
- **真人 cold-read 是主判、模型读者是辅证**：找一位真实业务侧的人只看一页纸 3 分钟、回答五个
  问题，这次**不能再记成「待执行」**；脚本化重跑五个问题只作防腐化辅证，两者分工写明、不互相冒充。
