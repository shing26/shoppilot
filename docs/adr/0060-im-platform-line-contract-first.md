# IM 平台接入：先契约可复现，真连待可行性考察

Context: 所有者的目标是把这个仓做成**可接入各 IM 的客服平台**，并让**同一个客服 agent 在不同平台上对同一个人是可复现的**。2026-10-04 的 grilling 把这件事拆成了三问，逐一核对代码后得到三个事实：

1. **缝已经在**：入站有 `ChannelAdapter` 归一契约，出站有 `channel.outbound`（ADR 0059 round26 落），渠道不进缓存键、不参与身份推导（ADR 0035）。所以这不是发明架构，是把 mock 适配器换成真的。
2. **两个平台无关的缺口现在就在**：`ChannelAdapter.NormalizedChat` 只有 `(query, idempotencyToken, contact)` 三格，**没有 `conversationId`**——今天走 webhook/email 的调用方不自己传 `X-Conversation-Id` 头的话，`AuthFilter` 每次现生成一个随机 UUID，**每条消息都是全新会话、追问必然断**。而幂等派生 token（`IdempotencyService.resolveToken`）是 `tenantId|customerId|tool|参数`，**不含渠道且 TTL 6 小时**，客户端不给 token 时靠参数猜「哪两次是同一次提交」。
3. **真连今天不成立**：企业微信 / 钉钉 / 飞书的收消息都要配**公网 HTTPS 回调**（外加各自的 token / 签名校验），本机没有稳定公网地址；Telegram long polling 与 Slack Socket Mode 免公网，但**在这台机器上能否连通未实测**。

Decision:

1. **主线分两段，A 段（契约可复现）先做，B 段（真连）的开关交给一次独立的可行性考察**（票 98），不预先假定 B 一定能开。
2. **平台无关的两格先行**（票 96）：`NormalizedChat` 补 `conversationId`；适配器**必须**从平台 message id 派生 `clientToken`。这两格任何平台都���要，且**完全能在 CI 里验证**。
3. **A 段只接一个平台**（避免退化成「为假想的适配器写抽象」，裁定 C 的同一条纪律）。选择标准是「入站事件 JSON 能否录制成夹具 + 归一结果能否断言」，**不是哪个平台最流行**——各家的入站事件都是公开的结构化格式，A 段选谁的成本差别很小；**真正的选择发生在票 98**。
4. **录放门**：A 段的证据形态是「录制的 IM 事件 JSON → 归一 + 幂等派生 + 会话键」的 0 token CI 门禁，与 ADR 0049 的检索录放门**同款**（那条路子在本仓已证明可行，它当时还补上了「CI 里没有任何断言在守检索排序」那个洞）。
5. **暴露面红线**：任何隧道 / 公网方案**只能放行回调路径 + 强制平台签名校验**；ops 端点（故障注入、清缓存、队列）一律不对外。**未做暴露面审查之前不开 B 段。**
6. **身份模型本主线不动**：平台用户 id（企业微信 `external_userid`、飞书 `open_id`、Slack `member_id`）与仓里的 `customerId` 之间**没有映射表**，也不在本主线建。理由：那是数据模型级的改动，而它一旦做错就是跨租户泄露——本仓已被咬过三次（`findById` 不拼 `@TenantId` 两次、分流规则跨店劫持一次）。**「同一个人跨平台是同一个身份」明确不是本主线的交付内容。**

Considered Options:

- **先接最流行的平台（企业微信）**：否决。它的收消息必须公网回调，而这正是今天不成立的那一格；先接它等于第一步就撞在暴露面上。
- **A 段做「平台无关的 IM 事件骨架」**：否决。那是为假想的适配器写抽象，正是本仓明禁的 speculative generality。
- **把「平台」做成配置而不是适配器**：否决。IM 协议不统一（签名、事件形状、会话模型、限流各不相同），配置化最后会变成一个带 40 个开关的适配器。
- **现在就把「跨平台身份统一」一起做**：否决。它在数据模型层，且比整个 IM 主线都大；混在一起会让 IM 那一段永远处于「还在改地基」的状态。

Consequences:

- **本仓「每条能力都能在干净 runner 上复现」这条属性部分保留**：A 段完整保留，B 段必然打折——那一格**必须照登**，不许含糊过去。
- **对外表述不得说「已接入 XX 平台」**，只能说「适配器契约可复现」或「真连已验证」。含糊的措辞会把一句无法核对的话钉进交付材料。
- 平台选择**推迟到票 98**，A 段选的平台有可能在 98 之后被换掉——因此 A 段的产物是**录制的夹具**，不是「接入了某家」这件事。
- 本主线的名字不该是「多平台客服系统」，它是「**IM 适配能力**」。前者是产品主张（要改写 ADR 0052 的「不宣称上线」），后者不是。
