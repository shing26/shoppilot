# 三级级联意图判定，且不为分类单开模型请求

Context: 任务书要求区分静态规则检索与动态交易动作，但未定义意图来源。若意图分类依赖一次独立 LLM 调用，缓存省下的模型开销会被分类器原样花回去，缓存收益归零。决定：三级级联判定，成本递增、能早停即早停——L0 规则层（实体正则 + 关键词表 + 所有格动作词表，<1ms，判定 cacheable/dynamic）、L1 向量层（每意图 8-15 条样例句取质心做最近邻，复用 L2 语义缓存那一次 bge-m3 向量化）、L2 模型层（仅 L0/L1 均不确定时进模型）。进模型时 tools 全量随请求下发，由模型是否返回 `tool_call` 充当意图证据，全程只有一次模型请求。

意图清单封顶 10 个：`POLICY_RETURN` `POLICY_SHIPPING` `POLICY_PROMO` `POLICY_FRESH` `ACTION_ORDER` `ACTION_LOGISTICS` `ACTION_ADDRESS` `ACTION_REFUND` `ESCALATE` `UNKNOWN`。`UNKNOWN` 是显式意图而非异常，fail-closed 不查缓存，模型也判不动则转人工。

Terminology note（2026-09-08 补）：本 ADR 原文把意图三级写作 `L0` / `L1` / `L2`，与缓存两级 `L1 精确` / `L2 语义` 撞名，是同一份文档里两套序号指两套东西的语言事故。现统一为 `T0 规则` / `T1 质心` / `T2 模型`；`L1` / `L2` 保留给缓存分层。见 `CONTEXT.md`。

多意图取**动作优先**：动作链路可顺带注入检索到的政策上下文，反向不成立，因为政策答案被禁止输出断言式个性化结论。

Consequences:
- 缓存准入不再纯靠关键词表，代价是规则表与样例句集两份资产需持续维护，且都要进版本控制。
- L1 给缓存链路增加一次向量比对（约 10ms），换来意图判定质量；TP99 30ms 预算需为它留出余量。
- 意图清单是缓存分区、工具裁剪、限流统计、评测集共用的唯一枚举，新增意图需同步这四处。
