# 收口轮的新证据按拆口处置，未做项一律挂触发式重开条件

Context: round14 定位为收口轮——只做 ADR 0024 筛子未排除的外壳项、记账收口、外加本 ADR 回答「为什么停在这里」。同一天的独立取证复核带来三条 P0 与一条 CI 判断，正面撞这个定位：README 自述「JVM 无日志消失、没有 hs_err、归因未定」，而 14 份崩溃日志一直躺在仓库根，且全部可归因到 native 内存 OOM；写回线程池饱和时请求线程替池去付一次 Redis 写加一次 Qdrant upsert，34 个指标无一格覆盖这件事；「转人工 = 落可查工单」这条否决项的「可查」，被看门狗的「失联即重启 + seed 全量」顺手抹掉——而那复位居然是压测与三条演示的复位机制本身。CI 被同时判为「唯一比现有票面更符合 0024 筛子的候选」。收口轮不许悄悄扩面，但知道而不写下来更糟。

决定：本轮定位不变，四条新证据按拆口处置——

- **P0-A（崩溃归因）整条进本轮**（票 31）：读那 14 份日志出归因表，README 的「归因未定」改有因结论；三个 headline QPS 数字旁边把当时的主机内存与 CPU 条件从「已知限制」提到数字旁；两个起栈脚本给 JVM 设显式堆上限，并明写「此后起栈带显式上限，历轮压测读数按当时状态原样供着」。
- **P0-B（写回饱和没有指标）拆半合并**（票 27 + 票 29）：行为那一半（`caller_runs` 计数、队列深度暴露、停机丢弃计数）进票 27 的写回池 seam——只有自造 seam 才包得出带计数的拒绝策略，裸线程池数不出「多少次被请求线程代跑」；观测那一半（饱和 gauge 与 counter）作票 29 第四组，与前三个「值随状态变、不随请求变」的形状同构；「命中路径 TP99 是未饱和队列下的读数」这句口径进票 30。
- **P0-C（reseed 抹工单）本轮不做但有主**：票 30 把「可查」的作用域在 README 写成整句；工单持久化与 RESOLVED→买家回流两条差距登记进生产就绪评估；重开条件见下第 2 条。
- **CI 子集本轮不做但有主**：作下一轮第一票，重开条件见下第 1 条。

## Considered Options

- P0-C 最小真修（biz-mock 的内存库改文件持久化 + seed 改幂等）：否决。「重启即 seed 全量」同时是演示世界的复位机制——每次起栈拿干净世界、压测档档可重复靠的都是它；要持久化就得先回答「审计留痕 vs 一次性演示世界」的职责分家，那是 biz-mock 的数据所有权重设计，不是收口。
- P0-C 网关侧加工单审计副本：否决。副本与真单之间没有一致性协议，多出一个看似权威的第三本账。
- P0-B 独立成票：否决。同一个 seam 被两票先后改两次，是收口轮不该有的形状。
- CI 本轮加一票（只跑「构建 + JVM 单测」档）：否决。它确实过筛——ADR 0024 当年否决的是全量 17 步门禁形态（要 Ollama、ES、Qdrant 的那个理由对子集不成立），但子集在异机上该判什么红本身要单独磨，硬挤进本轮会让停机窗口与指标面给新面让路。
- 拦截率 74% 那格当场改判「架构下不可达」：否决。摘红是判据面动作，本轮铁律是判据与阈值零改动；只允许在红的旁边记一句事实。

## Consequences

- 重开条件一律写成触发式：触发前不做是决定，不是遗忘；触发即自动回到射程，不必重新论证该不该做。
  1. **CI 子集门禁**：下一轮开工第一票，不需要任何外部事件。例外：若异机跑通该子集需先偿还本轮落下的债（例如测试隐性依赖本机状态），偿债票排它前面。
  2. **工单持久化与 RESOLVED→买家回流**：触发 = biz-mock 被真工单系统替换（投产前置本身）。在那之前，「进程生命周期内可查」是本仓官方口径，不算欠账；「可查工单」的定义进 `CONTEXT.md`。
  3. **action-only 分意图数上头条**：触发 = 有人提出一条新判据，能机器判定「哪个数字配当头条」且现有 17 步门禁承载得了。纯观点之争不开这条——同一份产物里 REFUND 94.4% 与 0.0% 两种读数并存 94 点之差，靠散文调和撑不到下一轮。
  4. **拦截率 74% vs 80%**：触发 = 任务书指标定义与 ADR 0003 缓存准入规则的冲突被显式裁决（改定义或改架构，二选一写成新 ADR）。在那之前红照挂，旁边只有「冲突已知、裁决挂起」的标签。
  5. **最小告警集**：ADR 0024 的否决理由（本机无可打实例、写了只能证语法）自带过期条件——本仓任何一天出现可机器寻址的 Prometheus/Alertmanager 形态（含 CI service container），该否决自动失效。本轮票 29 的 `transition_total` 正是为那天做的前置。
- P1 挂账清单（登记、不排优先级，除上述四条外本轮未裁决归属）：语义缓存写回失败无计数器、会话存储 fail-open 无指标、熔断只保护业务 Mock、调试台排印组（小字中文叠大写惯例的字距、无减动效偏好、无焦点样式声明、断点单一）。「摘掉必判错」的本仓信条在语义缓存写回上没有执行——与负缓存计数器注释里自己写的标准不符，这条记在票 30 的账上，改不改归下一轮。
- 指标名计数：全仓 grep main 现算为准。本轮 34 这个数在 README 成立（复核过）；票 29 落地后必然换代，换代时写明数法，不抄旧格数。
