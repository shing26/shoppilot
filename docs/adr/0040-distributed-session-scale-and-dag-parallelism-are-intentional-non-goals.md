# 十万级会话总线与多工具并行编排是有意不做，各带触发条件

Context: 对标架构含 Redis Streams 十万并发会话与多工具并行调度。round17 评估确认这两项不是模块缺口而是部署形态差异：前者需要多实例拓扑，后者在单机 22ms 命中 P99 的量级下没有可观测收益。按 ADR 0024 纪律，把"没做"改写为"有意不做 + 触发条件"，审计时不算遗忘项。

Decision:

| 项 | 有意不做的理由 | 触发条件（满足才重开） |
|---|---|---|
| Redis Streams 会话总线 | SessionStore 已是 Redis；并发已实测 800 档 0 错误；十万级是拓扑问题，单实例上换数据结构不改变任何结论 | EmailAdapter 等渠道被迫同步等待长任务，或出现第二实例部署 |
| 多工具并行 / DAG 编排 | 两个工具 + 22ms 缓存命中世界里，并行收益低于归属校验与幂等语义的复杂化成本；ADR 0008 的时延预算论证仍成立 | 出现真实"三步以上且步间无依赖"的意图，且工具 P99 > 500ms |
| 真实渠道集成（微信/IMAP） | 外部凭据与外网可达性违反单机边界 | 项目定位变更，WebhookAdapter 契约被真实方消费 |
| 满意度自动回流再训练 | 无训练管线与数据规模 | 出现可寻址的离线训练环境与真实语料积累 |

Considered Options:

- 硬补 Streams 以"数字对齐"对标架构：否决。换数据结构刷不出真实性，单机 800 并发 0 错误是更诚实的数字。
- 并行编排作为"加分项"先做着：否决。ADR 0036 已把 Plan 收敛为 ≤2 步串行，并行走向与其直接冲突，两套执行语义不可共存。

Consequences:

- 本 ADR 是 round17 范围的收口边界；四项在触发条件满足前只登记不执行。
- README 已知限制章节按本表改写，全部从"未做"改为"在当前定位下有意不做，触发条件为 X"。
