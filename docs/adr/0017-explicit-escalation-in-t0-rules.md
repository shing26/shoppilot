# 显式转人工写在 T0 规则层，不由 embedding 可用性决定

Context: ADR 0007 的三级级联把最便宜的 T0 放在最前面，但转人工（ESCALATE）当时只存在于 T1 质心与 T2 模型里——规则层没有它。2026-09-09 的验收跑出了这道缝隙：08:49:21 网关日志记下一次 embedding 超时（`向量化失败（Ollama 是否已启动并 pull 了 bge-m3？）: request timed out`），T1 拿不到向量，`TriageEngine` 按 fail-closed 把用户那句「转人工」降级成 UNKNOWN 交给模型定案。验收脚本第 7 条等了近 25 秒，拿到的是模型自述，既没有 fallback 帧也没有工单。七种降级原因里其余六种都不依赖 embedding，唯一依赖它的恰恰是"用户亲口喊人来"这一条。

决定: 显式转人工词表（转人工 / 转个人 / 人工客服 / 真人客服 / 人工服务 / 转接人工 / 人工介入）进 T0，并排在实体与第一人称判定**之前**——"90001 这单搞错了，转人工"要的是人，不是订单查询。命中即 `TriageResult.dynamic(ESCALATE, "T0", false)`：不碰 embedding、不碰模型、不准入缓存（与 ADR 0006 的写回资格一致）。否定形式用紧邻窗口排除：关键词前 2 个字符内出现 不/别/莫/没/无需/取消/拒绝/退出 即不算求助，「别转人工」不触发；不做整句否定扫描，否则「这个不合规，转人工」会因句中有"不"而漏判。

Considered Options（已否决）：把 embedding 超时调大（只是把问题往后推，Ollama 真卡住时照样复现）；在 `TriageEngine` 里给 ESCALATE 单开一条"embedding 失败时的兜底词表"（等于在级联之外再写一份分类规则，两份词表必然漂移）；把这条性质交给模型定案（多付一次调用与秒级时延，而这次调用本身也要依赖模型服务可用）。

Consequences:
- 串号防线不受影响：T0 定案的 ESCALATE 与 T1/T2 出来的同样 `cacheAdmissible=false`，缓存里没有它的位置。
- 只保证字面显式表达这条最低可用线。paraphrase 型求助（"叫你们经理过来处理"）仍走 T1/T2，embedding 不可用时照样 fail-closed 进模型——转人工的整体可用性由三层各自兜底，不由 T0 独扛。
- 工具调用评测是走网关端到端的，显式样本从"模型定案"变成"T0 定案"，因此 `eval/results` 的 ESCALATE 行要按改动后重跑为准，旧数字不能继续沿用。
- 由 `T0RuleLayerTest` 三组新用例钉住：T0 定案且不准入缓存、优先于实体与第一人称、否定窗口边界（正反两例各一条）。
