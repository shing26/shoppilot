# 告警最小集能进 CI 了：`promtool test rules` 推翻了 ADR 0024 的排除理由

Context: 本 ADR 由 round22（ADR 0048）的票 67 触发。本仓**零告警规则**（无任何 `*.rules.yml`/`*alert*`/`*prometheus*`，round21 复核过）。ADR 0024 曾把「最小告警集」列为非目标，理由是：

> 本机无 Prometheus 与 Alertmanager 实例，**写了只能证语法、证不了该响时会不会响，正是这条判据要拦的自述**。

而 ADR 0024 说的「这条判据」是同一份 ADR 立的总筛子 ——「一项改造只有能在本仓以 **0 token、不依赖一次性活体读数**的形式被机器复跑证明，才进本轮范围」。同时 ADR 0030 第 5 条为该否决挂了过期条件：

> 本仓任何一天出现可机器寻址的 Prometheus/Alertmanager 形态（含 CI service container），该否决自动失效。

Decision:

**一、排除理由被技术路径推翻，故本票是「触发已到」，不是「政策越过」。** `promtool test rules` 是**纯离线**的告警规则单元测试：喂合成序列、断言**该响时响、不该响时不响**。它证的正是 ADR 0024 说「证不了」的那一句，且满足那条总筛子（0 token、不依赖活体读数）。**ADR 0024 排除告警的核心理由因此不再成立，ADR 0030 第 5 条的触发线随之真正达成。** 它与票 64/66 的「政策越过」性质完全不同，**不许混为一谈**（ADR 0048 逐字记了这条）。

**二、规则最小集：4 条，全部引用真实指标名。**

| 规则 | 表达式（引用真实指标名） | 该响的含义 |
|---|---|---|
| 依赖不齐 | `shoppilot_dependency_up == 0` | 向量 / 词法 / 语料三格有不 UP |
| 业务中台熔断打开 | `shoppilot_circuit_state == 1` | 熔断器已打开，业务调用被本地挡下 |
| 业务调用失败 | `rate(shoppilot_tool_timeout_total[5m]) + rate(shoppilot_tool_unavailable_total[5m]) > 0` | 超时或不可用真的发生了 |
| 降级率超阈 | `rate(shoppilot_fallback_total[5m]) / rate(shoppilot_requests_total[5m]) > 0.2` | 降级占请求的比例越线 |

**副作用很好**：规则引用真实指标名 → **谁改了指标名，告警测试当场红**（这是本票顺带换来的一个额外守卫）。

**三、引入方式：CI 新增一步，`curl` 固定版本 promtool 二进制 + 打印并校验 sha256。** 这是把外部依赖**局限在一步之内**、可 pin 可审。其余步骤仍 0 依赖。**这是本票的真实代价**（往一个刻意保持零依赖的 CI 子集里加一个需下载的二进制），记在这里，收口时不许含糊过去。

**四、红线：不得声称这些规则在生产会响。** 本票证明的是**规则在该响的合成序列上确实响**，以及**不该响时确实不响**；它不证明本机或任何生产环境挂了 Prometheus、也不证明告警会送达。README / EVIDENCE 的措辞必须守住这条。

Considered Options:

- **只写规则文件、不写 `promtool test rules`**：否决。那正是 ADR 0024 说「证不了该响时会不会响」的形态，等于把已被推翻的排除理由原样捡回来。
- **用 `prom/prometheus` 官方容器镜像跑**：否决（本轮）。免去自己散落二进制版本，但要把「拉镜像」引进 CI —— 仓库其它 0 token 步都不碰 Docker，本机与 runner 的行为差异风险更大。
- **把 promtool 二进制提交进仓**：否决。~100MB 二进制入仓，且升级要走提交而不是改一个版本号。
- **接本机已有的 Prometheus 实例**：否决。那是别的项目的容器（跨项目边界），且会把「规则对不对」与「实例挂没挂」搅在一起。
- **把告警规则写进 `application.yml` 或 Java 代码**：否决。告警规则的形态就该是与 Prometheus 生态一致的规则文件，否则 `promtool` 用不上、未来也搬不走。

Consequences:

- **CI 子集从五步（round22 票 64 之后为六步）再加一步。** 六步与七步的顺序在 spec 里写死：构建与 JVM → 判据自检 → 离线 rescore → 套件夹具 → **检索录放门（票 64）** → 覆盖率棘轮 → **告警规则测试（票 67）**。票 67 排在覆盖率之后，因为它需要一个额外下载的二进制，失败时不该拖住已有的 0 依赖步骤。
- **指标名是这套规则的接口**：改名即红。这与 round22 票 66「加标签不加名」的选择相容 —— 票 66 不改任何规则引用。
- **不新增任何真实 Prometheus/Alertmanager 部署**；本票不闭合 ADR 0030 第 5 条的「接上真实实例」那一半，只闭合「否決自动失效」这一半。下一半的触发条件保持原样。
- 收口时 `docs/CODE_MAP.md` 的 CI 步与 `docs/EVIDENCE.md` 要同步；`ROUND_FP`/`G6_EXPECT` 按仓库家法换代。
