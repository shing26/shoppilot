# 编排自研并只留一条 provider 缝，换框架是适配而不是重写

Context: 本仓的编排层（`agent/AgentStateMachine` 665 行 + `agent/ToolDispatcher` + `llm/LlmGateway`）是自己写的：10 个状态、工具循环硬上限 2 轮（ADR 0008）、纠偏轮、缓存读与写回资格（ADR 0006、0018）、singleflight、Triage 三级级联的 fail-closed（ADR 0003、0007）、7 种降级 reason 落工单、逐状态 `step()` 事件与 34 个指标。这些不是实现细节，它们是**对外数字的承重件**：`perf` 模式固定延迟 Mock 是压测与 TTFT 曲线的基准（ADR 0001），归因那句「725 ms 里 300 ms 是 Mock 首字下限、311 ms 是本机 bge-m3、只有 104 ms 是网关编排」只有在编排自己手里时才成立。主流替代是 Spring AI 与 LangChain4j：Spring AI 1.0.0 的 starter 实测依赖 `spring-boot-starter 3.4.5`（本仓 `spring-boot.version=3.3.5`），当前 GA 已到 2.0.1；LangChain4j core / open-ai 都是 GA `1.20.0`，但其 Spring Boot starter 最新仍是 `1.20.0-beta30`。两者的卖点（自动工具循环、ChatMemory、VectorStore 抽象）与本仓已有的编排、缓存、检索、会话存储**正面重叠**，而重叠处恰好是判据所在。

决定：编排层继续自研，**只保留一条 provider 缝**——`llm/LlmClient`（`complete` / `stream` / `mode` 三个方法）。任何模型或框架的引入都只允许发生在这一层，`AgentStateMachine` 的状态流转、工具循环轮数、缓存准入与写回、降级与工单、指标与 token 记账不得交给框架接管。`perf` 的 `MockLlmClient` 是压测量具而不是 provider，永久保留自写形态。

## Considered Options

- 替换式薄适配（把 `dev` / `local` 两个客户端换成框架实现，保留 `LlmGateway` 与状态机）：**方案成立，本轮不做**。它只降维护量（两个手写 HTTP 客户端约 430 行），不动任何指标口径，成本 1–2 天；但换来的收益是「用过某框架」，而本仓当前缺的不是 provider 实现能力。触发条件见下。
- 并存式薄适配（新旧客户端同时保留 + 开关双跑）：否决。同一时刻出现两条活跃编排路径，两条都要过测试与压测基线，故障时分不清是哪条在跑——这是「堆技术栈」在工程上的准确定义。
- 半替换（框架接管工具循环与会话，自家缓存、降级、指标仍在）：否决。工具调用会有两套循环（框架内部 vs 2 轮硬上限）、指标出现两处口径、框架的 ChatMemory / VectorStore 与自家缓存准入、写回、singleflight 重叠。框架的收益拿不到，自家的证据保不住。
- 彻底替换编排层：否决。成本 2–4 周（`agent/` 1549 行 + `llm/` 917 行 + 相关测试 5 个文件，另需重写工具 schema 的注解形态），且必须重挣全部证据：224 条 JVM 用例、17 步活体验收、`docs/EVIDENCE.md` 里每一条读数与归因口径、ADR 0020 的干净检出 ≤600 s。这条与 ADR 0024 的定位和 ADR 0030 / 0031 的冻结同时冲突。
- 「一开始就该选框架」：不采纳为现状辩护，但结论不变。ADR 0001 要求三态可切换且指标分口径，`local` 走 Ollama 原生形状、`dev` 要 OpenAI 兼容 base-url 加日预算熔断与故障注入——这些适配层任何框架都得写；同时 Spring AI 1.x 会把 Boot 从 3.3.5 拉高，引入它等于先升级再重验基线。选型的代价当年成立，今天仍成立，本 ADR 把它写成可核对的文字。

## Consequences

- 面试口径固定成一句：编排是我最需要被测量的部分（命中率、工具轮数、TTFT、token、降级工单），框架会把控制点收进去；provider 缝留在 `LlmClient`，换成框架是 1–2 天的适配，不是架构决策。
- 重开触发线（满足任一再开票，且仍需过 ADR 0031 的两条件：同一缺口被不同面试官问过两次、1 个工作日内可完成且不改判据阈值 gold）：
  1. **多 provider / 多模型路由成为主需求**（例如需要按意图或成本在同一次请求里切模型），自研客户端维护成本超过适配成本；
  2. **只有框架才有的能力成为某个目标 JD 或需求的前置**（MCP 客户端、ChatMemory、向量库抽象、图编排），且接入后仍能被现有指标口径逐格接住；
  3. **协作要求标准写法**（外部接手者要求按框架惯例组织编排）。
- 触发后走**替换式**而不是并存式：框架实现替换掉它替代的那个客户端，实现数量不增加；`MockLlmClient` 不动，压测基线不重测。
- 本 ADR 只登记选型与触发线，不构成功能重开，不新增依赖、不改任何判据、阈值、gold 或既有 ADR 结论。
