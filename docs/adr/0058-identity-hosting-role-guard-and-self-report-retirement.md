# 身份域由业务与工具服务承载，角色守卫取代自报身份

Context: [0056](0056-identity-domain-and-audit-stream.md) 定了「自建轻量身份域：用户表 + bcrypt + 自签 JWT + 登录/注册 + 角色守卫」，但**没有定它住在哪个进程**。这不是遗漏一笔就能过去的细节：[0053](0053-four-domain-service-split.md) 把服务清单钉成四个，并在 Considered Options 里以「每多一个 JVM 约 500 MB、本机全栈已约 7 GB」为由否决了第五个服务。而身份域在 0053 的清单里没有位置——它是横切关注点，不是四个业务域之一。

同时仓里现在有三处**自报身份**，它们都已经在注释里挂了自己欠的账：

- `OpsController` 的 `X-Agent`（坐席自称，转发给工单服务的 claim/release/resolve）；
- `RefundReviewController` 的 `X-Reviewer`（退款审核人）；
- `FeedbackController` 的 `X-Reviewer`（反馈复核人）。

三者都进 `audit` 事件的 `actor` 字段（`AuditEvent` 的 javadoc 就写着「坐席 id、`system` 或运维账号」）。**退款放行是不可逆的资金动作，而它的责任人现在是一个请求头。**

Decision:

1. **身份域由 `shoppilot-biz-mock` 承载**，以内部端点 `/api/identity/*` 暴露（`X-Internal-Token` 之后，与其余内部面同一信任层）。网关对外提供 `/auth/login`、`/auth/register`、`/auth/me`，并用已有的 `JwtService` 签发**带 `role` claim** 的令牌。
2. **角色三档**：`BUYER` / `AGENT` / `ADMIN`，随令牌下发，进 `TenantContext.Identity`。
3. **角色守卫落在网关**：工单动作（claim/release/resolve）与退款审核要求 `AGENT` 或 `ADMIN`。
4. **自报头退役**：认证身份在场时，actor 一律取自已验签的令牌（网关向下游发 `X-Actor`）；只有运维面凭证（见第 5 条）在场时，才回落到请求头并**显式标注该 actor 未经认证**。
5. **`X-Ops-Token` 不退役**，它是运维面凭证（故障注入、缓存清理、演示复位），不是用户身份。ADR 0029 对它的门控一字不改。两条线的分工写死：**ops token 守的是「不是随便一个人」，角色守的是「是谁」**。
6. 密码哈希用 `spring-security-crypto` 的 BCrypt（单 artifact，**不引整个 Spring Security**）；本仓依赖面因此 +1，在此登记。

Considered Options:

- **第五个服务（独立身份服务）**：否决。0053 的资源账直接适用——本机全栈已约 7 GB、当前可用约 1.9 GB，而身份域在演示流量下拿不到任何独立扩缩容收益。ADR 0056 自己也在 Considered Options 里以同一理由否决了 Keycloak。
- **放网关**：否决，但**不是因为功能不行**——网关是全栈唯一发签与验签的地方，看起来最自然。真正的问题是：网关目前**没有数据源**（无 JPA / Flyway / H2），加身份就要给全栈最重、延迟最敏感的那个进程再挂一个数据库栈；而且 0053 拆分的理由正是「不同演化节奏的域不该共用一个进程的心跳」，身份（几乎不变）与对话编排（一直在变）恰好是两端。
- **放工单与坐席服务**：否决。理由是数据局部性——账号的主体是买家，而买家、租户、订单都在 biz-mock；坐席只是三种角色之一，让工单服务为两种不相干的角色持有凭证面，是拿错的钱包。
- **用现成用户表框架**：否决，0056 已记。
- **直接废掉 `X-Ops-Token`**：否决。验收脚本、调试台、演示脚本全靠它，那批脚本是**判据面**；动它们的认证方式就是改判据。改成两条分工明确的线（第 4、5 条）而不是一条取代一条。

Consequences:

- **biz-mock 的域范围变宽**：0053 给它的定义是「订单、物流、退款、工具执行、审批闸门」，本 ADR 追加「身份与账号」。这是**有意偏差**，必须写进 `docs/CODE_MAP.md`，不能让后来者按 0053 的清单去找「身份在哪」。
- 网关登录端点要在内部链路上传明文口令。这条链路本来就是回环 + `X-Internal-Token` 的内部面，与其余内部调用同一信任层；但**它是本仓第一次让口令离开进程**，因此记在这里而不是省略。
- **登录是租户级路径，不是平台级放行**（实现期更正，2026-10-04 票 80）：用户名按 **(租户, 用户名)** 唯一而不是全局唯一——跨店同名是正常业务，按全局唯一等于逼所有店用一个命名空间。
  代价是登录表单必须先有租户（调试台与工作台本来就有租户选择器）。收益是 `/api/identity/*` 不用改 `InternalAuthFilter` 的放行规则，
  `users` 表也能照常挂 `@TenantId` 租户过滤器，不必给 ADR 0005 开例外。
- 审计事件的 `actor` 从「可能自报」变成「多数经认证、少数显式标注自报」。收口审计可据此新增一条门禁：关键动作的 audit 事件里未标注自报的 actor 占比。
- **密码与令牌策略只做到演示口径**：BCrypt cost、锁定策略、密钥轮换都不做量产级处理。这一点必须写进交付材料而不是省略（0056 已要求）。
