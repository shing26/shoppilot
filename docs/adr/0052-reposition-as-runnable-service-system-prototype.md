# 定位改写：从面试作品到可运行的客服系统雏形

Context: ADR 0024 把本仓口径钉死为「面试作品，不宣称任何形态的上线」，理由是真实投产需要某家商家的订单库、平台方的身份签发、以及能出真钱的退款链路——这三样个人开发者拿不到。**这个事实判断至今仍然成立**，本 ADR 不推翻它。变化的是所有者的目标：2026-10-01 的七问 grilling 裁定，本仓要成为一个**可运行的**多租户客服系统（用户端、渠道调度、知识库、工具模块、安全合规、自动分流工单、咨询与售后闭环），而不是只在纸面上证明自己。

Decision: 定位改为「可运行的客服系统雏形」，自用/演示口径。三条红线随定位一起继承，不因"要做系统"而松动：

1. **不宣称上线**：无生产 SLA、无真实商家数据、无真钱退款链路。README 里"远未到可上线"这句继续成立。
2. **工程纪律不变**：0 token 可对账、判据/阈值/gold/分母不动、收口审计照跑。变成多服务不降低可复核性。
3. **外部资源依赖仍不做**：真 IdP、真支付、真第三方渠道凭据、公网部署——触发条件另立。

ADR 0024 原文不改写，改为在其顶部加换代指针；它的「真实投产是外部资源问题」这层判断继续有效。

Considered Options:

- 维持面试作品定位不变：否决。目标已变，继续按旧口径裁剪新需求会逼着每条新工作先论证"它算不算面试证据"，那是错的问题。
- 模块化单体（不拆服务）：否决。工单与坐席的负载形态（人工异步、长时）与实时对话不同，塞在同一进程里会让 SLA 计时和 pull 领取无处安放。见 0053。
- 只写系统设计文档不动代码：否决。系统设计的价值在于跑起来；纸面版本既验证不了并发与事件语义，也拿不到"它真的分流过一次"的证据。
- 真上线接真实用户：否决。0024 的判断未被推翻，外部资源仍然拿不到。

Consequences:

- 变更门禁从「v1.0 冻结 + ADR 0030 五条触发」转为「program 路线」：新工作要声明它服务 program 主线的哪一段，并挂 ADR 编号。
- 路线与决策见 `.scratch/shoppilot-mvp/system-program-customer-service.md`；紧随本 ADR 的 0053-0057 是它的逐项落法。
- 交付层（README / DELIVERY / RELEASE / PROJECT_PLAN）的定位表述要按本 ADR 更新，**但性能与判据数字不得因定位变化而重算**。
