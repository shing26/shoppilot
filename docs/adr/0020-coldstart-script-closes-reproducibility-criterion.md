Context: PLAN 第 165 行给 ticket 19 的判据是"让未参与的人照 README 跑一遍 → 十分钟内起栈并完成三条演示"。
截至 2026-09-10，机器侧只有一半：`scripts/clean_clone_check.ps1` 能把 HEAD 克隆出来、在空数据卷上照 README 起栈、
跑完三条演示，但它**没有 10 分钟这道预算**，也**不逐条验三条演示各自的输出**——每步只要求命中任意一个标记。
README 当时诚实地写着"换人换机仍然没证"，于是这条承诺项实际悬在"等一个没参与的人来跑"上，而交付窗口（9/13，无余量）
内不会出现这样的人。用户决定：不引入外部人肉测，用无环境状态的冷启动脚本自闭环收口，判据按"10 分钟内端到端冷启动
+ 输出 3 个预期状态码/文本"执行。

决定：
1. 判据拆成两条机器可判的：(a) 端到端墙钟 **≤ 600 s**，覆盖前置检查 → clone → 起栈 → 三条演示（构建与入库都在
   `up.ps1` 里，全算进去才是新用户体验到的时长）；(b) 三条演示各自的预期输出**逐条命中**，缺一条即 FAIL。
2. 预期输出选"能证伪"的那几个字段，不选"跑完了"：① 缓存拦截 = 第一次真的打了模型 + 第二次 `cache=L1/L2` +
   模型调用增量 0 次；② 串号防线 = A/B 店答案不同 + 伪造 token 返回 401；③ 降级转人工 = SSE 降级帧里的工单号
   在运维队列中查得到，且带 `reason=` 与 `status=`。
3. `Run-Step` 的标记匹配从"命中任意一条"改成逐条断言，并打出 `[x]/[ ]` 清单：红了必须说得出是三条里的哪一条，
   不能只报"输出里没找到标记"。
4. 收口时写清"机器证明到哪一级"：这条判据覆盖**提交物自足性**（HEAD 克隆、空数据卷、仓库外无 `.env`）、
   **冷启动是否在预算内**、**三条防线各自是否可观测**；它不覆盖"另一个人"，也不覆盖"另一台物理机"。
   这个替换记在 ADR 里，README 与 ticket 19 的措辞同步跟上，不留"原判据已完成"的误读。

Considered Options（已否决）：
- 等一个没参与的人来跑（判据字面）。交付窗口内没有这样的人，这条承诺会永远停在"没证"；而它真正要防的风险
  ——构建产物齐不齐、容器名撞不撞、数据卷要不要预置、入库依赖、`.env` 在不在仓库外——恰好全部是机器可判的。
- 照原始请求补一个 `scripts/demo.sh`。本仓库 25 个 `.ps1`、0 个 `.sh`，Windows 上没有可用的 bash 运行时；
  为一条判据再造一套平行入口，会把"哪一套是真的"变成新问题。等价映射是现成的：
  `docker compose up -d` + `mvn package` + `demo.sh` 三步 = `up.ps1` + `demo.ps1`。
- 把 10 分钟预算写进 `run-acceptance.ps1`。那是同一个工作目录里的暖跑（有 `target/`、有数据卷、有 `.env`），
  量的不是冷启动，也不会有人"照 README"跑它。
- 只看退出码。这台机器多次在构建中途把 `mvnw.cmd` 的 JVM 带走而它返回 0，README"假红"一节记过；
  退出码为 0 的步也打过成功的字，所以判据必须落在输出文本上。

Consequences:
- 判据实测一次通过（2026-09-10 17:54，`logs/clean-clone-check-20260910-175431.log`）：前置检查 4 s + clone 18 s
  + 起栈 113 s（冷构建、seed 5 万单、90 块全量入库）+ 三条演示 106 s = **241 s**，预算 600 s，两步都在第 1 次尝试即过。
  三条演示的实际输出：`第二次 24ms intent=POLICY_SHIPPING triage=T0 cache=L1`、`第一次打模型 1 次；模型调用增量 0 次`、
  `两次答案是否不同：True`、`伪造 token 直接 401`、`工单 T1789034312444-0 reason=TOOL_UNAVAILABLE status=OPEN`。
- 一个假绿被顺带堵掉：`Get-Metric` 取不到 actuator 计数器时返回 `-1`，两次 `-1` 相减也是 0，
  "第二次没打模型"这条断言本会白送。加上"第一次打模型 `[1-9]` 次"之后，计数器不可用会当场红。
- 前提比上一轮更挤而不是更松：本次前置检查打到空闲物理内存 **1 GB**（上一轮通过时 1.5 GB），判据没有为此放宽；
  `up` 仍允许重试一次，日志里两次尝试都在——重试是把"最挤的那一分钟"绕开，不是把红洗成绿。
- 剩下的缺口写在明处：同一台物理机、同一位作者、同一份 `up.ps1`。"换机"需要第二台机器才能证，本冲刺不做；
  被追问时的答案是这三条缺口连同这张落点日志一起给，而不是把 241 s 说成"任何人都能在十分钟内跑起来"。
