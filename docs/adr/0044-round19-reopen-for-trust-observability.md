# round19 重开：补齐可信性观测（embedding 计时器 / Plan 记录 / 上下文组成 / 输出上限），其余八项挂触发条件

Context: 2026-09-24 做过一次围绕六个维度的对仓复核（①真实业务需求与架构设计是否匹配 ②任务规划核心能力 ③上下文工程 ④可观测性与评估体系 ⑤人机协同 ⑥业务闭环完整性），触发物是 `D:\WorkBuddyData\` 下的两份外部清单（`RAG与Agent管线_指标闭环可补齐项清单_2026-09-24.html`、`七项目定位档案_2026-09-24.html`），但复核结论逐条对仓重核过，不引用清单里与仓内实测不符的数字（清单的 30 ADR / 170 `@Test` / 「Qdrant 距离度量未声明」/「416 条场景分片」四处已核实为错，见 round19 spec 的基线复核节）。

复核结论：这个项目在**评估体系**（判据唯一、量具自证 40/40、CI 五步 0 token 门禁）与**护栏**（动作层幻觉治理三件套、三道隔离防线、七道写回资格）上是强项；缺口集中在两处——**闭环的最后一公里**（工单状态不回流、退款停在受理态、知识不反向沉淀、无敏感动作审批）与**上下文/可观测的最后一格**（embedding 段无服务端计时器、无单请求 token 预算、无显式输出上限、`done` 帧不带 Plan 与上下文组成）。

这两堆缺口**既不是事实性错误、不是崩溃或回归**（`REFUNDED` 无运行时流转、工单不回流、无审批闸门、无 task 级判据都是范围边界的自然后果，不是实现与承诺不符——`README.md:22` 与 `CONTEXT.md:130` 早已明写「跨重启与 RESOLVED 回流不承诺」），**也没命中 ADR 0030 五条触发线**（第 2 条要 biz-mock 被真工单系统替换、第 4 条要先做裁决、第 5 条要出现可机器寻址的 Prometheus 形态）。因此 ADR 0031 的「面试同一缺口被问两次」触发条件未命中，`PROJECT_PLAN.md:19` 的 v1.0.0 冻结线也放不过。本轮重开不是该条件的触发，而是项目所有者在知情该政策的前提下做出的显式覆盖决策：**只补齐不触碰保护对象的旁挂观测项**。**重开必须诚实记录为政策覆盖，而不是伪装成面试反馈触发**——与 ADR 0033、ADR 0041 同形。

Decision: round19 范围锁定 **5 项旁挂执行 + 1 项前置授权**；八项登记不执行、各挂触发条件。

具体口径：

- **「旁挂」是硬定义，不是修辞**：只允许「新增可观测字段 / 新增指标 / 新增配置项 / 纯文档」四种改动。**不改判据、阈值、gold、`judge()`、rescore 差异集合、状态机 10 状态枚举、2 轮上限，以及 ADR 0008/0030/0036/0038/0039 的任何结论。** 这条尺子来自 ADR 0033 的 Considered Options 原文（「本轮范围经可行性评估确认全部为旁挂式、不触碰冻结线的保护对象」）。
- **embedding 计时器必须带 `result` 标签**：`EmbeddingClient.embed()` 同时承载「命中进程内缓存」与「真打远程」两条路径（既有 `shoppilot_embedding_calls_total{result=remote|in-process-cache|singleflight-merge}` 就是这个分法）。不带标签的 Timer 会把 0.9 s 的远程调用与近零的缓存命中混成一个数，比现在的「外部探针估算」更糊。
- **票 47 会改变一个已公开的归因读数**（`README.md:211` 的 `725 = 300 + 311 + 4.8 + 5.8 + 104`，其中 311 是 `ttft_attribution.py:137-143` 自己探针量一次放进去的）。这是**测量保真度提升，不是摘红**：旧值按原样并列保留 + 加换代指针，不换口径、不删历史读数。凡「换测量方法导致数字变化」的场合都按这条处理。
- **票 48 不动 ADR 0036 的执行语义**：仍是「有序步骤 ≤ 2、前步失败即中止、串行不并行」。本票只把已存在于 `AgentStateMachine` 局部变量里的执行事实（`stepResults`）提升为可输出的记录，不改任何判定分支。
- **票 48/49 只往既有 `done` 帧加字段，不新增 SSE 事件类型**：`verify-console.mjs` 只断言帧序列含 `meta`/`done` 与引用数，`SseEventSinkTest` 只断言特定字段存在，两者都不逐字段钉死——加字段向后兼容，与 `promptVersion` 当初加进 `meta` 同形态（`SseEventSink.java:79` 的注释就是这个先例）。
- **票 50 的默认值给足余量**：`PromptCatalog` 的规则 11 写「不超过 200 字」，但输出里还要含工具调用 JSON，所以上限不是「按 200 字设小」而是「设成足够大的稳定性护栏」。目的不是省 token（那是 `TokenBudget` 的日预算熔断，ADR 0012），是**防输出失控**。
- **覆盖率是硬约束**：gateway LINE 门槛 `54.0`，round18 实测 `55.37%`，余量只有 1.37pp。**本票新增的 gateway 代码一律配 JUnit 用例**，否则 `scripts/check_coverage.py` 直接红——这是本轮最容易踩的坑，写在 spec 的验收判据里。

非目标（本轮不执行，全部进 round19 spec 的登记节，各挂触发条件）：退款终态推进、工单 RESOLVED 回流消费点、敏感动作审批闸门、task-level 判据、CI 覆盖活体数字、拦截率 74% vs 80% 裁决、上下文输入侧裁剪、知识反向沉淀自动咬合。

Considered Options:

- **只做 ADR 0031:10 豁免的修复（事实错误/回归/崩溃/门禁要求），其余登记**：否决。逐条核过之后，这个口径下能站住的只有「风格档位档位计算时 intent 传 null」一条，而它**根本不是缺陷**——`Rule.matches(channel, emotion, intent)` 里 intent 是活的匹配维度、`StyleServiceTest` 有 7 处调用传真 Intent 作断言、`profiles.yml` 只是没写 intent 规则，调用方在 INTAKE 阶段（意图未定）传 null 是诚实的。按这个口径本轮等于无事可做。
- **全部只登记不执行**：否决。等于不迭代，而「embedding 段无计时器」「无显式输出上限」是两条**当下就成立的可观测/稳定性缺口**，登记它们不会让它们消失。
- **把闭环三项（工单回流 / 退款终态 / 敏感动作审批）与 task-level 判据一并做**：否决。前三项分别触碰 ADR 0030 第 2 条的未承诺边界、biz-mock 的业务终态语义、以及 ADR 0008 的 2 轮时延预算论证；task-level 判据触碰判据面（`verify_eval_judge.py:218/221` 精确断言「10 意图各 18 条、总 180、对抗 72/180=40.0%」）。四条都要先改已锁定结论，治理资本花得不成比例，也与本轮「旁挂」定义直接冲突。
- **先修本机 Ollama 环境（`OLLAMA_MAX_LOADED_MODELS≥2`）再跑全量 22 步矩阵**：否决。本轮改动是观测面，不依赖未命中路径；且那是机器级设置（User 与 Machine 两处被显式写下），票 46 已把它登记为独立放开条件，不夹带在本轮里顺手改。
- **本轮收口拦截率 74% vs 80% 那条挂起裁决**：否决。ADR 0030 第 3 条明写「纯观点之争不开这条」，而 ADR 0030 第 4 条给这条裁决留的两个出口里，「改口径」会踩 AGENTS.md「不改指标分母来让结果变绿」的铁律、「改架构（缓存前置）」会推翻 ADR 0003 并重新引入跨意图串号（本仓最不可协商的一条是串号 0 次）。三个选项已列进登记节，维持挂起。
- **把 `done` 帧的扩展改成新增 SSE 事件类型**：否决。新增事件类型要同步调试台的事件分发与 `verify-console.mjs` 的 35 项断言，而 `done` 帧本来就是「这次回答的元信息」出口（`citations` 与 `usage` 都在它里面），语义最贴、代价最低。

Consequences:

- 冻结线对 round19 之后的轮次继续有效；本轮结束后回到 ADR 0031 机制，**不自动续期**。每张票独立可交付，中途冻结任意时刻项目仍自洽。
- **票 47 改变一个已公开的 TTFT 归因读数**：`README.md:211` 与 `docs/loadtest-report.md` 的相关行需加换代指针，`docs/EVIDENCE.md` 的「TTFT 725 ms 归因」行需登记新的测量方法与新读数。旧值并列保留，不摘红。
- **票 48/49 动 `AgentResult` 这个 14 分量 record**：所有构造点（`AgentStateMachine`、测试夹具）需一次性同步，改动面比「加两个字段」看起来大。构造点在编译期暴露，不会静默漏改。
- **票 50 改 LLM 请求体**：理论上可能影响 dev 口径的 180 条 gold 读数（输出被截断会改答案）。默认值给足余量以规避，收口时须确认读数未漂移；若漂移，按「保留红值 + 归因」处理，不改判据。
- **`CONTEXT.md` 新增 5 个 canonical term**（槽位 / 降级 / 缓存写回资格 / 复核队列 / 计划）：它们都是代码与 README 里反复出现却从未进术语表的概念，补的是「引用时无权威定义」这个缺口，不引入新能力。
- **本轮不碰本机 Ollama 环境**：票 46 登记的 `verify-hit-zero-llm.ps1` 未达成项保持原样，放开条件不变（该值 ≥2 并重启 Ollama）。round19 的活体证据只到 `verify-console.mjs` 一条针对性步，**不跑全量 22 步矩阵**——理由是本机环境红会与真实信号混在一起，降低判据的可读性。
- 外部两份清单的定位结论（「RAG / Agent 管线的三个真实切面」、ShopPilot 承载「动作正确性」切面）与本仓自述一致，本轮不因此改动任何对外表述；清单里与仓内实测不符的四处数字已在 round19 spec 的基线复核节登记，供后续引用时避坑。
