# round17 重开：对齐完整落地级电商客服链路，范围 M1-M5

Context: ADR 0031 规定冻结期新功能必须由"面试同一缺口被问两次"触发。本轮重开不是该条件的触发，而是项目所有者在知情该政策的前提下做出的显式覆盖决策：以《电商智能客服Agent--已落地》架构图为对标，把 ShopPilot 的链路从"缓存+编排特长生"补齐到"完整电商客服 Agent"的叙事规模。重开必须诚实记录为政策覆盖，而不是伪装成面试反馈触发。

Decision: round17 范围锁定为五个模块，全部走"旁挂插入"，主链路 10 状态机不扩枚举：

| 票 | 模块 | ADR | 估时 |
|---|---|---|---|
| T-1 | 情感门 SentimentGate（前置过滤 + EMOTION_ESCALATION） | 0034 | 1-1.5 天 |
| T-2 | 多渠道接入 ChannelAdapter（契约级） | 0035 | 1.5-2 天 |
| T-3 | Plan 升级为有序步骤（仍在 2 轮界内） | 0036 | 2 天 |
| T-0 | Prompt 版本化（T-4 前置） | 0037 | 0.5 天 |
| T-4 | 风格引擎 StyleService | 0038 | 0.5-1 天 |
| T-5 | 满意度反馈闭环（显式 + 隐式 + 人工复核回流） | 0039 | 1-1.5 天 |

非目标（0040 成文化）：十万级并发会话（Redis Streams）、多工具并行/DAG、真实渠道集成、自动回流再训练。

准入筛子沿用 ADR 0024：每个模块必须给出 0 模型额度、可机器复跑的验证判据（词典层用例、MockLLM 用例、验收脚本断言）。活体 LLM 路径只在 dev 口径下另测，不作为唯一证据。

前置硬闸门（T-3 开工条件）：评测子集接 CI（357 条用例的 selfcheck + 离线 rescore 先进 CI），T-3 改造后全量评测不得低于基线。

Considered Options:

- 按 ADR 0031 继续冻结，等面试反馈：否决。所有者已明确选择主动扩展，且本轮范围经可行性评估确认全部为旁挂式、不触碰冻结线的保护对象（判据、阈值、gold、已锁定 ADR 结论）。
- 把五个模块一次全做进主链路（重写状态机为通用编排框架）：否决。这会把"手写编排"（ADR 0032）变成框架迁移，回归风险与叙事稀释都不可接受。
- 只做 M1+M5：登记为降级方案。若 T-3 评测回归超阈值且一周内无法收敛，round17 收缩为 M1/M2/M4/M5，T-3 按本 ADR 挂账。

Consequences:

- 冻结线对 round17 之后的轮次继续有效；本轮结束后回到 ADR 0031 机制，不自动续期。
- 每张票独立可交付，中途冻结任意时刻项目仍处于自洽状态。
- 新增用例进评测集后，judge() 需扩两处 schema（escalate、plan），扩 judge 必须同步补 selfcheck 夹具（ADR 0021 纪律）。
