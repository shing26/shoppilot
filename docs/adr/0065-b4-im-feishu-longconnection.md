# B4 开线：飞书长连接真连，暴露面判定为零暴露

Date: 2026-10-07　Status: Accepted　Owner ruling: 2026-10-07「开，第一平台选飞书」
Tickets: 票 98（考察）→ 票 99（本裁定）→ round31

Context: 票 98 的考察（ADR 0064）判 B 段可行且免公网长连接四选一。**所有者裁定**（2026-10-07）：
**B4 开线，第一平台选飞书**——裁定理由里有所有者自己的操作经验：「飞书经常配置，比较熟悉」，
且**其他候选平台（企微/钉钉/Slack）暂无接触经验**；平台配置摩擦是真实成本，这一条与其他
技术依据（见下）并列记录。

**选飞书的技术依据**（ADR 0064 问 2 节）：
- 长连接由官方 SDK 内置（Java oapi-sdk 2.4.0+），**无需公网 IP/域名/内网穿透、无需验签加密
  配置**——连接生命周期（心跳/重连）由 SDK 承担，自实现易错的那一整块不用自己写。
- 仅支持**自建应用**：企业内创建即用，免上架审核、免备案。
- 凭据只有一对（APP_ID + APP_SECRET），持面最小。
- 硬限制已知且可接受（单实例网关现状下）：每应用最多 50 连接；**多 client 是集群语义
  （同一消息随机只有一个 client 收到，不是广播）**——本仓网关单实例部署，语义无碍；
  若未来多实例，部署形态要重看（登记，不阻塞）。事件须 3 秒内处理完——本仓链路是
  收事件 → 入队/转发，不做长处理，满足。

Decision:

1. **B4 开线，第一平台 = 飞书（长连接形态）**。执行轮次为 round31，票见
   [`round31-spec-b4-feishu-live.md`](../../.scratch/shoppilot-mvp/round31-spec-b4-feishu-live.md)。
2. **暴露面判定：零暴露，且这是红线不是侥幸**。飞书长连接是网关进程内的**出站** WSS，
   不开新端口、无入站 HTTP 回调、无隧道、无公网地址。**B4 执行期间不得以任何理由
   （含调试便利）把网关端口暴露到公网**；若未来切回调形态，必须先过 ADR 0064 问 3
   列的四条残余风险评审（验签重放窗口 / 回调 DoS 面 / 反代后回环判定失真 / 静态入口
   误暴露），那是另一次决策，不是配置改动。
3. **执行顺序：A 段两格先行**（票 96 的 `conversationId` 派生 + `clientToken` 派生）。
   真连没有这两格就是「每条消息全新会话、追问必断」（ADR 0060 Context 第 2 条）——
   适配器契约的地基不因「急着真连」跳过。票 97 的录放门录制对象随裁定改为**飞书事件
   JSON**。
4. **SDK 引入决策：B 段引入飞书官方 SDK**（票 97 口径预留过这一格：「引 SDK 会在 B 段
   真正调 API 时才有用，而那时才需要它的凭据与网络」）。A 段录放门仍只吃事件 JSON，
   不吃 SDK——门禁保持 0 token、免凭据、干净 runner 可复现。
5. **凭据家法照搬**：`.env` 不入库；`APP_ID`/`APP_SECRET` 走环境变量；非回环绑定时空凭据
   **拒启**（PostureGuard 同一家法，B2 原语现成）；CI 不进（录放门免凭据）。
   真凭据的申请是所有者的运营动作（飞书开放平台注册企业自建应用），票 115 的活体验证
   以凭据到位为外部前置。

Considered Options:

- **选企微（智能机器人长连接）**：否决于本轮。单连接主备模型对单实例网关可行，但凭据
  两件套（BotID+Secret）与媒体解密（AES-256-CBC 逐链接 aeskey）都更重；所有者熟悉度
  也低于飞书。不构成否决结论——它是平台二的候选。
- **选钉钉（Stream 模式）**：否决于本轮。endpoint 动态分配（POST 换 endpoint+ticket）
  的注册协议比飞书「SDK 直连」多一层要自己管的状态。
- **选 Slack（Socket Mode）**：否决于本轮。连通性已验（ADR 0064），但所有者的部署
  环境与目标用户在国内，飞书的配置熟悉度直接压过它。Slack 保留为国际平台的候选。
- **跳过票 96/97 直接真连**：否决。「先跑通再说」会在真连链路上埋一个每消息新会话的
  断追问缺陷，而它的修复（两格派生）本来就是平台无关、可在 CI 验证的。
- **回调形态 + 隧道**：否决。长连接形态已验可行，把零暴露换成四条残余风险没有任何
  收益。

Consequences:

- **round31 的活体验证依赖真凭据**（票 115）：所有者在飞书开放平台创建应用并提供
  `APP_ID`/`APP_SECRET`（.env 持有）之前，wss 应用层握手这一格**保持未验照登**——
  票 98 边界的关闭以实测为准，不许提前写「已验证」。
- **CI 九步不变**：A 段录放门作为 0 token 步骤并入，不增加需要外部服务的步骤（round15
  纪律）；B 段的活体证据在门禁之外，照登。
- **对外表述纪律沿用 ADR 0060/0064**：wss 应用层握手实测通过之前，只能说「适配器契约
  可复现」；通过之后说「飞书真连已验证」并附读数，不说「已接入飞书」这种产品化措辞
  （ADR 0024/0052 的「不宣称上线」红线）。
- ADR 0064 的结论第 3 条（「裁定归票 99 与所有者」）至此执行完毕：本 ADR 就是裁定记录。
