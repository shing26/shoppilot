# round39 开轮依据：买家端产品化布局（对话主区 + 服务侧栏）

Date: 2026-10-25　Status: **Accepted**（2026-10-25 所有者指令「前端没怎么打磨，展示面太拉」）
Owner basis: 所有者确认先做坐席控制台后，指出买家端才是真正的用户入口，仍像 demo；
要求继续把产品面做出来，而不是继续打磨后端。
Tickets: 实现票 [158](../../.scratch/shoppilot-mvp/issues/158-buyer-surface-product-layout.md)（票面即本轮 spec）。

## Context

ADR 0070 B 段已把买家端从「单轮表单」做成对话流，并完成店铺入口、加载态与窄屏门禁。
ADR 0073 完成坐席控制台后，买家端成为唯一还停留在「功能齐全但展示面单薄」的产品入口：

1. 登录后首屏只有标题与三个文字按钮，桌面宽度下大量留白；
2. 工单进度被放在对话流下方，需要滚动才能看到，售后进度不成立；
3. 服务能力、店铺保障、快捷问题没有形成清晰的信息层次，观感接近验收夹具。

## Decision

1. 买家端升级为**对话主区 + 服务侧栏**的双栏产品布局：
   - 主区：欢迎态、对话流、输入区；
   - 侧栏：本次服务工单进度、服务范围、店铺保障。
2. 登录前保留既有 gate、一键体验与账号登录路径；不新增登录形态。
3. 所有既有行为、失败口径、选择器与文本契约保持不变：
   `.store-card`、`.gate`、`.welcome`、`.thread`、`.tickets`、`.composer` 继续存在；
   空态文案、工单抽屉、SSE 流式、重试与游客限制不改变。
4. 视觉只使用 `frontend-shared` 令牌，不引组件库、不加运行时依赖。
5. 前端源码与入库产物同次提交，CI 逐字节校验继续生效。

## Non-goals

- 不改买家后端契约、不改意图 / 工具 / gold 判据。
- 不做会话持久化、多店铺切换、图片或富文本。
- 不做订单 / 商品浏览页（仓里没有买家读端点，属于新功能）。
- 不改坐席控制台。

## Consequences

- `frontend-buyer/src/App.vue` 模板重排，样式扩展；`static/buyer/` 产物重建入库。
- 既有 `verify-buyer.mjs` 的选择器与文本断言应继续成立；若发现选择器失效，按票面登记并修正，
  不降低所量语义。
- 活体浏览器验收需要覆盖：店铺身份、对话主区、快捷问题、侧栏工单、窄屏无横向溢出。
