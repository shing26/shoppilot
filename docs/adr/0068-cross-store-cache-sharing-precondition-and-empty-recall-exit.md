# 平台桶的共享安全性：有店铺级条款的意图不跨店共享；空召回走确定性转人工

Date: 2026-10-17　Status: Accepted　Owner ruling: 2026-10-17 所有者报障「同一个问题在不同店铺回答一模一样，
即使问题与店铺无关也会根据问题回答」并指令「帮我找出缺陷并优化」。
Tickets: 票 129-131（见 [`round34-spec-cross-store-leak-and-empty-recall.md`](../../.scratch/shoppilot-mvp/round34-spec-cross-store-leak-and-empty-recall.md)）。

Context:

round33（ADR 0067）把「跨行业」补成了运行时的 `Domain` 维度，但**同行业内部**的跨店串答案没有修。
2026-10-17 在活体栈（profile=local，kbEpoch=6）上按所有者报障复现出两条缺陷、一条契约错位：

- **平台桶跨店共享不安全**。写回资格只看「本次引用是否全为平台条款」，可写方在租户隔离下
  **看不见别家的店铺级条款**。实测：T001（无死蟹门店细则）问「死蟹怎么赔付」→ 只引平台条款
  `fresh-06/fresh-02` → 写进 `PLATFORM:ECOMMERCE`；T002（有 `fresh-08-shop-t002-dead-crab`
  六小时窗口细则）与 T003 再问同句 → `cacheLayer=L1` 直接命中 T001 的答案，**逐字节 120 字相同**，
  T002 自己的门店细则永远不生效；把问法换成「死蟹赔付标准是什么」（避开 L1）T002 立刻检索到自己的细则
  ——证明检索与行业隔离本身是对的，缺陷只在共享判定。顺序效应同样成立：T003 先把
  「无理由退货窗口是几天」的平台口径（7 天）写进平台桶，T001 再问同句会命中它，而 T001 的本店规则
  是 `return-07-shop-t001-window`（15 天）。
- **空召回把编造当答案**。检索可见范围内 0 条时，系统把模型自由发挥的正文直接返回：T004（酒店）
  问「死蟹怎么赔付」得到「我们提供全额退款服务」、问「无理由退货窗口是几天」得到「15 天」
  ——零引用、无降级、不落工单；同一句第二次问才因负缓存转人工。T0 里那句「电商租户问酒店问题
  ……最终落到转人工」的注释在活体上不成立。这与 ADR 0009（办不成给一句实话并落可查工单）、
  ADR 0067 第 4 条（宁可转人工，不拿另一个行业的条款回答）与提示词第 1 条（条款未覆盖时说明并转人工、
  不要编造）三处承诺同时冲突。
- **命中路径引用详情缺出处**。round33 落了 `sourceHeadings` 却没落 `sourceDocs`，于是缓存命中时
  `citationDetails.doc` 恒为空串——买家端引用两列中的一列在命中路径失效（票 129 同批修掉）。

Decision:

1. **平台桶共享加前置条件**：一个答案进 `PLATFORM:<DOMAIN>` 桶（以及读它）的前提从「引用全为平台条款」
   收紧为「引用全为平台条款 **且** 本行业该意图不存在任何店铺级条款」。后者由新组件
   `knowledge/ShopRuleIndex` 实测（按 `scope=SHOP + domain + intent + 当前纪元` 查词法索引，
   size=1），结果按 (纪元, 行业, 意图) 记忆、语料换代即作废。读侧同样跳过平台桶：修复前写下的
   跨店答案因此自愈；对存在店铺级条款的意图，平台桶本来也再也写不进，读它只是白跑 Redis。
   **探针失败 fail-closed**（当存在店铺级条款处理）：ES 抖动时牺牲跨店命中率，不牺牲隔离。
2. **空召回走确定性出口**：政策意图在可见范围内检索到 0 条且未降级时，不调模型，
   直接以 `INTENT_UNRESOLVED` 转人工（落可查工单）并写负标记——与既有的 negative-marker 出口同源，
   首问与复问口径一致。检查放在检索之后、组装 Prompt 之前：既省一次模型调用，也让模型没有发挥机会。
   **检索降级（degraded）不落此出口**：把一次中间件抖动固化成批量转人工是 2026-09-08 压测踩过的坑。
3. **缓存条目补 `sourceDocs`**：与 `sourceRuleIds`/`sourceHeadings` 同源同序，引用详情在命中路径
   恢复出处两列。`@JsonIgnoreProperties(ignoreUnknown = true)` + 缺失字段按空处理，旧条目自然降级。
4. **判据红线不动**：不改 180 条 gold、阈值、指标分母与任何既有验收判据。新增的
   `scripts/verify-store-isolation.py` 是 **add-only** 的第 29 步（full 档：门店细则必须在场、
   顺序效应不串答案、空召回确定性转人工、无门店细则的意图仍跨店共享），断言只看确定性字段
   （引用出处 / 缓存层 / 降级出口），不看模型文风，perf 与 local 档同判。

Considered Options:

- **拆掉平台桶、缓存一律按租户分区**：否决。ADR 0004 的「平台级政策全租户共享同一份」是锁定决策，
  对没有店铺级条款的意图（如 POLICY_SHIPPING）共享是正确且省钱的；为了三个意图整体弃用共享
  是用命中率买隔离，而隔离本来可以精确买。
- **按查询逐次探测（"有没有任何租户会在这一问上引到店铺条款"）**：否决。要么多一次模糊判定
  （阈值判断本身成为新的判据面），要么把探测做成第二份检索实现；按意图的粗粒度会多挡一点，
  但挡错的方向是"多存几份本店答案"，而漏挡的方向是串店答案——粗粒度在这里是正确的一边。
- **保留空召回自由发挥，只靠提示词约束模型**：否决。活体实测 3B 模型不听：提示词第 1 条明写
  「不要编造」，「死蟹全额退款」照编。试点词是唯一挡不住的那类（酒店对死蟹做全额退款承诺，
  买家可以拿着这句话来要钱）。
- **空召回首问也只给"无依据话术"、不带工单**：否决。ADR 0009 已经裁定降级要落可查工单；
  话术与工单是同一条承诺的两半，只给一半等于回到 2026-09-28 空答案缺陷的老路。

Consequences:

- **命中率**：`POLICY_RETURN` / `POLICY_PROMO` / `POLICY_FRESH` 三个意图（都有店铺级条款）在同行业
  多店流量下不再跨店共享。**单租户压测读数不受影响**（载荷来自单店流量），**多店混合流量下的
  命中率影响未测量**——照登，不声称。
- **空召回出口换代**：首问从「模型自由发挥」变成「转人工 + 工单」。语义上更严（fail-closed），
  代价是"确实没有这条政策"的问句会立即落单；180 条 gold 的活体重跑未做（需 dev 额度），
  其对答案类读数的影响**未验证**——照登。
- **探针失败 fail-closed**：ES 不可用时平台桶整体停用（L1 跨店命中降级为本店命中），
  隔离不受影响；这是有意的取舍方向。
- **收口审计读数不动**：`票据 + 登记` 的既有判据一条未改；新增门禁为 add-only 步。
