# 5.5 天预算下的范围裁剪

Status: superseded by ADR 0015 —— 本清单中因打字耗时砍掉的项已全部恢复，仅"无价值"类削减保留。


Context: 竖切计划原估 9 个全职工作日，交付窗口为 2026-09-08 至 2026-09-13（5.5 天），且需预留 1 天用于 README、演示脚本与 STAR 话术——面试尚未确定但随时可能约。决定按以下清单裁剪：跨实例 singleflight 只保留进程内层；不引入 Prometheus/Grafana，改用 Micrometer + `/actuator/metrics` + 压测结果 CSV 汇总；`local`（Ollama）模式保留 profile 但不做专项验证，降级故事改由 LLM 超时与 biz-mock 故障注入承担；工单抽屉为只读，不做接管与状态流转交互；测试收缩为跨租户越权、幂等重复提交、缓存写回资格三条必测；数据规模定为 3 租户 / 200 买家 / 5000 订单；明确不做 rerank 精排。

Consequences:
- Elasticsearch 保留但降到"够用级"：BM25 一路召回 + RRF 融合，不做自定义分词器调优、不做同义词词典、不做检索质量对比实验；30 篇政策语料量喂不出调优价值。
- 砍掉 L2 语义缓存的**阈值标定实验**（反义/近义对抗对与阈值曲线），保留 L2 功能本身。因此简历与文档不得写"阈值经评测集标定"，正确表述是：阈值取保守值 0.95，串号防线由缓存准入与意图分区承担，不依赖阈值。
- Tool Calling 的**标注评测集不可砍**——它是 ADR 0001 中"准确率 >= 95%"的唯一数据来源，与上述被砍的阈值标定集是两个不同资产。
- 无余量。已知三处高概率卡壳点：HikariCP 默认 10 连接在虚拟线程高并发下会先于 CPU 饱和；Qdrant 与 ES 的 Docker 内存配额；DashScope tool calling 返回格式细节。任一处卡半天即继续向下砍。
