# round48 开轮依据：质量收口，不开新功能

Date: 2026-11-04　Status: **Accepted**（2026-11-04 所有者指令「按 round48 方案开始：先做票 200 文档真值同步，再做票 201 LLM 录放门」）

结构性债务拆开。冻结线（ADR 0030 / ADR 0031 / ADR 0052）继续有效；本轮由所有者显式政策覆盖开轮，
**不自动续期**。

## Context

2026-11-04 的六维复核（产品定义 / 架构 / 编排 / 检索 / 评测 / 可维护性）给出一个明确判断：
**工程的防御性已经很强，但「AI 质量」还没有被工程化地守住。** 三条证据：

1. **AI 行为不在 CI 里**。CI 只有 JVM mock 测试与静态门禁；180 条 gold 依赖云端额度与手工起栈，
   活体矩阵依赖本机 Ollama / 容器 / 显存。改 prompt、改检索、改工具策略，CI 可能全绿而真实行为已退化。
2. **同一件事有三个数字**。README badge 写 738 条测试、`STATUS.md` 写 773、`TUNING_PLAN.md` 写 701；
   README 写 76 篇 ADR，目录里实有 81 篇；工具准确率 `STATUS` 写 93.3%、`TUNING_PLAN` 写「全分区 100%」，
   而最新全量 dev 读数是 179/180（99.4%，`ACTION_REFUND` 94.4%），「100%」用的是退款定向重跑 18/18。
   这不是小数漂移，是把定向重跑并进了全量口径——本仓最核心的对外承诺是「可验证、不改口径」，
   这一格必须先修。
3. **默认真实模型路径弱于演示路径**。默认 `local`（qwen2.5:3b）的 180 条工具选择约 166/180（92.2%），
   `ACTION_REFUND` 只有 50%；对外演示默认走 `demo`/`perf` 模板档。动作意图恰恰是涉资、最需要质量的一档。
   Stage3 路由表（政策走本地、动作走云端）已经算出来，但仍停在「离线评估完成、未改线上」。

## Decision

1. **round48 的主题是「质量收口」**：先让读数可信（票 200），再让行为可回归（票 201），
   然后补答案级判据（票 202）；结构债（203）、真实依赖（204）、前端测试（205）与检索/路由决策（206）
   排在其后。**票 200、201 先执行，其余票在 201 的门禁成立后再开。**
2. **不新增功能、不新增服务、不新增看板**。本轮最多新增一篇 ADR（本文）；其它决策写进
   tracker 与票面，不为「整齐」补文档。
3. **不改判据面**：gold、阈值、`judge()`、降级枚举 10/降级 9、指标分母全部原样。
   票 200 只改「读数与出处」，不改任何判据；票 201 只加一层回放执行路径，不改生产判定。
4. **回放门只守编排与提示词回归，不冒充模型漂移证据**。录放门能证明「同一份模型输出下，
   系统的判定与答案没有变」；它不能证明模型本身没变。模型能力仍由周期性 dev / local 活体评测负责。
5. **默认档是否展示真实模型，作为票 206 的决策项**，不在本轮偷偷改默认值。

## Consequences

- PR CI 会增加一步 0 token 的回放门；录制物入库，体积与更新流程要写进 README / CODE_MAP。
- 回放 cassette 绑定 `promptVersion + model + messages hash`；prompt 换代需要重录，否则门禁会红——
  这是有意的：它强迫每次 prompt 改动都留下对照。
- 票 200 会调整 README、ARCHITECTURE、TUNING_PLAN 与 `docs/current-metrics.json` 的当前读数；
  历史表格（README 的 09-10 / 09-11 读数、DELIVERY 的更新记录）保持原样，只加指针，不改写历史。
- 本轮的「未达成」仍按实登记：没有录制预算的 180 条 cassette、未跑的 local 活体、未实现的答案级判据，
  都不许用「机制已就绪」替代实测。
