# 本轮口径是面试作品，不宣称任何形态的上线

Context: 生产就绪度评估给出 16 项差距，个人开发者手上只有其中 13 项的解锁条件。真实投产需要某家商家的订单库、平台方的身份签发、以及能出真钱的退款链路，这三样拿不到，评估报告第 13 项自己也写着「换真库/真 IdP 属新项目量级」；外壳投产需要真实部署目标，而公网可达会把「零模型额度」这条铁律变成「有上限」——`mode: local` 的 qwen2.5:3b 在小机型上跑不动（本机一次问答实测首字 11.6 秒），`mode: dev` 直打云端就是花钱。

决定：口径取面试作品，验收判据收紧成一句——一项改造只有能在本仓以 0 token、不依赖一次性活体读数的形式被机器复跑证明，才进本轮范围。这条判据与铁律 3「每句自述必须机器可重跑」同构，它是本轮真正的筛子。

## Considered Options

- 全真投产：否决，缺的不是工时是外部资源。
- 外壳投产（真实部署 + 合成数据 + 真实第三方访问）：否决。它是本轮之外的一步，做它要同时改掉「零额度」与「活体读数不得当证据」两条铁律，一次改两条判据的代价高过它带来的信号。
- 无外部观众的自我完善：否决，没有收敛力，16 项会一直做下去。

## Consequences

- 进本轮：密钥与运维端点 fail-fast、会话键补买家归属、readiness 补向量与检索与知识库、日志配置与 traceId 贯穿、REST 全局异常出口、调试台剩余交互缺陷。
- 不进本轮，明示为非目标：最小告警集（本机无 Prometheus 与 Alertmanager 实例，写了只能证语法、证不了该响时会不会响，正是这条判据要拦的自述）、Dockerfile 与 CI（17 步门禁要 Ollama 加 ES 加 Qdrant，runner 上跑不起来，红的 CI 比没有更糟）、跨实例 singleflight 验证、异机复现、分布式追踪。
- 「上线」在本仓文档里的唯一含义是真实商家数据上的对外服务；本轮全部读数只证明外壳与降级设计，不证明处理真实订单的能力。README 那句「远未到可上线」在本轮结束时仍然成立，不许因为补了几项运维实活就改口。
