# dev 默认值与 mock 身份签发的合法性由绑定地址决定

Context: 生产就绪度评估把「三处密钥带可启动的 dev 默认值」列为高优第一位，常规做法是加一个 prod 档、在里面把默认值删净。本项目不能这么办，两个理由。ADR 0020 的干净克隆判据要求「克隆目录无 `.env` 也能起栈并跑通三条演示」，直接删默认值会打死那条判据，而它第十一轮刚被逐条实跑复现过。本轮口径是面试作品（ADR 0024），不引入 prod 部署档，那「只在 prod 档里收紧」就是一个永远不成立的条件，等于没写。

决定：收紧的触发器取绑定地址。绑回环时，三处 dev 默认值合法、mock 身份签发端点照常注册，但启动打 WARN，并在观测面回一个 `devDefaultsInUse` 字段让人能机器核；`server.address` 一旦不是回环，任一处仍取默认值即启动失败，运维端点须显式关闭或换成非默认凭证，mock 身份签发端点不注册。

## Considered Options

- 加 prod profile 并在其中删净默认值：否决，本轮没有 prod 档，且它与 ADR 0020 那条判据正面冲突。
- 显式风险开关，要自己设 true 才收紧：否决。忘记设等于没有，而它防的恰恰是「没人想过这件事」。
- profile 名含 prod 才守护：否决，那是死码。

## Consequences

- 爆炸半径不在本 ADR 里写死数字：运维令牌的命中点总数由全仓 grep 现算为准，抄文档必过期（第十一轮为格数立的就是这条规矩，这里照用）。按形状说，收紧要动的实质只剩一处——`index.html` 那个令牌预填。`scripts/` 下的验证脚本与审计脚本自己全跑在回环上，一行不改；连带要改口的只有 README「身份不可伪造」那一格的措辞。
- 绑定回环只是必要条件，不是防线。反向代理场景下上游打的是 `127.0.0.1`，外面已经能到这里却仍判合法。这句必须写进 README，不留给读者自己发现。
- 非回环时 mock 签发端点不注册，等于承认身份层的默认配置是纸糊的。README 与问答库里凡指着 mock JWT 讲设计取舍的地方要跟着加限定：本仓钉的是不可伪造，不是不可领取，两个词的定义见 `CONTEXT.md`。
- 审计脚本不改。A3 那处的 dev 运维凭证保持原样——触发器不改变回环上的行为，量具的锚点链因此不必再换一代。
