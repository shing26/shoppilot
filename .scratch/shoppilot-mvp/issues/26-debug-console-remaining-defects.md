## 承接（票 22 收尾双轴审查转过来的两条）

- **勾 8 / S4**：「调试台换身份后清空对话区」目前的长期量具是**静态页结构断言**
  （`ConversationOwnershipTest#servedConsoleResetsConversationOnIdentitySwitch`：读网关下发的那份 HTML，
  钉「清 `#chat` + 换会话 id」确实挂在身份比较之后、且比较早于把新身份写进 `state`）。浏览器里的真实渲染
  只做过一次性活体复跑（2 条气泡 → 0 条、时间线清空、同身份再点一次不减少），按铁律那类读数不许长期引用。
  本票既有的那条「每条都在 `verify-console.mjs` 里落成断言」顺手把它收进去：改买家框 → 点换身份 →
  `#chat .msg` 归零且 `#conv` 换了值；再点一次换身份（身份未变）气泡数不减——第二条防的是把清屏写成无条件清。
  注意那是 15 项之外的新增项，README 里凡按「15 项 / 15 条断言」数当前轮断言的地方要一起换代（票 21 那种加前置不改数的例外不算）。

  本票若给调试台加「按会话 id 查上下文」那类口子，必须先回到 ADR 0025 重开一条决定，别在实现里顺手把映射表请回来。

## 收尾双轴审查（fixed point = cf638ae）

落点与票 24、票 25 共用一份 17/17，日志名与读数写在 README 的「票 24 / 票 25 / 票 26 共用落点」那一段。

**这一票买到了什么**：走查那 12 项里剩下的九项一次收拾完，且这九项从此不再靠「一次跑器加 12 张截图」作证——
`verify-console.mjs` 从 18 项涨到 35 项，跟着门禁跑。最值钱的两格不是修好的那两处样式，而是：
其一，抽屉那处「点开之后第二次点不动」从此有 `elementFromPoint` 这一格量着（那一轮的人工跑器正是死在这里、
超 30 s 崩掉，当时只留下一句「疑似遮挡」）；其二，运维读数那两格把「失败」与「上一次的成功值」在 DOM 上分成
两件事（`dataset.state` 与 `textContent` 同写），并且证明两格各管各的——令牌错时 `refunds` 变灰，
不受令牌保护的 `circuit` 仍报 live。这不是样式，是「面板说的话能不能信」。

**Spec 轴（逐勾取证，判据在哪、读数是什么）**：

- 勾 1（空输入）：`ask()` 里那句 `if (!query) return` 换成 `showHint('先输入一个问题，再点发送')` 并聚焦，
  提示行 `role="status" aria-live="polite"`。格：`empty submission says so instead of going silent`，
  它同时断「气泡数 0 → 0」——反馈要有，但不许把空问句伪造成一轮对话。
- 勾 2（超长回显）：`rejectionText(res)` 读票 25 那半给的 `message`，回显成 `请求被拒绝：400 query：问题太长，上限 500 字，请精简后再问`。
  格：`overlong input echoes the backend validation message` 同时要求 `500` 这个数在句子里，
  并要求提示行已清空（上一勾那行不许赖在下面）。这一勾能成立全靠票 25 补的那格
  `#streamEndpointSendsTheSameEnvelopeForInvalidInput`：`Accept: text/event-stream` 下 400 的 JSON 信封若被换成 406，
  这条断言就是空转。
- 勾 3（进行态）：`typingRow()` 挂在对话区末尾、拿不到就撤——三处撤：第一个 token、`!res.ok`、`finally`。
  它刻意不写进气泡（气泡靠 `textContent` 累加 token，混进去就把「正在」两个字复述进答案）。
  格：`first-token wait shows an in-progress line and takes it away`，读数是 `typing="正在等模型首字" left=0`；
  前置是那一格自己先 `#btnFlush` 清一次缓存，否则 L1 命中会把打字机退化成一次性下发，量的就成了缓存而不是流式。
- 勾 4（读数分家）：`setGauge(id, text, stale)` 是这一格唯一的写字处，两支（`circuit` / `refunds`）都从它走。
  两格各查一个失败原因（票 21 拆出来的那两个）：空令牌 → `未填令牌` + `state=stale`；错令牌 →
  `读不到：ops.token_mismatch` + `state=stale`（`failureReason` 优先读票 25 的 `code`，没报文才退回状态码）。
  两格都另断 `circuit` 仍 `live`：分家的意思是各管各的，不是一起变灰。
  顺带一处是量具逼出来的：`page.fill()` 只发 `input`，`change` 要等失焦——原注释写「fill 会触发 change」是错的，
  而挂在 `change` 上等于「粘完令牌不挪鼠标，footer 上还是上一次的值」。改成输入后去抖 400 ms，注释换成实测事实。
- 勾 5（回执分家）：`report()` 落 `#opslog`（class `ops ok/bad`），`clearTimeline()` 只清 `#timeline`。
  格：`ops receipts stay out of the answer event stream` 断 `#timeline` 里 `ops` 行为 0、`#opslog` 行数 ≥ 1；
  原来那格 `fault injection applied through gateway proxy` 的取证处也从 `#timeline .ev` 换成 `#opslog .ops`——
  不换它就变成在测「回执混在事件流里」这个被本票修掉的旧行为。
- 勾 6 / 勾 7（窄屏两格）：`@media (max-width:1100px)` 里那句 `display:none` 换成「横跨两列的一条」，
  `main` 的高度改由 flex 分配（原先 `calc(100vh - 49px - 62px)` 把页脚按死 62px，页脚一换行就盖内容）。
  格：900px 那格断的是几何而不是存在——`h > 60`、事件行数 > 0、`top >= 对话列 bottom - 1`（它得真在主列下面，
  不是叠在上面）；390px 那格断 `footer.scrollWidth <= clientWidth` 与文档宽度不溢出（走查当时的实测是「需 1264px / 可见 390px」）。
- 勾 8（抽屉四格）：遮罩 `hidden` 随开关同步；`Esc` 与点遮罩各关一次；`header` 抬到 `z-index: 21` 且抽屉与遮罩
  从 `inset-top: 49px` 起（那 49px 与同文件里 `header` 声明的高度同源，注释点名）。最能打的是
  `open drawer does not intercept the header button under the cursor`：拿 `elementFromPoint` 打在「工单队列」
  按钮正中，命中 id 必须还是它本身。这一格是变异量不出来的——它防的是「修好之后又长回来」，所以留成常驻格。
- 勾 9（对比度）：`--ink-3` 由 `#8b929d`（白底 2.9:1）改到 `#6b7280`（4.83:1），一处令牌带动 label / `.dim` /
  `#mode` / `.empty` / `.ctl .t` 全族。格 `secondary text clears WCAG AA (>= 4.5:1)` 量的是浏览器里算出来的比值，
  清单按走查点名的那一族来再加本票新写的三处。**这一勾第一轮判早了**：第一轮只量白底那几处，
  `#opslog` 的 `.empty` 坐在 `--line-2` 浅灰底上，同一支令牌只有 4.16:1；补进清单后当场露出来，
  处置是那一格单独改深一档到 `--ink-2`（5.21:1），不动全家共用的令牌。
- 勾 10（次一级三项）：工单卡片带 `fmtTime(t.createdAt)`（`TicketView.createdAt` 是 `Instant`，
  缺值时 `fmtTime` 出 `-`，那格按 `\d{2}:\d{2}:\d{2}` 断，不放 `-` 蒙过去）；`#customer` 加 `maxlength="32"`；
  末尾那具游离 `</script>` 删掉，且第三项的量法是 `fetch('/')` 拿**服务器下发的那一份原文**数闭合标签，
  不是 `page.content()`——游离标签正会被解析器替人吃掉，量修过的 DOM 等于自证。
- 勾 11（全部落成断言）：`console` 18 项 → 35 项，17 格新增对应上面九勾 + 次一级那一格。
  票 22 转过来的那条「换身份清屏只有静态页结构断言」也在里面：两格并排，同身份再点一次气泡数不减（10 → 10）、
  换买家则归零且 `#conv` 换值（10 → 0），第二条防的是把「清屏」写成无条件清。
- 勾 12（三条作废猜测）：本票没有为它们写任何一行「修复」，也没有留任何一条为它们设的格子。
- 勾 13：全程 `local` 档、`ollama` 打底，零付费额度；审计项数仍是 95。

**Standards 轴：报 7 → 成立已修 3、成立接受 3、报出后不成立 1**。

- S1 [P2] **对比度只量白底那几处**（成立，已修）：见勾 9。这条的价值一半在量具——它证明「按点名的那一族量」
  和「按手边好量的那几处量」不是一回事。
- S2 [P2] **`contrast.length >= 4` 的下限把「一个选择器没命中」当成通过**（成立，已修）：原清单第五条 `.empty`
  在探针跑到时早被内容替换，`probe()` 返回 null 被 `filter(Boolean)` 抹平，四条命中就满足了下限。
  现在是七条清单 + `>= 6`，并且空态那一条用「同段临时插一个同结构节点、量完撤掉」拿到真实级联。
- S3 [P3] **量具里那条「fill 会触发 change」的注释与实测不符**（成立，已修）：实测只发 `input`。
  页面改 `oninput` + 400 ms 去抖，注释换成事实；这条同时修掉一个真缺陷（粘完令牌不挪鼠标就没有读数）。
- S4 [P3] 那 49px 是同文件里的第二处硬编码（`header { height: 49px }` 与抽屉/遮罩的 `inset-top`），
  改 header 高度会分家。成立并接受：两处挨在同一屏的同一个 `<style>` 里，注释点名同源；
  且真挡路的那一半已由 `header { z-index: 21 }` 独立管住——数值漂了最坏是难看，不是点不动。
- S5 [P3] `.hint` 用 `textContent` 写同一句话时屏幕阅读器不重复播报（`aria-live` 只在内容变化时报）。
  成立并接受：这一行的语义是「当前输入框的状态」，同一句重复播报反而吵；真要保证可达，该在按钮上标 `aria-disabled`，
  那已经登记为下一轮候选；ADR 0030 的 P1 清单本轮不扩写，不再指向一张不存在于本轮的票。
- S6 [P3] 每个 token 都调一次 `pending.remove()`（首帧之后是空操作）。成立并接受：换来的是三条撤电路径
  （首帧、`!res.ok`、`catch`）不必各自判存在，少一处漏撤就是少一个「进行态挂在屏幕上不走」的缺陷形状。
- 报出后不成立：「工单卡片的时间戳是前端自己造出来的」——不成立，`TicketView` 那一列 `Instant createdAt`
  是既有字段，代理原样带出；`fmtTime` 缺值只出 `-`，而那格明确不许 `-` 通过。

**转票**：无；S5 只登记为下一轮候选，未新建本轮票，也不扩写 ADR 0030 的 P1 清单。本票欠的两样都记在本页上而不是别处：其一，`.hint` 那类即时反馈若要键盘/读屏可达，得配合
按钮态一起改，不是一行的事；其二，`49px` 那对同源常量若长出第三处，就该换成一个 CSS 自定义属性——
现在两处，注释点名，不到动手的时候。
