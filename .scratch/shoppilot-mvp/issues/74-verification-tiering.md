# 74 验证分档：日常档 / 全栈档 + 事件对账门禁

**Status:** implemented（2026-10-02）

## What to build

ADR 0053 的 Consequences 直接派生：全栈约 7 GB，日常档子集约 3.5 GB，而本机同时跑着另外四套项目（实测可用内存曾只剩 0.5 GB）。**验证不分档 = 验证不可复跑**。

**范围被裁定 A 收窄（见 spec §0）**：本轮**不跑活体验证**，所以本票交付的是**机制**而不是读数。

- `run-acceptance.ps1` 加 `-Tier daily|full`：
  - **daily**：中间件 + 网关 + 工单服务（+ 可选业务服务），够跑 JVM 门禁、定向验收；
  - **full**：四服务 + local 模型，**仅清场日**。
- 分档写进 `docs/EVIDENCE.md` 与 `README` 的验收段；**全栈档的红不得冒充日常档信号**（round17 起的既有纪律，措辞照抄那条）。
- 收口审计新增**事件对账**门禁（0054 承诺的第三类证据）：发布数 / 消费数 / pending 是否归零。审计常数随票换代。**注意**：门禁只在 JVM 层（裁定 D 的内存实现）成立；真实 Redis 上的 pending 读数照登未达成。
- **资源读数本轮取不到**（不起栈）——记一条**待补**而不是编一个数字。

## Handoff notes

### 关键决策

1. **档位切的是「步骤集合」，不是判据**。这是本票最要紧的一句话：两档里每一步的判据逐字相同，
   daily 只是选了一组不依赖活体栈的步骤。把它写成「daily 档判据更松」就是一个假的降级。
2. **daily 档的步骤集合写死、不从 `Need` 反推**：反推会把「某一步今天临时不依赖栈」悄悄变成口径变更，
   而这里要的是常量的意图——一眼能看出哪些步骤归日常档。
3. **`-Only` 撞档位时退出码 2 并点名**，不静默忽略：`-Tier daily -Only plan` 会说清它在 full 档、
   daily 有哪些、要跑它请用 `-Tier full`。静默忽略会让「我明明指定了它」变成「它怎么没跑」。
4. **事件对账门禁钉 surefire 报告而不是脚本输出**：门禁真跑过、条数没被悄悄削掉，两件事一起判。
   顺带把审计项数从 95 推到 96，并给票 20 里那两处历史 95 加了历史标记（H7/H7b 随之转绿）。

### 踩到并修掉的两个真问题

1. **门禁一开始用裸 SQL 插入，于是它根本没在考验幂等**：重投那条用例炸在唯一约束上——因为去重发生在
   `AuditEventWriter`（票 71）里，而裸 SQL 绕过了它。改成**走生产的幂等写入器 + 消费者按生产形状 catch**，
   门禁才真的量到「重投被再次交付、但不产生第二行」。
2. **四个用例共用同一个通道实例，被拒的事件留在 pending 里被下一个用例消费**，
   报出来的红却落在**后一个**用例身上。加 `@BeforeEach` 排空（表与通道都排）。
   这和 `RoutingDispatchTest` 里「一个用例的选择偷走另一个用例的断言」是同一个病。

### 现场三问

1. **为什么档位切步骤而不是切判据？** 因为两档必须对同一件事给同一个答案。切判据等于让「日常档」变成
   一个更松的说法，而本仓的红之所以有意义，正是因为没人能通过改口径让它变绿。
2. **为什么门禁钉 surefire 报告？** 钉脚本输出的话，把用例删掉再打个同样的字符串就过去了；
   钉报告等于同时证明「跑过」和「条数没被削」。
3. **为什么 daily 档不包含起栈那几步？** 因为起栈是 7 GB 的动作，而 daily 档的意义是「任意机器随时能跑」。
   把它算进去，daily 就退化成一个跑不动的 full。
