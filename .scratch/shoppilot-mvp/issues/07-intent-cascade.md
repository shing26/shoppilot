# 07 — 意图三级级联判定补全

**What to build:** 十个意图（含 `UNKNOWN`）在 T0 规则、T1 向量质心、T2 模型三级下被判定，动作优先，全程不为分类多花一次模型请求。落实 ADR 0007。`L1` / `L2` 只指缓存两级，不用于意图层。

**Blocked by:** 05 — 最细竖切；06 — L1 精确缓存、写回资格与进程内 singleflight

**Status:** ready-for-agent

**Verify:** 用一条口语改写政策问句与一条含订单号问句各请求一次 -> 前者定案政策咨询且准入缓存，后者定案业务办理且不准入缓存。

- [ ] 意图枚举是 `CONTEXT.md` 意图清单的唯一定义源，缓存分区、工具裁剪、限流统计、评测集四处共用，禁止字符串散落各处
- [ ] 本 ticket 落地本地 embedding 客户端（`bge-m3`，1024 维）与 10 意图内存质心，向量化能力由 ticket 09 的语义缓存直接复用，不得出现第二套 embedding 调用路径
- [ ] T1 质心层：每意图 8-15 条样例句取质心做最近邻，与 T0 规则层共用一次向量化，不额外调用 embedding
- [ ] T2 模型层仅在 T0/T1 均不确定时进入，tools 全量下发，由是否返回 `tool_call` 充当意图证据
- [ ] 判定结果 `intent` 是服务端上下文的一等字段，供缓存 payload filter、限流统计、trace 与 SSE `meta` 事件共用
- [ ] 多意图取动作优先；`UNKNOWN` 为显式意图，fail-closed 不查缓存
- [ ] 规则表与样例句集进版本控制，改动可追溯；两者是需长期维护的资产，不是临时脚手架
- [ ] 用例：一条含订单号的口语句判为 `ACTION_LOGISTICS` 且不准入缓存；一条改写句判为政策咨询且准入缓存
