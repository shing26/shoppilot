# 07 — 意图三级级联判定补全

**What to build:** 十个意图（含 `UNKNOWN`）在 T0 规则、T1 向量质心、T2 模型三级下被判定，动作优先，全程不为分类多花一次模型请求。落实 ADR 0007。`L1` / `L2` 只指缓存两级，不用于意图层。

**Blocked by:** 05 — 最细竖切；06 — L1 精确缓存、写回资格与进程内 singleflight

**Status:** done

**Verify:** 用一条口语改写政策问句与一条含订单号问句各请求一次 -> 前者定案政策咨询且准入缓存，后者定案业务办理且不准入缓存。

- [x] 意图枚举是 `CONTEXT.md` 意图清单的唯一定义源，缓存分区、工具裁剪、限流统计、评测集四处共用，禁止字符串散落各处
- [x] 本 ticket 落地本地 embedding 客户端（`bge-m3`，1024 维）与 10 意图内存质心，向量化能力由 ticket 09 的语义缓存直接复用，不得出现第二套 embedding 调用路径
- [x] T1 质心层：每意图 8-15 条样例句取质心做最近邻，与 T0 规则层共用一次向量化，不额外调用 embedding
- [x] T2 模型层仅在 T0/T1 均不确定时进入，tools 全量下发，由是否返回 `tool_call` 充当意图证据
- [x] 判定结果 `intent` 是服务端上下文的一等字段，供缓存 payload filter、限流统计、trace 与 SSE `meta` 事件共用
- [x] 多意图取动作优先；`UNKNOWN` 为显式意图，fail-closed 不查缓存
- [x] 规则表与样例句集进版本控制，改动可追溯；两者是需长期维护的资产，不是临时脚手架
- [x] 用例：一条含订单号的口语句判为 `ACTION_LOGISTICS` 且不准入缓存；一条改写句判为政策咨询且准入缓存

## Handoff notes

**关键决策**

1. **`Intent` 枚举是十意图的唯一定义源**，放在 `shoppilot-tool-api`（`com.shoppilot.tool.Intent`），缓存分区、工具裁剪、限流统计、评测集四处共用同一个枚举，禁止字符串散落。它必须在契约模块而不是网关模块，因为 biz-mock 与评测脚本都要认这套词。
2. **`cacheAdmissible() == isPolicy()`** 写在枚举里：只有 `POLICY_*` 可准入。`UNKNOWN` 是显式意图且 fail-closed 不进缓存——"判不出来"不是"可以赌一把"。
3. **T1 的候选集按动作证据裁剪（实测逼出来的修正，见下方"标定"）**：`T0RuleLayer.classify` 在扫到实体或第一人称时必定案返回，所以落到 T1 的句子没有实体证据；此时仍把 ACTION 质心放进候选，会把政策问句吸进动作桶——实测 `退款多久到账` 最近质心是 `ACTION_REFUND`(0.8518)、`你们家用的哪家物流` 是 `ACTION_LOGISTICS`(0.7766)，而动作意图不准入缓存，**分类越保守缓存越漏**。规则改为：有动作动词保留全 10 意图，无动作证据只留 `POLICY_*` + `ESCALATE`。
4. **三级级联，全程一次向量化、至多一次模型调用**：T0 规则（实体正则 + 关键词表 + 所有格动作词表）→ T1 质心（每意图 8-15 条样例句取质心做最近邻，与 T0 共用同一个 query 向量）→ T2 模型（仅在 T0/T1 均不确定时进入，tools 全量下发，由是否返回 `tool_call` 充当意图证据）。T1 判定线：最高分 ≥0.82 且领先第二名 ≥0.03，否则继续下沉。
5. **动作优先于政策**：多意图命中时取动作意图。"我的生鲜坏了要退款"既是政策又含动作词，走动作——因为动作需要真实数据，政策答案替代不了它。
6. **`intent` 是服务端上下文的一等字段**，供缓存 payload filter、限流统计、trace、SSE `meta` 事件共用同一份判定结果，不存在"缓存自己再判一次"。
7. **规则表与样例句集进版本控制**（`T0RuleLayer` 常量 + `resources/intent-samples.json`）。这两份是需长期维护的资产，改一行等于改产品行为，必须可追溯。
8. **本 ticket 落地本地 embedding 客户端**（`bge-m3`，1024 维，经 Ollama），ticket 09 的语义缓存直接复用同一个 `EmbeddingClient`，全项目只有一条 embedding 调用路径。

**你需要能当场回答的三个追问**

- *Q：为什么不直接让模型分类？* A：一次模型调用的时延与成本要摊到每个请求上，而 80% 的请求 T0/T1 就能定案。三级级联把分类成本从"每请求一次"降到"少数请求一次"，且 T0 规则可解释、可单测。
- *Q：T1 质心会不会一换语料就崩？* A：质心由 `intent-samples.json` 现算并缓存到 `shoppilot.triage.centroid-cache`，按样本指纹失效；改样例句会重算，不需要重新入库政策语料。
- *Q：10 个意图封顶够吗？* A：对电商客服场景够，且这是刻意的上限——意图数线性影响质心维护成本与误判面。新增意图要走规则表与样例句双份改动，这个摩擦是有意的。

**验证记录**

`T0RuleLayerTest` 10 项：含订单号的口语句判为 `ACTION_LOGISTICS` 且 `cacheAdmissible=false`；改写句判为 `POLICY_*` 且准入。

**T1 判定线标定（`scripts/calibrate_intent.py` -> `docs/intent-calibration.md`）**：在 180 条标注用例上扫 7 个置信度 x 4 个差值 x 2 套候选规则，选定 **置信度 0.70 / 领先差值 0.020 + 按动作证据裁剪候选**，政策问句准入率从 9.1% 升到 72.7%，判错桶 1/24（4.2%），动作问句被准入为政策 0 条。三条硬线写进脚本的退出码：动作泄漏必须为 0、置信度不得低于 0.70、判错桶率不超过 5%。判错桶只是质量线——缓存 key 含归一化文本，同一句永远落进同一个桶，不会把 A 题的答案发给 B 题，它损失的是命中率不是正确性。`scripts/verify-polarity.ps1` 覆盖准入失败时的 fail-closed 行为（「这个是不是不能退」→ `UNKNOWN`）。

排序说明：本 ticket 必须先于 L2 语义缓存落地。L2 的 Qdrant 检索强制带 `intent` 过滤，若先做缓存则要么把意图硬编成 mock，要么写出不带意图桶的裸向量缓存，落地时必然破坏性重构（ADR 0003、0007）。
