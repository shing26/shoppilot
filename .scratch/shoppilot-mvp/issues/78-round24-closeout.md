## Handoff notes

### 这一轮真正买到的东西（与 spec §0 的预判对照）

**容器化不省内存**——spec §0 写这句话时是推理，本轮**实测到了**：构建时 Docker 引擎被宿主内存压杀、
`wsl` 后端卡死且进程杀不掉，强制重启才恢复。这是那句话的第二次验证（第一次是全栈与另三个项目栈共存时的 OOM）。

真正买到的是三条：
1. **干净克隆一条命令**（ADR 0020 那条可复现性判据第一次真正兑现）；
2. **`mem_limit` + `restart`**：崩了只崩容器。中间件被压杀后网关空转 **72 次**那个教训是它的直接证据；
3. **基础镜像可本地化**：代理对 Docker Hub 不通时，经 `docker.m.daocloud.io` 拉下来 `tag` 回原名即可，
   Dockerfile 的 `FROM` 命中本地镜像——**不用改宿主任何配置**。

### 抓到的三个洞（都是「本机怎么测都测不出」那一类）

1. **`mvnw` 的 CRLF**（票 77）：干净克隆时被 autocrlf 转成 CRLF → 容器构建 `exit 127`；本机工作树是 LF、构建照过。
2. **固定 `container_name`**（票 77 → 79）：Docker 全局名，第二份克隆必撞。改成按项目加前缀，主仓渲染一字不变。
3. **中间件缺 `restart`**（票 76）：只有 full 档服务有策略，中间件被压杀后再没起来，网关在它上面空转 72 次。

另外还修了两处**我自己写的假绿/漏改**：`-Containerized` 就绪失败却照样打「栈已就绪」横幅；
以及票 79 第一笔提交**漏了 `docker-compose.yml` 这个文件**，而我当时那句「默认渲染一字未变」
恰恰是旧文件渲染出来的、区分不出改动有没有发生——是第二份克隆仍然撞名才暴露的。

### 必须带走的欠账（三笔）

1. **ports 段不吃 shell 环境变量**，成因**未查清**：变量 `config --environment` 看得见、文件里有占位符、
   却没替换进 ports；`export` 与 `VAR=x cmd` 两种写法都试过。现在靠 `.env` 绕开——**那是绕过，不是解释**。
2. **compose 里 gateway 对依赖用 `service_started` 而非健康门**：起栈会在依赖未就绪时认为链路可用。
3. **容器化不省内存**（见上）。

### 现场三问

1. **这一轮为什么没动 CI？** 容器档要下镜像、起容器、连 Ollama；round15 当年明写 CI 八步不依赖外部服务，
   票 73 加第九步时又强调一遍。**「不起栈」与「起栈」之间隔着的不是懒，是 runner 上跑不起来。**
2. **为什么默认档一行没动？** 容器档是 `-Containerized` 下的并行一条路。默认渲染核对过与改动前逐字相同。
3. **这轮最值钱的产出是哪个？** 不是「能起」，是那三个「本机测不出」的洞——它们全都只在
   **换一份克隆 / 重启一次机器**时现形。
