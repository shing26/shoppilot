# 137 安全闸清单重列：新结构下哪些出口不可重试

**Label:** wayfinder:grilling　**Status:** implemented（决策票：裁定 + 清单，零代码改动）　（map：[135](135-wayfinder-agent-autonomy-map.md)）

**Claimed by:** zcode wayfinder session 2026-10-18

## Question

spec 决策 4 列的「安全闸四类不可重试」是 2026-10-01 的结构。当前结构下，**「不可重试」的确定性出口完整清单**是什么——
旧四类之外，审批闸、角色拒、空召回出口、写动作守卫、限流各自算不算、以什么形式算？

## 已核实的事实（不必重查）

- **旧四类**（spec 决策 4）：归属拒绝、编造拦截（`ToolDispatcher.isUntrustedOrderNo`）、幂等回放
  （`IDEMPOTENT_REPLAY`）、终态拒绝（`STATE_NOT_ALLOWED`）。
- **新结构候选**（2026-10-01 之后落地）：
  - 审批闸 `PENDING_APPROVAL`（round21 票 59）：**受理不是失败**，走正常出口——但它是不是「反思不得触碰」的语义？
  - 角色拒 `role.denied`（round30 / ADR 0063）：发生在**网关层**，不在工具循环内——要不要在清单里显式写明「循环外的闸」。
  - 空召回确定性出口 `INTENT_UNRESOLVED`（ADR 0068）：在**检索之后、模型之前**——同样在循环外。
  - 写动作守卫（票 41）：模型承诺写动作但没调工具时的纠偏（一次）——与「反思」语义相邻，必须划界。
  - 限流（ADR 0007）：准入层，循环外。
  - `ShopRuleIndex` 探针（ADR 0068）：**不是闸**，是缓存共享前置——列为「非闸」以免清单膨胀。
- 相关既有语义：`TOOL_ROUNDS_EXHAUSTED` 超限收口；`ToolStatus` 当前 6 成员
  （`OK / NOT_FOUND / STATE_NOT_ALLOWED / PENDING_APPROVAL / IDEMPOTENT_REPLAY / TIMEOUT`）。

## 口径

- 本票是**决策票**：产出「不可重试清单 + 每条所在层（网关/状态机/biz-mock）+ 与反思的边界一句话」。
- 理由线照 spec：反思重试被安全闸拦下的调用 = 换着花样绕闸；跨租户串号 0 次不可被威胁。

## Resolution（2026-10-18，grilling 三问：Q1/Q2 获所有者裁定、Q3 未获答按建议值；决策票，零代码改动）

**会话记录**：Q1（清单结构）裁定**三段式**；Q2（闸清单成员）裁定**旧四类 + 审批闸 + 行业门**；
Q3（循环外节宽度）未获回答，按建议值（完整六行）记录；写动作守卫划界依既有语义整理（未单开问）。
三处建议值若与所有者本意不符，可在 [142](142-round-scoping-and-adr-0069.md) 落 ADR 0069 前修正。

**判据一句话（反思作用域）**：反思只作用于「工具真的调了、且失败可归因操作性」；
**闸 = 重试或换路即绕闸**——直接走原出口，反思不得介入。

### 一、闸清单（反思不得触碰；重试或换路即绕闸）

| # | 闸 | 层 | 形式与原出口 | 与反思的边界一句话 |
| --- | --- | --- | --- | --- |
| 1 | **归属拒绝**（跨租户/不存在订单一律 `NOT_FOUND`，不区分「存在但不可见」） | biz-mock（`BizMockService:280-292,422`） | 循环内：`failedStep`（`AgentStateMachine:793`）→ 计划中止（:411-419）→ 模型组织人话，不落降级工单 | 反思不得换单号重试——换号即撞库/越权探测；原出口照旧。 |
| 2 | **编造拦截**（`isUntrustedOrderNo`：格式非法或买家没说过） | 网关（`ToolDispatcher:87-90,173`） | 循环内、调用前：`Dispatch.fabricated`（`status=null`）→ 退回追问（`askSlot`；追问超限 `SLOT_UNRESOLVED`） | 该调用根本没发生过，不是可反思的失败；反思不得补枪或编新单号。 |
| 3 | **幂等回放**（`IDEMPOTENT_REPLAY`：同 token/请求指纹的写动作已执行过） | 网关（`ToolDispatcher.executeWrite:116-121`）+ biz-mock | 循环内：回放首次结果回填，**不算失败**（不在 `failedStep`），循环继续 | 反思不得重执行写动作；重放结果就是答案（`duplicateSubmit` 与 `implied_retry` 计数照旧）。 |
| 4 | **终态拒绝**（`STATE_NOT_ALLOWED`：业务状态前置校验不过） | biz-mock | 循环内：`failedStep` → 计划中止 → 模型组织人话 | 反思不得换参重试同一业务动作——状态在轮内不会变。 |
| 5 | **审批闸**（`PENDING_APPROVAL`：资金动作已受理、待人工放行） | biz-mock（受理）+ 网关（受理落幂等，`executeWrite:129-133`） | 循环内：**受理即收尾**（:404-409；resume 路径 :709-712），不打第二跳模型、不走 fallback、不落工单 | 反思不得对同笔资金动作重发或改参重发——那是绕审批；受理不是失败，原出口照旧。 |
| 6 | **行业门**（非电商租户 `toolsFor` 返回空工具集；未登记租户 fail-closed 成 `UNKNOWN`，ADR 0067） | 网关（`AgentStateMachine:765-774`；网关派生同门 :460） | **前置裁剪（非出口）**：工具不下发，模型照实说明办不了（prompt v1.1.0 第 7 条） | 反思换路只能在门后工具集内——工具集不因反思放宽，也不得借反思绕门派发。 |

### 二、循环外的确定性出口（反思结构性够不到；登记为边界）

| 出口 | 层 | 为什么够不到 |
| --- | --- | --- |
| 限流 `RATE_LIMITED`（键 = 租户 + 买家/IP；单位由 ADR 0004 定，票面引的 ADR 0007 只是「意图枚举四处」的转引） | 网关准入（`ChatAdmission.check` → `RateLimitService`） | 在状态机之前；同步 429 / SSE 降级帧两条路 |
| 情绪门 `EMOTION_ESCALATION`（词典层 0 token；显式转人工词表绕行，ADR 0042） | 状态机 INTAKE（:131-150） | 在意图判定之前 |
| 显式转人工 `USER_REQUESTED` | 状态机 TRIAGE（:178-181） | 用户意图，不是失败 |
| 请求级幂等回放（ADR 0046 票 58） | 状态机 INTAKE（:158-164） | 整轮回放先于一切；**回放不是降级**（刻意不走 fallback） |
| 空召回/负缓存 `INTENT_UNRESOLVED`（ADR 0068；负缓存命中 :201-206、SingleFlight 落空 :221-222 同出口） | 检索层（模型前，:290-298） | 在工具循环之前 |
| 角色拒 `role.denied`（ADR 0063） | **面外：运维面 `OpsController:148/164/461`** | 不在买家对话链路（退款审核/工单动作 403）——比「循环外」更远一格 |

### 三、非闸（明确排除，防膨胀）

- `ShopRuleIndex` 探针（ADR 0068）：缓存共享前置——不是闸、也不是出口。
- 判据一句话：**不是拒绝、不是终态出口 → 不进闸清单**（前置类不逐条列，本票只留这一条实例与判据）。

### 四、写动作守卫与反思的划界（依既有语义整理）

- **对象不同**：纠偏（票 41 nudge）治「**没做**」——模型文字承诺了写动作但没调工具；反思治「**做了但失败**」且失败可归因操作性（③）。纠偏不是闸（不拒绝、不拦），不进闸清单。
- **记账不同**：纠偏上限 1 次、**不占工具轮**（轮次只统计真正执行过的工具，票 41/ADR 0008 语义不动）；反思**占工具轮**、同工具同型上限 1 次（spec 决策 4）。最坏模型调用有界照 [136](136-autonomy-budget-and-steps.md)：≤4 工具轮 + 预算检查 1 次 + 纠偏 1 次。
- **互不替代、可同轮先后出现**：如「读工具失败 → 反思重规划 → 模型改口承诺写动作却没调 → 纠偏一枪」；反之亦可。两者都不放宽闸。
- **轮尽写未办**：照旧 `TOOL_ROUNDS_EXHAUSTED` 落工单（票 41 守卫），不因反思存在而给口头承诺留门。

### 五、给 [138](138-failure-triage-reclass.md) 的输入

1. **闸集（①类）**：`NOT_FOUND`（归属）/ `STATE_NOT_ALLOWED`（终态）/ `IDEMPOTENT_REPLAY`（幂等回放）。
   **编造拦截不是 `ToolStatus`**（`Dispatch.fabricated`，发生在调用前、`status=null`）——138 按 ToolStatus 重列时它不占格，但占本票闸清单第 2 条。
2. **审批闸 `PENDING_APPROVAL` 不硬塞进 ①②③**：它是「受理非失败」的终态出口（ADR 0047）——建议映射表给它第四格「非失败终态」或等价显式说明。
3. **③候选（操作性失败）**：`TIMEOUT` / `UNAVAILABLE`（含熔断打开、锁忙、序列化失败）——归类由 138 定。
4. **事实修正**：`ToolStatus` 实为 **7 成员**——票面（137/138 同错）写的 6 成员漏了 `UNAVAILABLE`（`view/ToolStatus.java:25`）；138 重列必须按 7 格。
5. 边界句照本票第一、二、四节。

### 六、附带发现（登记不执行 → `registered-debt.md` R11；实现轮处理）

**写动作守卫（票 41）没吃行业门**：`expectedWriteTool(intent)`（`AgentStateMachine:305`）与纠偏条件（:327）都不看 `domain`——非电商租户若被 T1 判成 `ACTION_REFUND/ACTION_ADDRESS`（ADR 0067 已承认 T1 能产出，故在 `toolsFor`(:766) 与网关派生(:460) 加了两道门，守卫这一处漏了同一道），模型无工具只能文字作答 → 纠偏仍会触发一枪：+1 次模型调用、`shoppilot_write_nudge_total` 记一次「纠偏」、且给模型的指令（「直接调用 applyRefund 把它真的办掉」）与 prompt v1.1.0 第 7 条（无工具时「照实说明办不了」）冲突，存在诱导谎报「已提交」的风险。
**依据边界**：代码路径核实，未活体复现；`AgentStateMachine` 无 HOTEL 级 JVM 用例。**修法（实现轮）**：纠偏条件加 `domain == Domain.ECOMMERCE`（或按 `toolsFor` 非空判），顺带补 HOTEL 用例。

## Handoff notes

**关键决策**：见 Resolution 第一至四节。一句话：**三段式清单**——闸 6 条（旧四类 + 审批闸「终态受理」+ 行业门「前置裁剪」）反思不得触碰、
循环外 6 出口登记为边界、非闸明确排除；反思只在工具循环内、只作用于③操作性失败。

**验证落点**：决策票，文档级验证 = `git diff --check` + `git status --short`。机器落点留给实现轮：
138 的 JVM 用例钉三分法每格；写守卫的行业门缺口已登记 `registered-debt.md` R11（触发 = 实现轮动写守卫时顺手修）；
gold / 判据面零触碰。

**三个现场追问**：

1. 「反思不得触碰」是不是「连换路也不行」？——是。闸的意义就是不给「换着花样绕闸」留门；原出口照旧
   （编造→追问、归属/终态→计划中止、审批→受理即收尾、幂等→回放）。换路只允许发生在③操作性失败上。
2. 行业门为什么进闸清单（它连出口都不是）？——它是安全语义（跨行业隔离）且反思会重规划工具集：
   列进来是为了钉死「工具集不因反思放宽」；形式标「前置裁剪」以免与出口混读。
3. 角色拒为什么标「面外」？——它在运维面 `OpsController`，不在买家对话链路；「循环外」不足以描述它，
   防止实现轮把它误当买家链路的闸去接线。
