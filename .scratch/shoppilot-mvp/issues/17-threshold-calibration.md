## Handoff notes

**关键决策**

1. 验收按"交付物 / 原始向量 / 系统"三层写，而不是只写一条通过与否。原始向量层两条判据实测不成立，报告里明写"未达成"与"判据本身不成立"，再用系统层证据把安全性质的结论补回来。没改判据，也没把不成立的说成成立。
2. 第一轮扫描只有一对反义越界（0.9682），查下来是样本集缺"最小对立对"——只改一个否定词的那种。补了 4 对后越界数从 1 变 4，且全部落在 0.9645-0.9802：**最小对立对是稳定越界的，不是偶发越界**。这条补样动机写在报告里，不是事后挑数据。
3. 为兜住这类同桶反义新增 `PolarityGuard`（ADR 0016），`CacheEntry` 因此多带写入时的归一化问法字段，历史条目无该字段按 fail-closed 不复用。守卫只做词法判定：NEGATED / AFFIRMING 互斥，正反问（"是不是""能不能"）记 NEUTRAL 不拦，句末"不/没"（"可以退货不"）按语气词处理。
4. 脚本退出码从"反义对不得越界"改成"每条越界对必须被某一层具名防线兜住"。前者在真实 embedding 上不可达，后者才是系统安全性质；Python 镜像实现与 Java 用例两头钉，实现漂移当场红。
5. **0.95 工作点上 L2 召回实测为 0**（同意图改写对最大余弦 0.9435）。80% 级拦截归因给 L1 精确哈希 + SingleFlight，README 不得把拦截率记在语义缓存头上。

**需要能当场回答的三个追问**

1. "那你这语义缓存不是白做的？80% 拦截率是虚的？" —— 拦截率是真的，归因不是。标定实验的价值就在这：它把"语义缓存兜口语化改写"这句任务书原文证伪了，并给出替代结论（L1 + 穿透合并兜热点，L2 只兜写得极近的同意图重复）。
2. "为什么不换个 embedding 模型或者加 rerank 把召回救回来？" —— 换模型改变的是余弦分布，不改变"同意图桶内存在反义"这个结构问题；0.9645-0.9802 这四对换成任何通用中文模型都可能还在。要提召回就得同时提误命中，0.85 处 precision 0.231 那一行就是证据。
3. "词法守卫会不会把正常改写也拦掉？" —— 会，NEGATED 与 AFFIRMING 永不互用是有意的保守。A-not-A 判 NEUTRAL 不拦、句末语气词不拦，剩下的误杀在当前工作点不可测量（召回本来就是 0），且每次拒绝都打点，不是静默失效。
