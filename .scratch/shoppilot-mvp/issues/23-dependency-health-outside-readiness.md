# 23 — 依赖健康与就绪门分开，假健康灯变可信

**What to build:** 让「还能应答但已经降级」与「别再给它流量」成为两个各自可读、可断言、并且在页面上看得见的事实：向量、检索、知识库的真实状态挂在新的 `deps` 组，调试台那颗灯第一次有能力变红。落实 ADR 0026。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

**Verify:** 单测面置依赖为 DOWN 后同时断三件事 -> 浏览器面断灯 -> 拿一档把依赖弄残的实验 profile 起栈，证明门禁照样放行 -> 零额度。

- [ ] 向量、检索、知识库三个健康指示器在位，且都挂在新 `deps` 组下
- [ ] `readiness` 组的成员一字未动（这是 ADR 0026 的红线，不是本轮可商量的项）
- [ ] 依赖置 DOWN 时一条用例同时断三件事：`deps` 红、`readiness` 仍 UP、答案按既有降级路径给出
- [ ] 用把依赖人为弄残的那几档实验 profile 起栈并跑门禁：必须仍然放行——这条就是「没从运维口把 fail-open 改回 fail-closed」的证据
- [ ] 页面健康灯改读 `deps`，并补上它从来就没写过的变红分支
- [ ] 灯的可用三态在 `verify-console.mjs` 那条既有 seam 里各有断言，不再靠肉眼看颜色
- [ ] 摘掉任一健康指示器的注册，至少一格用例当场判错（第十一轮给合取项立的规矩）
- [ ] 零额度；审计项数保持 95
