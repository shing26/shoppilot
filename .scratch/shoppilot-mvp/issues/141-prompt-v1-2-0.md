# 141 提示词换代：v1.1.0 → v1.2.0

**Label:** wayfinder:grilling　**Status:** implemented（决策票：改动点 + 版本 + 联动面，零代码改动）　（map：[135](135-wayfinder-agent-autonomy-map.md)）

**Claimed by:** zcode wayfinder session 2026-10-18（第四张：141）

## Question

4 轮/4 步 + 反思要模型配合，提示词底座要改什么：预算与步数的说明方式、反思的触发表述、
失败分类的对客表述、以及版本资产与 `meta.json` 的换代方式（是否与 [139](139-reflection-observability-and-enum.md) 的观测字段联动）。

## 已核实的事实（不必重查）

- 现底座：`prompts/agent-system/v1.1.0.md`（round33 换代为**行业无关**底座，11 条规则）；`meta.json` fail-fast；
  `PromptCatalog` 版本进 SSE 与评测报告（票 35）。
- 提示词里的既有边界（改时不得踩）：条款未覆盖→说明并转人工（与 ADR 0068 的空召回出口**同语义**，勿重复）；
  不承诺未执行的动作（ADR 0008「不猜不骗」）；可选参数按默认值直调；纯咨询场景不承诺办理。
- local 3B 的实测弱点：长指令容易丢（round31 的「已提交但没调工具」纠偏、票 56 的编造单号都靠**代码**兜，
  不是靠提示词）——提示词换代的收益要按 dev 档判，local 只照登。

## Resolution（2026-10-18，grilling 两问均获所有者裁定；决策票，零代码改动）

**裁定**：① 反思配合**折进第 4 条**（保持 11 条）；② 预算说明**不写数字**（配置是唯一源，第 9 条原文不动）。

### 二、不做的事（防漂移）

- **不写数字**（4 轮 / 4 步不进提示词）：`SHOPPILOT_AGENT_MAX_TOOL_ROUNDS` 是唯一源；env 调档时提示词不漂移。
  [136](136-autonomy-budget-and-steps.md) 的注记（「预算说明从 2 轮换为 4 轮」）据此更正——**v1.1.0 从未写数字**，只有第 9 条「轮次有限」。
- **不教失败分类**（①②③不进提示词）：闸在模型之前、②类中止、③类才反思——分类由系统执行；
  写进提示词反而给模型「讨价还价」的空间。
- **不加新条**：11 条结构保持（local 3B 长指令易丢；票 56 / round31 的教训 = 关键约束靠**代码**兜底，提示词只管表达层）。
- **不动**：第 3 条纯咨询兜底、第 7 条不猜不骗、第 9 条「轮次有限」、第 10 条复述合并结果、第 11 条 200 字上限。
- **R11（写守卫没吃行业门）不在本票**：那是代码修复（`registered-debt.md` R11），提示词无需为它改动。

### 三、与 [139](139-reflection-observability-and-enum.md) 观测字段的联动

- **无新联动**：`promptVersion` 已随 SSE `meta` 与评测报告（票 35 机制）；139 的 `plan[]` 字段与 counter 是系统侧、不读提示词。
- 唯一联动 = **归因**：v1.2.0 的评测读数与 v1.1.0 分开摆（[140](140-eval-suite-and-dev-budget.md) 的新评测集基线标 `v1.2.0`）。

### 四、给 [142](142-round-scoping-and-adr-0069.md) 的输入

- ADR 0069 的落地清单里，提示词换代 = **第 4 条一句扩写 + 版本三件**（新文件 / meta / 测试钉子）；
- 「不写数字」的理由（配置唯一源）写进 ADR 决策依据，防止实现轮或后续轮「顺手把 4 写进提示词」。

## Handoff notes

**关键决策**：见 Resolution 一、二节。一句话：**v1.2.0 的实质改动 = 第 4 条一句扩写**（反思配合折进现条，
保持 11 条）；**预算数字不进提示词**；其余换代动作 = 版本资产与四处钉子同步 + 评测归因。

**验证落点**：决策票，文档级验证 = `git diff --check` + `git status --short`。机器落点留给实现轮：
`PromptCatalogTest`（v1.2.0 + 11 条 + 首尾锚点）、两个 `promptVersion` 断言（`GatewayMainPathJvmTest` / `ChannelFlowJvmTest`）、
`meta.json` 指向；历史版本文件保留。gold / 判据面零触碰。

**三个现场追问**：

1. 为什么只改一条？——提示词的收益面窄（local 3B 长指令易丢，关键约束靠代码兜底）；
   v1.2.0 的实质改动就是第 4 条一句，其余是版本资产与钉子同步。
2. 反思为什么由系统发起而不是提示词驱动？——闸 / 中止 / 反思的判定在状态机（138 的规则六条）；
   提示词只负责「收到失败上下文后怎么做人话与再试」。
3. 评测怎么归因？——`promptVersion` 已在 meta / 报告；v1.2.0 上线后任何读数按新版本标注，
   140 的基线要标版本号（与 v1.1.0 的读数不可混比）。
