## Problem Statement

系统能把一条买家诉求从对话走到可查工单，能在依赖挂掉时按写死的取向降级，但外壳还欠四样，而且证据层自己说了三句假话。

外壳侧：停机时缓存写回池只有 `shutdown` 没有 `awaitTermination`，在飞与排队的写回静默丢弃，没有任何一格计数说丢了几笔；这个池饱和时走「请求线程代跑」策略，被代跑的是一次 Redis 写加一次 Qdrant 向量 upsert——队列一满，命中路径的请求线程要付远程 I/O 的价钱，而这正是大促峰值场景，34 个指标里无一格覆盖。配置面只有必填性守护（绑定地址那条规则），格式与范围没人管：端口写 0、阈值写 1.5、温度写 9，都照样启动，直到某次请求炸出间接错误。熔断器状态、票 23 的依赖健康组、票 21 的 dev 默认值声明，全都只活在 HTTP 出口里，观测不到趋势。

证据侧：README 写着「JVM 在高并发下无日志消失、没有 hs_err、归因未定」，而 14 份崩溃日志一直躺在仓库根，全部是 native 内存 OOM，崩溃瞬间的系统空闲内存与被测出头条吞吐那一刻的空闲读数是同一件事；三个 headline QPS 数字的峰值步主机条件（空闲内存记 0.0、CPU 89-99%）藏在「已知限制」里而不是数字旁；「转人工落可查工单」这句否决项自述漏了作用域——看门狗自愈重启的全量 reseed 顺手抹掉已落库工单，README 只承认了较轻的另一半。

## Solution

口径沿用 ADR 0024 的筛子：能在本仓以 0 模型额度、不依赖一次性活体读数的形式被机器复跑证明，才进本轮。本轮是收口轮，做五件事，票号 27 到 31：

一，停机 seam（票 27）：新造写回池组件，提交点从状态机搬过去，停机走「宽限→超时→强制→计数」，饱和走「代跑→计数→暴露队列深度」；graceful shutdown 进公共配置，35 秒总预算写进运维段。二，配置校验（票 28）：`@Validated` 只管格式与范围，必填性继续由绑定地址那条规则独占；校验失败不回显密钥；必填清单做机器可读的集合断言。三，状态进指标面（票 29）：熔断、依赖健康、dev 默认值、写回饱和四组自注册 gauge/counter，熔断瞬时值必配迁移计数器。四，记账收口（票 30）：把「可查」作用域、TP99 未饱和口径、74% 红的挂起标签、孤儿票面引用、过期快照的失效标注，一次写进 README 与生产就绪评估。五，崩溃归因入账（票 31）：读那 14 份日志改有因结论，headline 数字旁补主机条件，起栈脚本设显式堆上限。

裁决掉但没消失的，全部挂在 ADR 0030 的触发式重开条件上：CI 子集 = 下一轮第一票；工单持久化与 RESOLVED→买家回流 = 真工单系统替换业务 Mock 那天；action-only 头条改判与新判据绑定；拦截率 74% 的定义冲突待显式裁决、红不摘；最小告警集在出现可机器寻址的告警栈那天自动回到射程。

## User Stories

1. As 运维, I want 停机时排队的写回在宽限期内落完, so that 一次正常重启不悄悄丢掉任何一条缓存答案。
2. As 运维, I want 宽限期耗尽后被迫丢弃的写回落在一个计数器里, so that 「停机丢了什么」有数可查而不是凭猜。
3. As 运维, I want 停机预算（HTTP 收尾 30 秒 + 写回池 drain 5 秒 = 35 秒）写在 README 运维段, so that 我看门狗超时敢不敢设 30 秒有依据。
4. As 运维, I want `stop.ps1` 等端口释放的超时不小于停机预算, so that 脚本不在预算用尽前误判「停了」。
5. As 排障者, I want 池关闭后仍到达的提交走调用线程代跑而不是抛进黑洞, so that 最坏情况是慢,不是丢。
6. As 排障者, I want 队列满时被请求线程代跑的次数有计数器, so that 「宁可慢不可丢」这条策略的代价第一次变得可见。
7. As 排障者, I want 写回队列深度作为 gauge 暴露在指标面, so that 命中路径 TP99 读数是饱和下的还是未饱和下的,当场分得清。
8. As 指标面使用者, I want 熔断器状态既能看瞬时值又能看两次抓取之间发生过几次迁移, so that 闪断不被「值随状态变」的抓取盲区吞掉。
9. As 指标面使用者, I want 依赖健康组的每个依赖以 `dependency_up` 标签值出现在指标面, so that 票 23 的灯与 Prometheus 侧说的是同一件事。
10. As 指标面使用者, I want dev 默认值在用与否同时是指标不是只有 HTTP 出口一个读数, so that 抓取端能按时间轴看到某台实例何时开始吃默认值。
11. As 接手本仓的开发者, I want 端口、时长、阈值、温度、轮次这些配置字段在启动时就按格式与范围判错并点名哪个字段, so that 我不必从一次请求的间接报错倒推配置写错了。
12. As 接手本仓的开发者, I want 必填性守护继续只管绑定地址那一件事, so that ADR 0029 的「必填是绑定地址的性质,不是字段的性质」不被配置校验顺手破掉。
13. As 安全审查者, I want 任何配置校验失败的报错信息不回显三处密钥与运维令牌的当前值, so that 校验器本身不成为泄密出口。
14. As 量具维护者, I want 「哪些环境变量必填」以一条集合断言钉住（配置文件占位符集合 == 清单）, so that 加必填项时机器拦漏,而不是靠一份没人更新的人读清单。
15. As 陌生读者, I want README 里「JVM 无日志消失、归因未定」改成有因结论并引用崩溃日志, so that 我对着仓库根目录数文件时抓不到话说满。
16. As 陌生读者, I want 三个 headline QPS 数字旁边直接印着当时的峰值步主机条件（空闲内存与 CPU）, so that 「1013 vs 1200 未达成」的归因我不用翻到限制段才能对齐。
17. As 维护者, I want 业务 Mock 与网关的 JVM 显式设堆上限, so that 16GB 笔记本上「同机压测 + 13 个容器」的现场不再靠默认策略赌运气。
18. As 下一轮压测者, I want 起栈形态变更（显式堆上限）在 README 注明, so that 我知道历轮读数为什么不可原样复现,而且不必假装它们能。
19. As 买家, I want 「转人工落可查工单」的「可查」作用域被写成整句, so that 看门狗重启抹单这件事不再是只有作者知道的秘密。
20. As 坐席, I want 工单持久化与「人工处理完→买家知道结果」两条差距登记进生产就绪评估, so that 它们和那 16 项享受同等待遇,而不是散在聊天记录里。
21. As 面试官, I want 「命中路径 TP99 22ms」带未饱和队列的口径标注, so that 这条数字在我追问饱和前就已经自己招了。
22. As 面试官, I want 拦截率 74% 那格红旁边挂着「与 ADR 0003 定义冲突已知、裁决挂起」, so that 哪些红是缺陷、哪些是定义问题,分得清。
23. As 后续读者, I want 调试台票里那个指向虚空「另一票」的 `aria-disabled` 欠账有了真实去向, so that 我不再按票号去找一张不存在的票。
24. As 未来审计者, I want 上轮项目梳理快照带基线失效标注, so that 读到「票 23-26 待做」时先看到它已过期一轮。
25. As 告警栈的未来使用者, I want 本轮只做指标前置、不写告警规则这件事写在票面, so that 「为什么这里没有 rules 文件」有答案。
26. As 门禁维护者, I want 本轮全部新断言落在既有 JVM 单测面与浏览器验收面, so that 审计保持 95 项、门禁步数不变。
27. As 门禁维护者, I want 崩溃归因票的复跑判据是文档级断言（README 不得再出现「没有 hs_err」式字样、归因段引用日志文件名、起栈脚本含堆上限参数）, so that 它不靠任何一次性活体读数作证。
28. As 接手者, I want 本轮不重开「最小告警集」非目标、不冲召回率/拦截率, so that 收口轮结束时判据、阈值、gold 与开工那天逐字一致。
29. As 下一轮规划者, I want 五个触发式重开条件各自写清「触发前不做是决定」, so that 我不必重新 grill 一遍该不该做。
30. As 量具维护者, I want 指标名计数按全仓 grep 现算并在换代时写明数法, so that 「34 个」这类格数永不腐烂成第二个「归因未定」。

## Implementation Decisions

- 本轮定位：只做 ADR 0024 筛子未排除的外壳项 + 记账收口 + 一份「为什么停在这里」的 ADR（即 0030）。停机预算、配置校验、状态指标面三条已锁决策逐字照 ADR 0030 与本次裁决执行。
- 写回池 seam：新组件 `cache/WriteBackPool`（网关侧），`submit()` 内部自带异步链路日志坐标包装；`close(Duration)` 语义 = shutdown → awaitTermination → 超时则 shutdownNow 并计 `shoppilot_writeback_dropped_total`；池关闭后的提交走调用线程代跑。状态机的写回提交点整体迁入，原提交处不再直接持有线程池。`CallerRunsPolicy` 包一层带计数的拒绝策略，队列深度经该 seam 暴露——这是 P0-B 行为半票成立的前提，裸线程池数不出代跑次数。
- 停机预算：graceful shutdown 开关进公共配置；HTTP 收尾用 Spring 默认 30 秒不调；写回池 drain 宽限 5 秒；总预算 35 秒写进 README 运维段；`stop.ps1` 加一格「等端口释放超时 ≥ 预算」。
- 配置校验：校验注解只管格式与范围（端口、duration>0、阈值 0-1、温度 0-2、轮次 ≥1）；必填性继续由票 21 落地的绑定地址规则独占，理由照 ADR 0029；校验失败的报错不回显三处密钥与运维令牌；「必填清单」只做机器可读的集合断言（配置文件占位符集合 == 清单），不写人读文档。
- 状态指标面：自注册，不引入 resilience4j 的 micrometer 桥（本仓只依赖 circuitbreaker 本体）。命名统一 `shoppilot_*`。四组：熔断状态 gauge（0/1/2）+ 迁移计数器 `shoppilot_circuit_transition_total{from,to}`（瞬时值会漏掉两次抓取之间的闪断，两者必须成对）；`shoppilot_dependency_up{dependency}`；`shoppilot_dev_defaults_in_use`；写回饱和组 `shoppilot_writeback_queue_depth`（gauge）+ `shoppilot_writeback_caller_runs_total`。票面写老实话：本轮不写告警规则，只做完前置。
- P0 裁决记录（详见 ADR 0030，此处只登形状）：P0-A 整条进本轮含脚本堆上限改动；P0-B 拆半——行为进票 27、观测进票 29、口径标注进票 30；P0-C 与 CI 均为「本轮不做但有主」，账记票 30 与 ADR 0030,代码一行不碰。
- README 运维与指标段的记账改动全部归票 30 与票 31 两条文档票，票 27/28/29 不改 README 叙事，只加各自那一格事实（预算句、指标换代句）。
- 依赖关系：票 29 第四组依赖票 27 的队列暴露；票 30 依赖票 27 与票 29（口径文字要引用已落地的对象名）；票 28、票 31 无阻塞,可与票 27 并行开工。

## Testing Decisions

- 只用两个既有 seam，不新增第三个，不新增门禁步骤：全部新断言落 JVM 单测面（不起容器）；浏览器验收面本轮不新增格（`aria-disabled` 欠账记给下一轮，不在本轮兑现）。
- 票 27 五条不起容器用例：宽限内跑完不丢 / 超时才丢且 `dropped` 计数对 / 池关后提交走调用线程代跑 / 队列满时代跑被计数 / 队列深度读数随实际积压变化。
- 票 28：格式与范围各判错点一条；一条断言校验失败的报错信息不含三处密钥与运维令牌的任何当前值；一条集合断言钉必填清单。
- 票 29 四组各一条「值随状态变、不随请求变」用例：状态迁移后 gauge 与 transition 计数各自对得上、打请求不改变 gauge 值；熔断组另断「两次抓取之间的闪断只有 transition 计数器看得见」。
- 每条新防线都有「摘掉它必定当场判错」的用例，沿用第十一轮给合取项立的规矩：`dropped` 计数、`caller_runs` 计数、`transition_total` 三格各配变异反证。
- 票 31 是文档与脚本票：复跑判据取文档级断言形状（README 字样、归因段引用文件名、起栈脚本含显式堆上限参数），不进 JVM 用例面；日志内容本身是仓内一手证据,引用文件名不引用行号。
- 全部门禁用 local 档，0 模型额度；一次性活体读数（含历史 env-*.json）只登记当时状态。审计总项数保持 95，判据、阈值、gold、评测口径零改动。
- 同类先例：票 21 的绑定地址用例族与 `IdentityArchitectureTest` 是「不起容器断配置行为」的形状；`RequestTrace` 的异步包装用例是 seam 内包装行为的形状；round13 各票的「并发不互相污染」用例是停机/饱和类用例的参照。

## Out of Scope

- 告警规则文件（票 29 只做指标前置；触发条件见 ADR 0030 第 5 条）。
- 工单持久化、RESOLVED→买家回流、「可查」跨重启承诺（触发条件见 ADR 0030 第 2 条）。
- CI 子集门禁（触发条件见 ADR 0030 第 1 条，下一轮第一票）。
- action-only 头条改判与拦截率 74% 的改判（分别挂 ADR 0030 第 3、4 条）。
- P1 挂账组：语义缓存写回失败计数器、会话存储 fail-open 指标、LLM/向量/检索侧熔断、调试台排印组（小字字距、减动效偏好、焦点样式、断点密度）。
- L2 召回率、拦截率、任何判据/阈值/gold 的冲刺或调整；Dockerfile 与部署形态；会话状态键旧数据迁移；重开「最小告警集」非目标辩论。
