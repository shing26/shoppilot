## 0. 本轮一句话

B3 让资金动作的责任人不可抵赖；B4 把 IM 适配器从「录放门里的契约」变成「**吃上真网络**的
长连接」：飞书 WebSocket 长连接收事件 → 走平台无关的两格（会话 id + clientToken 派生）→
进既有入站链路。**零暴露**是本轮的红线：网关不开新端口、无入站回调、无隧道。

## 1. 范围

- **做**：
  1. **A 段两格先行**（票 96，平台无关）：`NormalizedChat` 补 `conversationId` 派生 +
     适配器从平台 message id 派生 `clientToken`——真连没有这两格就是每条消息全新会话；
  2. **飞书适配器 + 录放门**（票 97，录制对象 = 飞书事件 JSON）：录制平台原样事件做夹具，
     归一 + 幂等派生 + 会话键三样断言，0 token 进 CI；
  3. **飞书长连接客户端**（票 113）：引入官方 SDK（oapi-sdk 2.4.0+）建长连接，事件归一后
     进 `ChannelAdapter` 契约，出站回复走飞书 API；
  4. **凭据接线**（票 114）：`APP_ID`/`APP_SECRET` 走 `.env`（不入库），PostureGuard
     非回环空凭据拒启；
  5. **wss 应用层握手活体验证**（票 115）：真凭据实测长连接建立与事件收发，关掉票 98
     照登的「应用层未验」边界。
- **不做**：
  - 隧道/公网回调形态（ADR 0065 决策 2 红线）；
  - 跨平台身份统一（平台 `open_id` ↔ `customerId` 映射表）——R3，触发条件未到；
  - 第二平台（企微/钉钉/Slack 留候选）；
  - 飞书**群聊/卡片/富媒体**全家桶——本轮只做单聊文本问答链路（与既有 chat 链路对齐），
    富媒体解密（aeskey）那格登记。

## 2. 硬约束

- **判据面零改动**：A 段录放门是新增 0 token 断言，不改任何既有判据；矩阵步数 / gold /
  阈值全不动。
- **CI 九步不变**：录放门并入既有 0 token 步骤（round15 纪律：不加需要外部服务的步骤）。
- **凭据不进仓库**：`.env` 家法 + compose/脚本 `:?` 必需语法（B2 PG 密码先例）；
  非回环空凭据拒启（PostureGuard）。
- **零暴露红线**（ADR 0065 决策 2）：B4 执行期间不得把网关端口暴露到公网。
- **A 段不引 SDK**（票 97 口径）：录放门只吃事件 JSON；SDK 只进 B 段的票 113。

## 5. 登记节

- **凭据申请是运营动作**：所有者在飞书开放平台注册企业自建应用、拿 `APP_ID`/`APP_SECRET`。
  凭据到位前，票 115 不动、wss 应用层握手保持「未验照登」；其余票不受阻塞。
- **多 client 集群语义**：飞书同一应用多 client 时消息随机落一个（非广播）。单实例网关
  无碍；**多实例部署时这条语义要重看**（登记，不阻塞本轮）。
- **3 秒处理时限**：飞书事件须 3 秒内处理完——本链路是收事件 → 转发，不做长处理；
  若未来链路变重，要改成先 ACK 后异步。
- **群聊/富媒体不在本轮**：群聊事件形状、消息卡片、媒体文件 AES-256-CBC 解密（aeskey
  逐链接）都登记为范围外；要做时先补录放门夹具再动代码。
- **旧版消息卡片回调不兼容长连接**（飞书文档口径）：本轮不涉及，接入卡片时要重看。
