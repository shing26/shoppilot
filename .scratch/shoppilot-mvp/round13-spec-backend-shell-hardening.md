# round13 spec：后端外壳加固（票 21-26）

**Status:** done（2026-09-16 补记状态位：票 21-26 已全部收口，早先误留 `ready-for-agent`）。本仓的 tracker 是 `.scratch/shoppilot-mvp/issues/NN-slug.md` 那批文件，没有 native label，状态按票面的 Status 字段记。

来源：2026-09-12 至 09-13 的 `/grill-with-docs` 会话，逐条经用户确认。落盘为 ADR 0023 到 0029 与 `CONTEXT.md` 六个新词条，本文件只综合，不新增决策。

## Problem Statement

这个系统能把一条买家诉求从对话走到落库工单，能在依赖挂掉时按写死的取向降级而不把「检索失败」翻译成「没查到」，能为每个数字留下可复跑的取证。但它的外壳还停在开发形态：三处密钥带着可以直接启动的默认值，身份可以凭一个公开在页面里的令牌被任意领取；`/auth/mock-token` 不要任何凭证就能签出「任意店铺 + 任意买家」的合法身份；会话上下文按「店铺 + 会话 id」归属，同店铺里两个人用同一个会话 id 就能互相看见对方的对话与没办完的待办动作；一次请求在日志里追不出主线，响应发出去之后的异步写回干脆认不回是谁触发的；REST 侧的错误文案按端点各写一遍，同一个失败在不同端点长成不同句子；调试台那颗健康灯从第一天起就没法变红。

对一位个人开发者来说，真实的商家订单库、平台身份方、能出真钱的退款链路都拿不到，所以「真实投产」不是这轮的努力方向。这轮要解决的是另一个问题：**一个陌生人在他自己机器上把这份代码跑起来、点两下、读十分钟，会不会当场抓到我们把话说满**。

## Solution

口径定为面试作品，唯一筛子是一句话：一项改造只有能在本仓以 0 模型额度、不依赖一次性活体读数的形式被机器复跑证明，才进这轮。据此做六件事，票号 21 到 26。

一是把「默认值什么时候合法」这条规则挂到**绑定地址**上：绑回环时一切照旧并可读地声明自己在用默认值，一旦绑到非回环，任何一处仍取默认值就启动失败，运维端点须显式关闭或换成非默认凭证，mock 身份签发端点压根不注册。二是把会话归属改成「店铺 + 买家」两者。三是给向量、检索、知识库做就绪状态，但把它们放在 readiness 之外的 `deps` 组，并让调试台那颗灯改读它。四是日志：logback 配置、落盘轮转、四个身份坐标进 MDC 并在异步边界手工接上。五是 REST 侧统一网关自产错误的出口形状，代理透传与流式那套一律不动。六是调试台剩下的交互缺陷。

## User Stories

1. As 接手本仓的开发者, I want 在非回环绑定时启动即失败并点名是哪一处默认值, so that 我不会把带着仓库里公开密钥的实例挂出去还以为它安全。
2. As 接手本仓的开发者, I want 在回环绑定时照旧用默认值一键起栈, so that 干净克隆判据与三条演示不被这条改造打死。
3. As 陌生读者, I want 在观测面上直接看到当前是不是在吃 dev 默认值, so that 不必翻配置就知道这台实例的凭证状态。
4. As 买家, I want 我在一间店铺里的会话不被同店铺另一个买家看见, so that 我说过的地址与订单号不会被回声给别人。
5. As 买家, I want 我上一句没说完的待办动作不被别人接着办, so that 别人不能拿我填到一半的改址去提交。
6. As 坐席, I want 工单队列仍然按租户切分, so that 收紧会话不会顺手改掉我看单的范围。
7. As 运维, I want 一次请求的四个坐标出现在这条请求打出的每一行日志里, so that 我能从一次 401 追到它下游的检索与写回。
8. As 运维, I want 响应之后的异步写回日志仍带着触发它的 traceId, so that 「答案发出去了、缓存没落地」这类事故能认回主人。
9. As 运维, I want 日志按大小与日期自己轮转落盘, so that 不必再依赖 shell 重定向那种一关窗口就没的形态。
10. As 调试台使用者, I want 健康灯反映依赖的真实状态, so that 它不再永远绿。
11. As 调试台使用者, I want 「还能应答但已降级」与「别再给它流量」显示成两件事, so that 我不会把降级当成就绪失败。
12. As 排障者, I want 下游透传回来的错误体保持原样, so that 我能分辨这句是网关说的还是业务层说的。
13. As API 调用方, I want 网关自产的错误有同一个形状并带 code 与 traceId, so that 我可以按字段处理而不是猜文案。
14. As API 调用方, I want 超长输入拿到可显示的校验文案, so that 界面不再只剩「请求被拒绝：400」。
15. As 面试提问者, I want README 不再把「身份不可伪造」写成覆盖任意领取, so that 答主在追问下不必改口。
16. As 调试台使用者, I want 换身份后旧气泡与旧会话被清掉, so that 页面不再把别人的话挂在屏幕上。
17. As 调试台使用者, I want 空输入给出提示而不是静默, so that 我知道是没提交而不是卡死。
18. As 窄屏用户, I want 事件时间线在小屏不被整块藏掉, so that 我在窄屏仍能看到本轮发生了什么。
19. As 下一轮审查者, I want 每一票的验收判据都能 0 额度机器复跑, so that 第十一轮那套双轴审查不必先花额度就能重跑。
20. As 接手者, I want 门禁在实现轮仍然判得出「本轮没碰判据、阈值、gold」, so that 我可以改实现而不丢那三条铁律。
21. As 接手者, I want 审计总项数与历轮那串自述保持不动, so that 开工不必先偿一遍换代账。
22. As 维护者, I want 用户模拟走查看出来的缺陷被固化进既有的浏览器验收 seam, so that 它不再养在系统临时目录里等被清掉。

## Implementation Decisions

- 口径与筛子：本轮是面试作品，不宣称任何形态的上线；「投产」（真实商家数据上的对外服务）列为外部前置、个人开发者不可达。判据见 ADR 0024。
- 收紧的触发器取绑定地址而不是 prod 配置档或显式风险开关：回环合法、非回环失败，并在观测面上回一个「是否在用 dev 默认值」的字段。运维令牌、内部令牌、JWT 签名密钥三处默认值与 mock 身份签发端点同受这条规则管辖。绑定回环只是必要条件、不是防线，反向代理场景明写。见 ADR 0029。
- 身份领取与身份伪造是两个词，README 那格「身份不可伪造」的措辞要收窄成它真正钉住的东西。定义见 `CONTEXT.md`。
- 会话归属取「店铺 + 买家」两者，外置状态的键加一段买家归属；旧状态不迁移，靠过期自然走。订单行侧的守卫本来就按「店铺 + 买家」拦，所以本轮修的是上下文可见性，不是资金安全，指标表那行不许顺手升格。见 ADR 0025。
- 可降级依赖不进 readiness 组：向量、检索、知识库三个健康指示器挂在新的 `deps` 组，readiness 组一字不动。理由是门禁与起栈脚本都以 readiness 为放行谓词，而多档实验 profile 存在的意义就是把某个依赖人为弄残。见 ADR 0026。
- 调试台那颗灯改读 `deps`，并补上它从来就没写过的变红分支。灯与就绪门是同一个 bug 的两端。
- 日志：新增 logback 配置、落盘与轮转；四个坐标（traceId、租户、买家、会话）在鉴权入口一次装进 MDC，装填点从对话控制器挪进鉴权过滤器，流式与 REST 共用同一来源，完成帧继续回显同一个值。异步提交点用一层手工包装接上上下文、用完清理，不引入 context-propagation 库。身份坐标进日志是合成数据上的取巧，真实投产须换假名标识，这句写进 README。见 ADR 0027。
- REST 错误出口：一个 advice 只统一网关自己产生的错误，形状为 code、message、traceId 三字段；鉴权拒绝那一处与它共用同一个 writer，出同一形状。代理透传的下游体不改写，status code 一律保持现状，流式那套八值 reason 加两层文案完全不动。见 ADR 0028。
- 运维令牌的失败原因拆成「开关关闭」与「令牌不匹配」两个 reason，与流式侧的 reason 风格同构；这一处是错误出口的第一块砖，所以错误出口票被它阻塞。
- 量具：审计窗口逐轮重锚到本轮起点，B7 改判内容级禁面（gold 与判据阈值所在文件、本轮起点那一刻已在库的 ADR），改动文件清单降为读数；路径白名单表删除。同一条重锚规则顺带治了 B6——它以某轮命名却把右端挂在 `HEAD` 上。审计总项数保持 95，不新增门禁步骤，新断言全部落在既有构建与单测两步里。见 ADR 0023。
- 一次性走查产物不再留在系统临时目录：生产就绪度评估已入仓成带日期的快照文件，走查看来的缺陷改固化进既有浏览器验收 seam。

## Testing Decisions

- 只用两个既有 seam，不新增第三个，也不新增门禁步骤：JVM 单测面（构建与单测两步已经在跑它，票 21 到 25 的全部断言落这里）与浏览器验收面（`console` 那一步，票 23 的灯与票 26 的交互落这里）。
- 只测外部行为：非回环配置下启动失败并点名是哪一处；回环配置下启动成功且观测面自报在用默认值；跨买家的会话 id 载出空会话、写不进去、待办动作不被续办；依赖置 DOWN 时 `deps` 红而 readiness 仍 UP 且降级路径照常出答案；同一请求内所有日志事件的 traceId 相等且非空、并发两请求不互相污染、异步写回那条日志认得回它的触发者；网关自产错误出同一形状而透传体逐字节不变；空输入与超长输入各自得到可见反馈。
- 每条新防线都要有一格「摘掉它必定当场判错」的用例，沿用第十一轮给合取项立的那条规矩；谓词能用单一的就不写成合取。
- 全部门禁用 local 档，0 模型额度；任何一次性活体读数只登记当时状态，不得当证据引用。
- 同类先例：`AuthFilterTest` 与 `IdentityArchitectureTest` 是身份面的既有单元形状，`verify-console.mjs` 是浏览器面的形状（PASS/FAIL 逐条打印加收尾断言），`verify_eval_judge.py` 的变异反证是「摘掉必判错」的写法参照。

## Out of Scope

- 最小告警集：本机没有可打的 Prometheus 与 Alertmanager 实例，规则只能证语法、证不了该响时会不会响，正面撞上本轮那条筛子。
- Dockerfile、CI、prod 配置档、真实部署目标：17 步门禁要本地模型与两套检索引擎，runner 上跑不起来，红的 CI 比没有更糟。
- 分布式追踪、跨实例 singleflight 验证、异机复现：前者要新依赖与外部收集器，后两者要两个实例或别人的机器。
- 换真库与真身份方（即「投产」本身）、把 biz-mock 换成真实商家数据。
- 改任何 status code、阈值、判据、gold、评测口径；新增门禁步骤；把 `mustNotLeak` 降级成注释。
- 会话状态键的旧数据迁移。
