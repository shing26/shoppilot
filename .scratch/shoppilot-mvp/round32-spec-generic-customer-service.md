# round32 spec —— 把「通用客服」从形容词变成两个能跑的场景

> 状态：**已收口**（2026-10-17 开轮与收口同日；票 117-123 见 [`issues/`](issues/)）。
> 依据：[ADR 0066](../../docs/adr/0066-round32-generic-customer-service-two-runnable-scenarios.md)
> （开轮 + 术语收敛授权）。性质：**所有者政策覆盖**（`RELEASE.md` Freeze policy 第 4 条），
> **不自动续期**——round32 收口即止。

## 0. 本轮一句话

业务侧读者（客服主管 / 运营 / 产品）在 3 分钟内能复述「**一进、一出、哪一步转人、什么情况办不了、
现在哪段未通**」。手段：一个具体门面场景（鲜果驿站 T002 死蟹理赔）+ 一个跨行业对照（酒店入住与
退改，纯咨询），用两个**都可跑**的实例证明「换知识库就换场景」，而不是用架构形容词声称通用。

## 1. 范围

- **做**：
  1. **门面场景：鲜果驿站（T002）死蟹理赔**。政策含六小时窗口、按只折算、需订单核验，且有一个
     真实边界——**系统不能看照片定责，必须转人**。
  2. **跨行业对照：酒店入住与退改规则（T004 云栖酒店，纯咨询、零工具依赖）**。它证明同一套代码
     换一套知识库就换一个行业；办理域换不了（本仓没有酒店工具）这条边界**照实写**。
  3. **业务一页纸**：`docs/round32-two-runnable-scenarios.md` 承担完整叙事。README 首屏降级为
     指路牌；`RELEASE.md` 只加换代指针、不改正文。
  4. **术语收敛**：`CONTEXT.md` 的「租户 / 店铺」改写成「租户唯一、店铺是电商域业务叫法」
     （ADR 0066 授权）；`POLICY_HOTEL` 进意图清单。
  5. **种子身份对齐**：店铺名以 `knowledge/` 语料为准改名（T001 星选生活旗舰店、T002 鲜果驿站、
     T003 云裳服饰旗舰店），补 T002 的生鲜演示固定单（时间相对 `now` 计算）。
  6. **新意图四处同步**：`Intent.POLICY_HOTEL` + `T0RuleLayer` 酒店词表 + `MarkdownChunker`
     `hotel-` 前缀映射 + `intent-samples.json` 样例句（质心现场算，不写死向量）+ 评测集新分区。
- **不做**：
  - 酒店**办理域**（订房 / 改期 / 取消下单）——要新增工具契约与判据，超出本轮对照目的；
  - 把酒店用例并进 180 条 gold（动分母，违反红线）；
  - 改判据、阈值、gold 或指标分母；宣称上线；为「看起来完整」加功能；
  - 真人 cold-read 之外的自动化「读懂度」评分器（模型读者只作防腐化辅证）。

## 2. 硬约束

- **判据面零改动**：酒店评测**单独成列、不给总分、不并入四列**；180 条 gold 与 CI 的 rescore
  基线不动。新增 `kind: hotel` 判据自带夹具与反证。
- **检索可见范围是 `tenantId + PLATFORM`**：酒店语料挂 `tenant_id: T004` 且**不挂 PLATFORM**，
  否则污染全部电商租户的检索结果（ADR 0066 决策 4）。
- **0 token 门禁照旧**：酒店政策问句必须能命中缓存（`cacheLayer ∈ {L1, L2}`）；CI 九步不变。
- **T0RuleLayer 顺序**：酒店词表判定放在实体 / 第一人称判定**之前**——否则「我订的房能免费取消吗」
  会因 `POSSESSIVE` 判成 `ACTION_ORDER`，挂上全套电商工具并被踢出缓存准入。
- **标定重跑是硬性**：多一个质心改变 T1 最近邻地形，`MIN_CONFIDENCE` / `MIN_MARGIN` 结论必须
  重跑 180 条标定重验，不许凭手感沿用。

## 5. 登记节

- **收口审计读数换代**：入仓的 `G6_EXPECT`（round22 落点 `[10, 57, 342, 39] = 448`）与 README
  的读数长期不一致；本轮按新鲜 JVM 实测换代 `[10, 69, 391, 45] = 515`，**不为凑绿改判据**，
  未达成的照登。**随之而来的一条红要认**：`G6_EXPECT` 读的 `logs/acceptance/{build,unit}.log`
  仍是 2026-10-05 的落点（448），所以审计此刻会报「常数 515 ≠ 日志 448」——那是**本轮没重跑带
  `build/unit` 的活体矩阵**，不是防线失效；不许为消红把常数改回 448。审计的 `PASS/FAIL` 读数
  仍是 round22 的旧落点，本轮**未重跑审计**（需活体栈），照登。
- **真人 cold-read 是外部动作**：本轮必做，执行者是一位真实业务侧的人；脚本化五问只作辅证，
  不得冒充主判结论。
- **跨行业成本照登**：酒店是**纯咨询对照**；接一个**办理域**行业需要新增工具契约与意图、扩状态机
  分支与判据，本轮的「改四处」结论只对咨询域成立。
- **T0 硬优先级**：酒店词表当前是 `T0RuleLayer` 的硬优先级；将来若真做酒店办理域，必须先重排这条
  顺序，而不是在词表上打补丁。
- **与收口审计 B7 禁面的冲突，照登**：`round3-closeout-audit.py` 的 B7 把 `knowledge/` 整体列为
  **内容级禁面**（round3 是纯文档轮，语料当时冻结）。本轮按 ADR 0066 决策 3/4 **必须新增**
  `knowledge/hotel-*.md`，因此 B7 在本轮窗口必然命中 `knowledge/`。**处理口径**：这是 ADR 0066
  的显式授权，**不为凑绿删除知识库、也不改 B7 判据**；审计若要重跑，由所有者在收口时把 B7 的
  `knowledge/` 禁面按 ADR 0023 的内容级本义重锚（或单列豁免并写明理由）。本 spec 与票 123 都记这一条。
