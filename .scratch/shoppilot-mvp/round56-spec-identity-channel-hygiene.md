## 2. 224 身份生命周期

把「演示账号能登录」升级为「账号生命周期可运营」：

1. access + refresh 双令牌；refresh 单次使用并轮换，复用旧 refresh 视为泄露，撤销整个令牌族。
2. 改密：校验当前口令；成功后撤销全部 refresh，旧口令立即失效，新口令可登录。
3. 失败锁定与登录限流：按租户 + 账号（必要时叠加来源）计数，窗口内连续失败达到阈值即锁定；
   锁定期间正确口令也不放行；窗口结束自动恢复；对外文案不泄露账号是否存在。
4. 停用账号 / 角色变更：refresh 立即拒绝；access token 最迟在一个短 TTL 内失效；
   角色能力每次按服务端状态重算，不再出现「停用后还能用 30 分钟」。
5. 前端：401 时单飞刷新并只重试原请求一次；刷新失败只登出一次，不形成循环；
   买家与坐席都提供改密入口。

非目标：SSO、MFA、邮箱找回、外部 IdP、全套 RBAC 重做、默认口令。

## 3. 225 渠道热生效与出站安全

把「保存配置后重启网关」升级为「可安全生效、失败可回滚」：

1. 渠道配置保存 → 探测 → 原子切换；成功时旧长连接停止、新配置接管，不重复消费事件；
   失败时保留 last-known-good 并返回明确错误；`restartRequired` 只在确实无法热切换时为 true。
2. 飞书连接生命周期由连接管理器负责；若 SDK 无法安全关闭旧连接，必须诚实降级为
   「需重启」并给出证据，不得假装热生效。
3. 出站 SSRF 防护：只允许 http/https；解析后拒绝 loopback、私网、link-local、云元数据地址；
   DNS 重解析与重定向逐跳复检；支持显式 allowlist。
4. 投递幂等与重试：去重键落 Redis/DB，跨网关重启仍生效；重试带指数退避与抖动；
   超过上限落 `CHANNEL_RECEIPT` 工单，不丢结论。
5. 管理面：区分「已保存 / 已生效 / 需重启 / 失败回滚」；密钥只显示掩码；
   「测试连接」与「保存并生效」是两个可验证动作。

非目标：真实 SMTP 发信（email 继续以回执工单交付）、微信/多平台接入、改退款与工单业务规则。
