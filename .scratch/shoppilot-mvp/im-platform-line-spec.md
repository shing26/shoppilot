# 主线：IM 平台接入（契约先行，真连待定）

> 状态：**已开线（2026-10-04）**，票 96-99。**本线与 round 编号无关**，它是一条 program 主线。
> 依据：[ADR 0060](../../docs/adr/0060-im-platform-line-contract-first.md)（新立）、
> [ADR 0035](../../docs/adr/0035-channel-adapter-normalizes-inbound-to-one-contract.md)（渠道归一）、
> [ADR 0059](../../docs/adr/0059-outbound-first-producer-is-ticket-resolution.md)（出站）、
> [ADR 0049](../../docs/adr/0049-retrieval-fusion-replay-gate.md)（录放门的同款先例）。
> 所有者目标（2026-10-04 grilling）：做成可接入各 IM 的客服平台。

## 0. 这条线**不交付**什么（先说清，免得日后被当成已做）

- **不交付「同一个人跨平台是同一个身份」**。平台用户 id 与仓里 `customerId` 之间没有映射表，
  本线**不建**那张表（ADR 0060 决策 6）。
- **不交付「已接入 XX 平台」**。A 段交付的是**适配器契约可复现**，不是「接上了那家」。
- **不交付多平台**。A 段只接一个平台，那是它在不为假想适配器写抽象的前提下的最小形态。

## 1. 为什么先做两格平台无关的东西

它们是任何平台都需要的，且**今天就能在 CI 里验证**，不需要凭据与公网：

1. **`NormalizedChat` 缺 `conversationId`**——今天走 webhook/email 的调用方不自己传会话头的话，
   `AuthFilter` 每次现生成随机 UUID，**每条消息都是全新会话，追问必然断**。这不是 IM 特有的问题，
   是现在就在的洞（`verify-channel.ps1` 的「跨渠道会话续接」断言是靠调用方手动传头才成立的）。
2. **幂等派生 token 不含渠道、TTL 6 小时、靠参数猜同一次提交**——客户端不给 token 时，
   同一个人在不同上下文说同样的话会被判成重放。IM 平台都有稳定的 message id，适配器**应该**从它派生
   `clientToken`，绕开那条脆弱路径。

## 3. 验收里必须有的两条「不成立也算数」

- **录放门要断「跨渠道会话不串」**：录两份同一个人、不同平台的事件，断言会话键**不同**
  而归一结果各自正确。这一格防的是「同一个 session 键被两个平台共用」。
- **录放门要断「幂等不靠参数猜」**：同一个人在不同平台发**同一组参数**、**不同 message id**，
  断言两次**都执行**而不是第二次被判重放。这正是今天那个 6 小时窗口的跨平台放大形态。

## 4. 证据形态（本线与前几轮最大的不同）

A 段：0 token、干净 runner 可复现（同检索录放门）。
**B 段：真凭据 + 真网络 + 可能的公网暴露，其活体证据在门禁之外**——那一格必须照登，
不许写成「已验证」。

## 5. 资源与红线

- 本机可用内存约 1.9 GB，全栈档只在清场日（与既有裁定一致）。
- **暴露面红线**：隧道 / 公网方案只能放行回调路径 + 强制平台签名校验；ops 端点一律不对外。
  **未做暴露面审查之前不开 B 段**（ADR 0060 决策 5）。
- 一条判据都没动：gold 180、阈值、`judge()`、降级枚举 10 / 降级 9、CI 九步的既有步骤原样。
  A 段新增的门禁是 **0 token**，所以它可以进 CI 而不放宽 CI 的任何既有性质。
