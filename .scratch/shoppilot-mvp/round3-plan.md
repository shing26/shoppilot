  ⑪ **`defer`/flush 的兜底只比数量、不比名字**（judgement）：flush 处比的是 `len(ALL_NAMES) - _before ==
     len(DEFERRED_NAMES)`，而 `H16` 又把 `DEFERRED_NAMES` 整个当成「本轮跑过」——把 `_run_h12` 正常路径那格

     处置：flush 里逐项 `assert _nm in ALL_NAMES[_before:]`，注释改成指明「真正的闸在这一道」。
     反证 = `ce12` 的 **CE-7**（临时克隆里换登记名 ⇒ 按名字核那道当场 `AssertionError`、退出码 1、无汇总行）。

     ⇒ 数量断言炸，这两种形状本来就兜得住；漏的只有名字错位这一种。
  ⑫ **收紧宽匹配时别退回去绑字面量**（judgement）：P13 ⑨ 那轮把 `h12_verdict` 的红名单匹配收紧成

     （和 `f6234c4` 刚治过的那条同型）。处置：改成 `startswith(_H12_NAME)`（模块全局、调用期求值，
     定义顺序不影响）；`H12b` 第四格的输入也换成 `_H12_NAME` 全名，不再手抄字符串。
     对拍跑器 `D:\tmp\oldvnew2.py`：同一份合成输入旧尺子与新尺子各跑一遍。
  ⑬ **防呆断言把「本轮只推迟一项」写进判据**（judgement）：`_run_h12` 开头那条 `assert ... == N - 1`
     真正的前提是「flush 里只有 `H12` 一项推迟且它先落地」，将来第二个 `defer()` 一加就自己炸自己；
     而且它的文案写「有新的 check 加在 flush 之后了」，那是**反方向**的诊断，真炸的时候会把人往错的地方带。
     处置：改成 `== N - len(DEFERRED_NAMES)`，文案中性化并把两种成因都列出来。反证 = `ce12` 的 **CE-5a**。

  ⑰ **A3 是点读数、不是差值**（judgement）：判据 6 写「全程 `tokensUsedToday` 差值 0」，而 A3 那一格读的

     入仓产物各自记着 `tokensUsedToday=0`，时点跨 `05:29`、`08:21`、`09:12`、`09:28`、`10:13`、`10:46`、`11:59`。

     `foreach ($c in (git rev-list 9d444c9..16a35fa -- <产物>)) { git show "${c}:<产物>" | Select-String tokensUsedToday= }`。

     正是本轮 ① 刚治过的那类病。计数器单调不减、窗口首末皆 0 ⇒ 区间内任意两点差值为 0。另配 `A3b` 作离线反证（本轮窗口提交信息里
