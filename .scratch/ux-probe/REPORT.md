# 产品面真实用户走查（round44 之后）

日期：2026-11-03　环境：本机演示栈 `127.0.0.1:8082`（网关）+ Redis `16380`；
ES `19200` / Qdrant `16333` 不可达（`/actuator/health/deps` 40.13 s 后 503）。
方法：5 个 Playwright 脚本，桌面 1440×900 与 390×844 双宽度，按真实用户路径操作，
不做判据断言，只记录实际看到的东西。脚本在 `.scratch/ux-probe/`（`buyer.mjs`、
`buyer2.mjs`、`workspace.mjs`、`knowledge.mjs`、`interaction.mjs`、`entry.mjs`、`scroll.mjs`、
`verify-p0.mjs`）；截图与 JSON 日志（`shots/`）是本机产物，不入库。

## 一句话结论

**接线是通的，路径是断的。** 状态归属、SSE 流式、动作锁、四类后端动作在实测里都对；
但一个真实用户从首页走进来，会先撞上「同一标签页换店串号」，再发现「不能点踩」「答完不滚屏」，
而这两处恰好是 round43/44 想端出来的那条链的入口。

全程 0 个未捕获异常、0 个 console error（调试台那一条 403 是运维令牌未填的预期拒绝）。

## P0

### P0-1 同一标签页换店，沿用上一家店的会话（跨租户串用）

**复现**：`/` → 点「星选生活旗舰店」→ 返回 → 点「云栖酒店」。
**实测**：地址栏是 `?store=T004`，店卡显示「星选生活旗舰店」，快捷问题是酒店问题
（"你们酒店是卖什么的？"），助手的回答是「我们是星选生活旗舰店，不是酒店哦～」。
新标签页直开 `?store=T004` 则完全正确（云栖酒店）。

**根因**：`frontend-buyer/src/App.vue:58` 直接读 `sessionStorage` 里的会话，`onMounted`
（:462-473）只要 `session` 非空就沿用它，**从不校验 `session.tenantId === STORE_CODE`**。
`store` 参数只影响 `tenant` ref（快捷问题）与首屏文案，不影响身份。

**影响**：买家端是多租户产品面，这是最容易演示到的一步。数据层没有越权（令牌是上一家的真令牌），
所以后端隔离没错；错在页面把「换店」当成了「刷新」。

### P0-2 买家页面没有任何点赞/点踩入口，知识飞轮没有入口

**实测**：`grep -rn "feedback|点踩|点赞"` 在 `frontend-buyer/src/` 下 **0 命中**；
`api.ts` 里没有 `chat/feedback`；`ChatThread.vue` 一条回答下面只有「重试」。
`README.md:366` 写着「回复后可点踩/点赞」，而买家页做不到。

**后果**：round43/44 的知识飞轮在产品里**无法由真实买家启动**。门禁脚本
（`verify-workspace.mjs:182`）是直接 `fetch` 造反馈的，所以一直是绿的——这层绿把断链盖住了。
工作台知识视图在真实产品里会长期是 0 待复核。

补充：`POST /chat/feedback` 只需要 `conversationId + verdict + reason`，买家页本来就有会话 ID，
补一个按钮的成本很低；阻塞点只是「会话 ID 不持久化」（见 P1-2）。

### P0-3 对话不自动滚动，新回答落在视口外

**实测**（390×844，连问 3 个问题）：`.thread` 的 `scrollTop=0`、`clientHeight=535`、
`scrollHeight=908`，最后一条消息在 y≈919 — **完全不可见**。
`grep` 全前端：`scrollIntoView / scrollTop / scrollHeight / nextTick` **0 命中**，两端口径一致。

**影响**：聊天产品最基本的跟随都没有。桌面端回答长了同样会掉到折叠线以下；流式期间更明显，
用户看到的是空白或旧消息，以为没反应。工作台的渠道会话消息列表（`max-height:360px`）同理。

## P1

### P1-1 默认入口是游客态，订单与工单被永久隐藏；首页文案与产品行为互相打脸

`App.vue:109` 的 `isGuest` 让 `refreshOrders`（:233）与 `refreshTickets`（:300）直接返回空，
侧栏写「游客模式不展示订单」，**但顶栏只有「退出」，没有登录引导**。
而首页（`static/index.html`）承诺「店铺名片、快捷问题、我的订单、我的工单与政策引用都在同一页」，
四个店铺链接全部落到游客态 —— 用户点进来看不到「我的订单」。

更别扭的是：游客令牌其实是**真实的 C001 令牌**（`api.ts:25-46`，20 张订单可见），
助手还能查到「订单 90001 尚未发货」，UI 却说"不展示"。同一页里一个知道、一个假装不知道。

`?guest=0` 能进真买家，但用户不会知道；`enterAsGuest` 成功就永远走不到
`enterAsDemoBuyer`（:155-175），「一键体验买家」只在回环栈之外才出现。

### P1-2 刷新即丢对话，会话 ID 也一起丢

`App.vue:81` 的 `conversation` 是模块内变量，`messages` 不持久化。实测刷新前后：
对话 297 字 → 0 字，欢迎区回来，**工单还在**但用户已经不知道自己问过什么、工单是哪张。
同一问题在 P0-2 上还会放大：没有稳定的 `conversationId`，点踩也就无法回指上一轮回答。

### P1-3 「已复核」反馈刷新即失联；复核工单与复核状态两边各走各的

- 工作台知识视图：「已复核」只存在会话内（`App.vue:160-163`、`Ticket190 现场追问 1`）。
  实测复核一条后刷新：待复核 0、已复核 0，这条反馈**再也无法附稿**——不是看不见，是卡死在 `REVIEWED`。
- 复核队列只回 `PENDING`（`OpsController.java:134-136`、`FeedbackService.reviewQueue`）。
- 点踩同时会开一张 `FEEDBACK_REVIEW` 工单（`FeedbackService.openReviewWorkItem`）。
  实测复核完成后该工单**仍是 OPEN**（`markReviewed` :92-104 完全不碰工单），
  队列里堆着 3 张「会话 … 的答复待复核」，而它们的反馈早已不在复核队列。
- 反方向也不通：队列里点开这张复核工单，只有「领取 / 释放 / 处理完成」，
  **没有「去复核」入口**，点「处理完成」也不会让反馈变成 REVIEWED。

结果是同一件事有两套账，且互不销账。真实坐席会在队列里结掉复核单，却一条知识都没沉淀。

### P1-4 中文输入法按回车 = 直接发送

`Composer.vue:17` 是 `@keyup.enter="emit('submit')"`，没有 `isComposing` 判断。
实测派发 `isComposing: true` 的回车：消息数 0 → 2，把还没选词的「我想问一下」发了出去。
对中文产品是高频误触。

### P1-5 弹层：Esc 不关、焦点不进、Tab 会跑出去

- 工单抽屉（`TicketDrawer.vue:23-24`）：打开后焦点仍在背后的工单卡上；Tab 先走 `查看全部工单`，
  再进抽屉；**Esc 无效**。
- 结单框（`ResolveDialog.vue:22-23`）/退款框（`RefundDialog.vue:23-24`）：`aria-modal="true"`
  但同样没有焦点转移、没有 Esc。
键盘用户实际被锁在「看不见的遮罩后面」。

### P1-6 订单深度卡被两层滚动裁切

侧栏 `.buyer-side` 有 `max-height + overflow-y:auto`（`App.vue:610-611`），
里面的 `.order-list` 又有 `max-height:360px; overflow-y:auto`（`SideActivity.vue:177`）。
实测展开一张订单后，「收货信息」被切在句子中间，「物流进展」整块在折叠线以下；
要在小框里滚，小框又在大框里滚。票 189 做的深度卡，默认状态下是看不到全貌的。

### P1-7 退出登录不中止正在生成的回答

`signOut()`（`App.vue:201-219`）清了 `messages`、把 `asking` 置 false，但**没有 `inFlight.abort()`**
（`stopAnswer` 就在下面 :452）。实测：流式中点「退出」→ 页面回到登录门，`/chat/stream`
请求继续跑；服务端继续消耗模型额度，失败时还可能继续落单。

## 正常的部分（避免误伤）

- SSE 逐帧解析、停止 → 重试、连点只发一次请求：都对。
- 订单深度卡的数据本身正确：状态推进条、脱敏号码、地址、物流节点倒序、运单号复制都工作。
- 结单框空结论拦截、退款确认框把金额与订单摆出来、知识视图四个动作（复核/附稿/发布/驳回）
  与「发布不立即生效」常驻提示：都对。
- 390px 下三入口均无横向溢出。
- 组件拆分后状态归属没破：没有重复请求、没有「登录了但没登录」、没有未捕获异常。

## 限制

- ES/Qdrant 不可达：依据面板、引用分组、缓存命中三条没验（门禁里也是红的）。
- 飞书无真实会话，渠道会话只看了空态。
- 退款队列为空，退款决策只走了确认框的空态与代码阅读，没有真正的放行动作。
